Text-shaper Wasm size audit

Audited revision: main at 2f62d6bae1da688904dfd1aba40b0ed507262824. Artifact: CI run 38096962674, artifact 11687095277. Scope: text-shaper Wasm only.

Findings

The shaper is built no_std, but still uses Rust alloc. Talc is the Wasm global allocator. Rust core remains because it is the language foundation for no_std. The 135,530-byte core attribution is not std and is not a generic-expansion measurement.

HarfRust is a direct runtime dependency: font registration builds HarfRust state and shape plans, and the runtime calls its shaping API. read-fonts provides SFNT access. The strongest identified size areas are first-party engine code, static data, HarfRust, and font parsing.

What the source confirms

  • The crate defaults to std, but its shipping build passes --no-default-features; the crate root then enables no_std and imports alloc.
  • Runtime collections include Vec, Box, and BTreeMap. They allocate without requiring std.
  • wasm.rs installs talc::wasm::WasmDynamicTalc. Replacing Talc would not remove Rust alloc collection code.
  • Runtime code calls HarfRust APIs including FontRef::new, ShaperData::new, ShapePlan, UnicodeBuffer, and shaper.shape(...).
  • The shipping graph includes HarfRust, read-fonts, Unicode crates, serde_json with alloc, slug-core, and target-specific Talc. Build-time serde_json/std and dev dependencies flate2/skrifa are not part of the Wasm runtime graph.
  • Release LTO, one codegen unit, panic abort, stripping, and two Binaryen -Oz/merge-similar-functions passes are already enabled.

Source: manifest, crate and shaping code, Wasm allocator, and shipping build and Binaryen flags.

SIMD and generic expansion

The scalar control build was 2,638 bytes smaller raw than SIMD (under 0.2%); gzip was 666 bytes larger and Brotli was 3,055 bytes smaller. This is a size-only probe. Keep SIMD based on timing evidence.

The 135,530-byte core bucket may contain concrete instantiations, but the audit did not isolate generic monomorphization. A controlled compiler-level build and final-artifact comparison is required to estimate it.

Next probes

  1. Simplify first-party preparation/layout/publication/ABI code and measure the exact artifact.
  2. Experiment with Unicode data representation independently; static data is about one fifth of the binary.
  3. Test HarfRust feature reductions only against explicit shaping support and Unicode conformance requirements.
  4. Test allocator alternatives only if they preserve allocation behavior and improve size or speed; alloc and Talc do different jobs.
  5. Choose SIMD based on performance, not binary-size expectations.

This audit does not show that the shaper is irreducible, nor does it prove a safe cut. Each candidate needs exact-artifact correctness, performance, and size validation. These numbers exclude other Wasm modules, TypeScript, and total package size.
