# Public API summary for owner review

**Compared.** Published `@pmndrs/glyph@0.1.0` (tag `v0.1.0`: `package.json` `exports` and `dist/**/*.d.ts`) against
`experiments/segment-indexed-layout` after `sil-green-49` (`packages/glyph/package.json` `exports`, checked against
`src/` and `tests/types/`). The one entry point added is `./pixi3d` (section 1); none was removed. The name lists were
taken by resolving every `export … from` of each entry point. Behaviour rows cite the source that implements them.
Deferred to 0.3.0 and **not** part of this release: inline objects (no public input or result; icons go through the font
stack, wrap-around through exclusions).

Entry points below: root = `@pmndrs/glyph`; `three` also applies to `three/typegpu`, which re-exports the same names.

## 4. Built surfaces

`onLayout` (a), the editing API (b) and the error surface (d) are built as described below. The editing session with
input-method support that earlier drafts proposed (`text.edit()`, `setMarkedText`, `markedRange`, `unmark`) was dropped:
an application tracks its own composition range and draws it with `rangeRects`.

### (a) `onLayout` (built)

| Integration    | Built form                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------ |
| Three          | `text.onLayout: ((text: Text, layout: ParagraphLayoutSummary) => void) \| undefined`, a property |
| R3F            | `<Text onLayout={(text, layout) => …}>`                                                          |
| Vue            | `@layout="(text, layout) => …"`, an emitted event                                                |
| TypeGPU-direct | `TypeGpuTextOptions.onLayout?`, and a settable `text.onLayout` property                          |

- **Argument.** The text and its `ParagraphLayoutSummary`, the same object `text.measure()` would return:
  unanchored, with `anchorOffset`. Reading it costs no extra engine call.
- **When it fires.** After the text's first preparation, and after any later preparation whose summary differs from
  the last one delivered. A paint-only change (`measure()` unchanged) or a transform change does not fire it. It
  fires at most once per text per `glyph.prepare()` or `glyph.shape()`, in a phase after the batch prepare and before
  any root stages. It does **not** fire from an on-demand read, because the read's caller already has the answer.
- **Rules.** The callback may read anything and may write transforms, `visible` and paint. Writing a layout input
  (`text`, `font`, non-paint `style`, `layout`, `constraints`, `flow`, `rasterPixelRatio`, spans) of **any**
  registered text throws `GlyphLayoutPhaseError` (code `'layout-phase'`) immediately and the text keeps its value. A
  throw from the callback propagates: the other callbacks still run and the frame publishes, then the render throws
  it (Three, R3F: `renderer.render()`; TypeGPU: the root's next `draw()`). In Vue a throwing `@layout` handler goes to
  Vue's own error handling.
- **Drawn after its callback.** A text with a callback is drawn only at a layout its callback has seen. What a
  callback writes is drawn by the same frame, the first frame included, with or without `root.attach(scene)`.
- **Late installation.** A callback installed on text that is already drawn receives the current layout in the
  next frame.

### (b) Editing API (built)

```ts
caret(position: TextPosition): TextCaret // { rect, line, level, secondary, clipped }
hitTest(point: LayoutPoint): TextPosition // { offset, affinity }
move(position: TextPosition, direction: TextDirection, unit: TextUnit, goalX?: number): TextMovement // { position, goalX }
boundary(position: TextPosition, unit: TextUnit): TextRange // { start, end }
rangeRects(start: number, end: number): readonly LayoutBox[]
replace(start: number, end: number, insert: string): void
```

These six methods and `TextOffsetError` are the whole surface, on Three `Text`, `TypeGpuText` and `Pixi3DText`
(`tests/types/pixi3d-api.test.ts`). `TextAffinity` is `'upstream' | 'downstream'`; `TextUnit` is
`'grapheme' | 'word' | 'sentence' | 'line'`; `TextDirection` is
`'forward' | 'backward' | 'left' | 'right' | 'up' | 'down'`.

- Offsets are UTF-16 code units of the source text. Coordinates are Text-local, +Y down, anchor applied. `forward` and
  `backward` are logical; `left` and `right` are visual across bidi runs; `up` and `down` take `unit: 'line'` and use
  `goalX`.
- Each query prepares the text if a setter left it dirty, makes one engine call, publishes nothing, and never returns
  `undefined`.
- **Grapheme boundaries are the engine's**, not `Intl.Segmenter`'s. Boundaries inside a ligature are valid stops;
  conjuncts and emoji sequences move as one unit.
- `TextCaret` keeps `secondary` (the other side's rectangle at a bidi boundary) and `clipped` (the offset is in text
  the layout did not draw).
- **Lone surrogates** in `insert` or in the text render as U+FFFD; nothing is counted and there is no API for them.
- `replace` edits exactly the range it names and rebases style spans: inserted text takes the style of the grapheme
  before it.

```ts
class TextOffsetError extends GlyphError<'invalid-offset'> {
  readonly method: 'replace' | 'caret' | 'move' | 'boundary' | 'rangeRects';
  readonly argument: 'start' | 'end' | 'offset';
  readonly offset: number; // the value as given
  readonly reason: 'not-integer' | 'out-of-range' | 'reversed' | 'inside-grapheme';
  readonly textLength: number;
  readonly before: number | undefined; // nearest valid boundary at or before offset
  readonly after: number | undefined; // nearest valid boundary at or after offset
}
```

The old `caretAt`, `caretForOffset` and `selectionRects` and the `GlyphCaret` type are removed (section 3). Caret
drawing, selection state, clipboard, undo, keyboard, pointer and input-method sessions stay with the application.

### (d) Error surface (built)

| Piece                    | 0.1.0                                                                                         | Built                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 5. Open naming questions

1. **Decided: keep `glyph.prepare()`, no per-root version.** Keep `glyph.prepare()`, or use `glyph.layout()` or `glyph.flush()`? Should a per-root `root.prepare()` also exist? The design mentions one, but none is built.
2. Confirm the renames since 0.1.0: `withGlyphs` → `readGlyphs` and `breakApart` → `split`.
3. **Decided: no count, no API.** Lone surrogates render as U+FFFD on every integration; the Three-only `replacedSurrogates` count is removed.
4. `msdfAtlas: 'msdf' | 'sdf'`: keep this option name and these values, or use `atlasChannels: 4 | 1`?
5. Keep `msdfBakedPages`, `MsdfBakedPages`, `MSDF_GLYPH_TABLE_*` and `SLUG_GLYPH_TABLE_STRIDE` in `/core`, or move them to a renderer-author subpath? Slug has no `msdfBakedPages` counterpart, and `SlugBandResidency` is now exported from `/core`.
6. Root hooks `prepared()` and `unchanged()`: keep these names, or use `afterPrepare()` and `skipped()`?
7. `TextGroupBatching` values `'auto' | 'shared' | 'group'`: keep them?
8. **Decided: `(text, layout)`, on summary change, and `glyph.prepare()` runs it.** `onLayout`: one `(text, layout)` signature or an event object; fire only when the summary changes, or on every preparation; and should `glyph.prepare()` run it?
9. **Decided: replaced.** The editing methods replace `caretAt`, `caretForOffset` and `selectionRects` with no aliases, and throw `TextOffsetError` instead of snapping, clipping or swapping.
10. **Decided: `'upstream' | 'downstream'`.** Affinity values.
11. **Decided: no session.** `text.edit()`, `setMarkedText` and the marked range were dropped; `replace` and `TextOffsetError` stay, and `GlyphErrorCode` gained `'invalid-offset'` and `'invalid-input'`.
12. **Decided: `replace` rebases spans.** Inserted text takes the style of the grapheme before it.
13. **Decided: an array.** Input error `path`: an array (`['spans', 2, 'start']`) or a dotted string (`'spans[2].start'`)?
14. **Decided: a new `<GlyphErrorBoundary>`.** In-canvas error handling: a new `<GlyphErrorBoundary>`, or widen `GlyphProvider errorFallback`?
15. **Decided: values stay kebab-case; the comment is fixed.** `TextAnchorY`'s comment calls its values "the exact kebab-case names returned by measure()", but `measure()` returns camelCase fields (`alphabeticBaseline`). Which wording should the docs use?
16. **Decided: removed, with every `onError`.** `TextFrameError` had no caller. Render-time failures are thrown from the render instead of reported to a callback ([decision](decisions/render-time-errors-throw.md)).
