## 4. Approved shapes: (a) and (d) are built, (b) and (c) are not

`onLayout` (a) and the error surface (d) were approved and are built as described below; the names are final. The
editing queries (b) and the editing session (c) remain proposals: `edit(` and `TextPosition` have no matches in
`src/`.

### (a) `onLayout` (built)

| Integration    | Built form                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Three          | `text.onLayout: ((text: Text, layout: ParagraphLayoutSummary) => void) \| undefined`, a property like today's `onError` |
| R3F            | `<Text onLayout={(text, layout) => …}>`                                                                                 |
| Vue            | `@layout="(text, layout) => …"`, emitted like today's `error` event                                                     |
| TypeGPU-direct | `TypeGpuTextOptions.onLayout?`, and a settable `text.onLayout` property                                                 |

- **Argument.** The text and its `ParagraphLayoutSummary`, the same object `text.measure()` would return:
  unanchored, with `anchorOffset`. Reading it costs no extra engine call.
- **When it fires.** After the text's first preparation, and after any later preparation whose summary differs from
  the last one delivered. A paint-only change (`measure()` unchanged) or a transform change does not fire it. It
  fires at most once per text per `glyph.prepare()` or `glyph.shape()`, in a phase after the batch prepare and before
  any root stages. It does **not** fire from an on-demand read, because the read's caller already has the answer.
- **Rules.** The callback may read anything and may write transforms, `visible` and paint. Writing a layout input
  (`text`, `font`, non-paint `style`, `layout`, `constraints`, `flow`, `rasterPixelRatio`, spans) of **any**
  registered text throws `GlyphLayoutPhaseError` (code `'layout-phase'`) immediately and the text keeps its value. A
  throw from the callback is caught and reported to that text's `onError` and the root's `onError`; the other
  callbacks run and the frame publishes. In Vue a throwing `@layout` handler goes to Vue's own error handling.
- **Drawn after its callback.** A text with a callback is drawn only at a layout its callback has seen. What a
  callback writes is drawn by the same frame, the first frame included, with or without `root.attach(scene)`.
- **Late installation.** A callback installed on text that is already drawn receives the current layout in the
  next frame.

### (b) Editing queries

```ts
type TextAffinity = 'upstream' | 'downstream';
interface TextPosition { readonly offset: number; readonly affinity: TextAffinity }
type TextUnit = 'grapheme' | 'word' | 'sentence' | 'line';
type TextDirection = 'forward' | 'backward' | 'left' | 'right' | 'up' | 'down';

caret(position: TextPosition): { rect: LayoutBox; line: number; level: number }
hitTest(point: LayoutPoint): TextPosition
move(position: TextPosition, direction: TextDirection, unit: TextUnit, goalX?: number): { position: TextPosition; goalX: number }
boundary(position: TextPosition, unit: TextUnit): { start: number; end: number }   // the unit that contains position
rangeRects(start: number, end: number): readonly LayoutBox[]
```

- Offsets are UTF-16 code units of the source text. Coordinates are Text-local, +Y down, anchor applied, the same as
  today's `caretAt`. `forward` and `backward` are logical; `left` and `right` are visual across bidi runs; `up` and
  `down` take `unit: 'line'` and use `goalX`. Each call makes one engine crossing and returns a fixed-size answer.
- **Ligature carets.** Grapheme boundaries inside a true ligature cluster (Latin, Arabic, Hebrew) are valid stops.
  Their x comes from GDEF `LigCaretList` when the bake kept it, otherwise from dividing the ligature evenly by
  component. Indic conjuncts and emoji sequences move as one unit.
- **Methods that exist today:**

| Existing name                                                                                                   | Behaviour today                                                                                                                              | Becomes                       |
| --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `Text.caretAt(x, y)` (Three), `GlyphPlacements.caretAt`                                                         | Nearest cluster boundary                                                                                                                     | `hitTest` then `caret`        |
| `Text.caretForOffset(offset)` (Three, new since 0.1.0), `GlyphPlacements.caretForOffset` (`glyph-placement.ts`) | No affinity. An offset inside a cluster **snaps to the cluster's start**. Throws `RangeError` only for a non-integer or out-of-range offset. | `caret({ offset, affinity })` |
| `Text.selectionRects(start, end)`, `GlyphPlacements.selectionRects`                                             | Swaps a reversed range and **clips** an out-of-range one; throws only for non-finite values                                                  | `rangeRects`                  |
| `GlyphCaret.leading`                                                                                            | Mixes up which bidi side the caret is on with line-end affinity                                                                              | `TextPosition.affinity`       |

`TypeGpuText` has no caret methods today.

- **Name alternatives:** `hitTest` → `positionAt`; `rangeRects` → `selectionRects` (keep the current name);
  `TextAffinity` values → `'before' | 'after'`.

### (c) Editing session

```ts
const session = text.edit(); // TextEditSession
session.replace(start, end, insert); // offsets: UTF-16 code units of the source text
session.setMarkedText(start, end, insert); // IME: replace [start, end) and mark the inserted range
session.markedRange; // { start, end } | undefined; later replaces keep it up to date
session.unmark(); // IME commit
session.dispose(); // ends the session; the derived lanes stop being maintained
```

The owner's conditions, quoted from the build log (2026-11-21): _"it must not reintroduce the edge cases that caused
API errors before; it throws when misused; and it must be easy to understand"_, and the design rule recorded with
them: _"offsets are UTF-16 code units of the source text and nothing else"_. As restated in the brief for this
summary: an offset that is out of range, reversed or not on a grapheme boundary throws a typed error naming the
offset and the nearest valid boundaries; nothing is snapped silently.

```ts
class TextOffsetError extends GlyphError<'invalid-offset'> {
  readonly method: 'replace' | 'setMarkedText' | 'caret' | 'move' | 'boundary' | 'rangeRects';
  readonly argument: 'start' | 'end' | 'offset';
  readonly offset: number; // the value as given
  readonly reason: 'not-integer' | 'out-of-range' | 'reversed' | 'inside-grapheme';
  readonly textLength: number;
  readonly before: number | undefined; // nearest valid boundary ≤ offset
  readonly after: number | undefined; // nearest valid boundary ≥ offset
}
// message: "replace(): end 5 is inside a grapheme; nearest boundaries are 4 and 6 (UTF-16 code units of the source text)"
```

- **Grapheme boundaries are Rust's.** They use the engine's Unicode version, not `Intl.Segmenter`; review H3 found
  the TypeScript check unsafe. Validation may therefore need one engine crossing.
- **Lone surrogates in `insert`** are drawn as U+FFFD, as setters do now; nothing is counted.
- **Marked ranges** are drawn from `rangeRects` geometry and are never style spans. As a span, a marked boundary
  inside `fi` or lam-alef would split a shaping cluster.
- **Name alternatives:** `edit()` → `beginEdit()`; `replace` → `replaceRange`; `TextOffsetError` →
  `TextRangeError`.

| Publication-time failure | `Text.onError`, `TextGroup.onError`, R3F `onError` prop, Vue `error` event, `TextFrameError`. | Unchanged per text. `root.onError` receives renderer rejection, fixed capacity, engine traps, refusals and layout-callback exceptions. TypeGPU-direct text has `error` and `onError`. GPU device loss is not detected.                                                                                                                                                                   |
| R3F in-canvas boundary   | `GlyphProvider errorFallback` catches only `GlyphFontError`.                                  | `<GlyphErrorBoundary fallback={(error, reset) => …} onError={…}>` renders inside `<Canvas>` and catches every error of the subtree it wraps.                                                                                                                                                                                                                                             |

The dispositions of every failure are in the [failure inventory](failure-inventory.md).

## 5. Open naming questions

1. **Decided: keep `glyph.prepare()`, no per-root version.** Keep `glyph.prepare()`, or use `glyph.layout()` or `glyph.flush()`? Should a per-root `root.prepare()` also exist? The design mentions one, but none is built.
2. Confirm the renames since 0.1.0: `withGlyphs` → `readGlyphs` and `breakApart` → `split`.
3. **Decided: removed, no public surface.** `replacedSurrogates` existed only on Three `Text`. Should TypeGPU and core get it too, and is the name right (alternative: `loneSurrogateCount`)?
4. `msdfAtlas: 'msdf' | 'sdf'`: keep this option name and these values, or use `atlasChannels: 4 | 1`?
5. Keep `msdfBakedPages`, `MsdfBakedPages`, `MSDF_GLYPH_TABLE_*` and `SLUG_GLYPH_TABLE_STRIDE` in `/core`, or move them to a renderer-author subpath? Slug has no `msdfBakedPages` counterpart, and the `slugSchema` doc comment names `SlugBandResidency`, which is not exported.
6. Root hooks `prepared()` and `unchanged()`: keep these names, or use `afterPrepare()` and `skipped()`?
7. `TextGroupBatching` values `'auto' | 'shared' | 'group'`: keep them?
8. **Decided: `(text, layout)`, on summary change, and `glyph.prepare()` runs it.** `onLayout`: one `(text, layout)` signature or an event object; fire only when the summary changes, or on every preparation; and should `glyph.prepare()` run it?
9. Editing queries: replace `caretAt`, `caretForOffset` and `selectionRects` in this breaking release, or keep them as aliases? Should those methods also throw instead of snapping, clipping or swapping?
10. Affinity values: `'upstream' | 'downstream'` or `'before' | 'after'`?
11. Editing session: keep `text.edit()`, `replace` and `setMarkedText`; name the error `TextOffsetError`; add the new `GlyphErrorCode` values `'invalid-offset'` and `'invalid-input'`?
12. When the text has style spans, should `replace()` throw, or should the inserted text take the style of the cluster before it? (Today the library never rebases spans.)
13. **Decided: an array.** Input error `path`: an array (`['spans', 2, 'start']`) or a dotted string (`'spans[2].start'`)?
14. **Decided: a new `<GlyphErrorBoundary>`.** In-canvas error handling: a new `<GlyphErrorBoundary>`, or widen `GlyphProvider errorFallback`?
15. **Decided: values stay kebab-case; the comment is fixed.** `TextAnchorY`'s comment calls its values "the exact kebab-case names returned by measure()", but `measure()` returns camelCase fields (`alphabeticBaseline`). Which wording should the docs use?
