# Fixed sampling protocol: fresh scoped High review

**Verdict: two admission guards need correction before the E6 full matrix.** The pinned Labs 0.9.0 patch itself has a coherent single-call route, and the protocol fixture proves that route for one isolated benchmark through eight fresh blocks. This is a read-only review of benchmark policy at worktree HEAD `b8fc4ce023f667c714e1b797ef9ff6ec0ec3fa0d` plus the listed uncommitted benchmark files. It does not review the ten frozen Rust changes, run a gate, produce E6 timings, or establish performance or seven-family parity.

## Findings

1. **[P1] Fixed-policy saved candidate reuse can bypass the harness digest.** `benches/scripts/support/saved-package-labs.mts:105-120` accepts a manifest without `harnessDigest` and falls back to `git diff --name-only <saved-commit>`. The new dependency patch is currently untracked, so this fallback cannot authenticate its bytes; it also does not read edited file contents the way `packageLabsHarnessDigest()` does. A saved manifest that claims `samplingPolicy: 'single-call'` but has its digest removed can therefore be accepted after a timing-input change if its artifact, environment, and recorded result still match. The policy and `plan.batch=false` checks at lines 81-104 do not close that input-identity hole. Require a present, 64-hex, equal `harnessDigest` for fixed-policy reuse; retain any intentional legacy fallback only for an explicitly justified old adaptive format. Add a negative saved-run test that deletes the digest from a fixed-policy manifest while keeping the other fields valid. This is a correction to the reuse validator, not to the Labs timer or callbacks.

2. **[P2] Full-suite completeness is checked only on the candidate.** `benches/scripts/run-package-labs.mts:113-120` requires 145 candidate run names under full single-call sampling. `runLabs` at lines 346-369 validates plans and block medians on whatever baseline rows were recorded, but it has no full-arm identity assertion. A truncated main or E2 baseline, or an unexpectedly incomplete published baseline, could be saved and compared without clearly failing this 145-identity policy. Make exact 145-identity coverage the default for every full baseline. Add one explicit caller-selected `published-no-outlines` availability mode that permits only the two named `outlines.bench.ts` identities to be absent: `copy per-glyph metrics with outlines after text change` and `read every outline from an unchanged copy`. Record that declared baseline mode in each arm's manifest; saved candidate reuse must still validate its own 145-identity contract while allowing a different declared baseline mode in the next arm. Do not infer availability from version, because these archives share version 0.1.0. Compare identity sets, not merely counts. Baseline check errors can remain explicit unavailable comparisons; they must not become silent absent rows. A fixture with one missing baseline row beyond those two is a deterministic negative control.

## What the reviewed implementation establishes

The dependency patch adds `LabsConfig.samplingPolicy?: 'adaptive' | 'single-call'`, validates it, defaults to adaptive, forwards the resolved value through the CLI's explicit worker environment, and supplies `batch: false` in `parseTuneEnv()` for the fixed policy. The installed package is `@pmndrs/labs` 0.9.0 under a pnpm path containing the registered patch hash. The installed Labs `measure` honors explicit `opts.batch` after its first-call eligibility probe. Its pilot plan is then replayed across later fresh-process blocks; `planOverrides()` takes the pilot's `batch` decision and fixed sample count. No patched hunk changes the measurement loop, clock, callback, fixture, or suite registration. The normal runner passes `GLYPH_LABS_SAMPLING_POLICY` for each fresh arm, while Labs strips inherited `LABS_*` variables before setting its worker inputs.

For successful runs in fixed mode, `assertLabsSamplingPolicy()` requires `stats.plan.batch === false` and exactly the requested number of finite block medians. A baseline run with a benchmark error has no timing claim and is deliberately reported unavailable; candidate errors fail. The isolated `protocol-proof.json` receipt reports adaptive batching under forced eligibility, explicit fixed non-batching, an eight-block patched CLI/worker result, and rejection of invalid config and runner values. Its infinite eligibility thresholds make the control deterministic rather than dependent on a favorable clock sample. This is proof of the patched route for a fixture, not a measurement of Glyph's 145 callbacks. The static audit confirms unchanged benchmark callback source and a historical 145-identity candidate; it cannot substitute for the new matrix's actual identity and plan checks.

The manifest records `samplingPolicy`; exact-policy reuse rejects an old manifest with no policy. The digest's path set includes actual dependency patch bytes, workspace and lock files, config, runner, and result/reuse logic, including untracked nonignored files. The patch SHA-256 is `1475111a563f675ba8de804b57a4a7500acad4f500771713dad8ad33b5be3002`, equal to the lock registration and installed pnpm patch path. The structural audit records unchanged non-Labs resolutions, importers, and snapshots. No reviewed hunk changes Glyph product/runtime dependencies or benchmark callbacks. The handoff records focused static and nine release-comparison tests passing; this review did not rerun them.
