## The current direct-operand hybrid

`state.rs:2030–2210,2970–3150`, `codec_gather.rs:597–718,1651–1900`, and `render_plan_compiler.rs:224–285` show one executor with a conservative direct admission. It requires a previous retained source correspondence, sparse-eligible order, complete whole-owner source intervals, unchanged selected-record count and the same storage topology, valid declared semantic and binding fields, and no decorated owner; failed admission returns to the packed path. The candidate builds a metadata-only gather workspace with `PlanGlyph`, masks, source correspondence and a 20-byte `DirectRowLocator` per selected row, then the ordered codec reads operands from current semantic/binding columns through those locators. It omits the retained packed field writes on admitted rows, but it does not avoid selecting each source, building planned glyphs, loading codec operands, deriving physical states, or writing renderer bytes. Selected-to-selected identity and selection changes can remain eligible under the existing full-change-mask and topology authority; a zero mask with changed selection rejects direct admission. It preserves the old packed fallback and allocates transient candidate storage. `direct_semantic_sources_total`/`direct_binding_sources_total` guard error equivalence rather than trusting a partial program input; metadata-only state cannot later masquerade as full packed columns.

The E5 exact Bitmap `full05` corrected native replay (`correction_bitmap_full05_output/native-work-ledger.json`, `identity.json`; terminal `correction_bitmap_full05_gate/result.json`) has 6,157 events, 4,099 encoded results and 1,977,392 encoded-result bytes. Its ledger SHA-256 `ceb89ce241102c79f055837a2be463f49c0c118c8c42dd3424abdfdc1dad3730` is byte-identical to the earlier `bitmap-native-ledger-direct-gate/native-work-ledger.json`; the corrected identity hashes match the final five Rust source files I inspected. In each of two publication totals, direct admission/completion is 1/1 with no miss, 10,240 visited source rows, 9,216 selected rows, **zero actual gather f32/u32 slot writes**, 138,240 f32 + 36,864 u32 direct operand loads, and 184,320 locator bytes. E4's authenticated warm comparison actually wrote 97,280 f32 + 20,480 u32 slots, or 117,760 slots / 471,040 bytes, per matching publication (`E4/native-work-ledger.json.raw`); these are the actual removed gather writes in this native trace. The E5 `elidedFullFieldWrites=175,104` counter increments by every selected program's declared input count and represents a **hypothetical full-fresh-field-write count**, not E4 writes deleted. Direct operand loads sum to that same count because the codec executes those declared inputs; they do not equal the prior actual write count and may have different locality. This is a scoped work substitution, not a net traffic, GC or elapsed-speed claim. Earlier failed and corrected receipts are kept in E5; the passing final package/check/pack/named summary has exit 0 and frozen source identity. E5's shipping shaper is 1,625,526 raw bytes versus prior E2 1,609,247 (+16,279), from `wasm-abi-and-section-evidence.json`; exact ABI imports/export signatures versus E2 remain equal and named standard sections match shipping. E5's final engine-allocator live-memory measurement reports maximum requested live 41,848,831 bytes, completed-call peak 42,049,147 and 774 maximum Wasm pages, versus E4/E2 40,471,115/40,671,431/728 under the same stated 71-phase protocol. That is about +1.38 MB requested live and +46 pages, limited to the shaper/engine allocator; it is not JS heap, renderer resource, or whole-application peak. Current latency and GC are unknown. The frozen source's 2,010 additions/240 deletions make deletion and local reasoning as important to admission as a favorable median.

The design's direct path is plausible for a stable dense rewrite because it removes full SoA staging while retaining packed output; it is less compelling for cold (no previous correspondence), topology/recordless changes (fallback), or sparse changes where full candidate scanning and 20-byte locators can overwhelm a small dirty interval. An admission miss can pay direct preflight/partial construction _and_ legacy gather. Test that frequency; do not infer from one successful Bitmap event. SIMD/SWAR remain useful in UTF-16 discovery, masks and codec stores, but the fused direct operand path may turn contiguous SoA loads into scattered semantic/binding loads. Hardware timing, cache misses, GC and end-to-end p95 must decide whether that trade wins. No speculative cache, second semantic pipeline or segmented physical representation follows from these receipts.

## Ranked coherent options and deletion criteria

1. **Measure E5 as frozen; decide on the whole variant and preserve every correct component.** Run one full seven-family eight-block matrix against same-machine main and release, reuse the exact candidate archive, and include E2 and E4 as independent prior controls where possible. Preserve raw absolute p50/p95, modes/exclusions, clock drift, size, scoped memory, host/JS memory and renderer bytes. A validated dense or other family gain is eligible to remain in the coherent hybrid even if this wave does not close overall parity; no arbitrary 5% floor applies. Retain E5 as the working base when its whole-variant evidence supports the gain and guards against adverse tradeoffs, then use a bounded coherent wave on the remaining gap. A correct but inconclusive component remains preserved and can be assessed in a compatible combination; it need not be promoted as a proved speedup. Restore E2/E4 as the working base only if the full evidence shows an adverse tradeoff, or the added complexity/memory has no defensible benefit. Keep E5 independently recoverable in either case.
2. **If E5 helps dense but misses a narrow guard, reduce admitted-path duplication inside the same owners.** A single accepted row iterator/source locator should feed codec and ordered emission while reusing the existing `PlanGlyph`, masks, and packed physical buffers. Delete the redundant full-field gather _and_ any repeated source/selection pass only after counters show both are replaced; collapse separate direct/packed control flow where one conditional operand provider can preserve cold and sparse paths. Keep 32-record rope/block layout and one ordered/session commit. The rollback unit is the whole coherent source wave, not a helper. Independent cold packed-output and host-byte equality, topology/recordless/fallback, error precedence, abort/retry, generation/lease and split independence must pass. Memory peak must fall or be justified by an end-to-end benefit.
3. **If dense remains open after E5, target the measured residual.** Retain any supported whole-variant gains from E5, including gains outside dense, while profiling the exact 512/1024 scene with named shipping Wasm to separate setter preparation, gather, ordered emission and host acceptance. Select the largest source-proven removable operation, possibly repeated request/semantic work across dense per-label setters or repeated source walks, while preserving each setter's completed queryable revision. Coalesce only _publication_ dirt and immutable request descriptors; do not coalesce or defer semantic acceptance. The deleted path must be identified by function/counter before code changes. For long Fredoka, a separate safe-run closure proof is needed; prior failed unsafe-window ideas are not reusable merely because dense remains slow.

The first two are one candidate and at most one corrective wave; a third bounded wave should only address a measured residual with a named deletion target. Each wave changes one ownership boundary in the existing layout, carries a clear revert point, and passes cold semantic/layout oracle, byte-identical physical output, error/rollback/lifetime proof, then main+release seven-family matrix. Final acceptance is family-level p50 and p95 parity over equivalent operations; admission of a coherent intermediate wave instead requires a validated benefit, preserved correctness and an explicit whole-variant tradeoff decision, not already-complete parity. Explain and decide every adverse small row; also check both synchronous setter-only and set/read/publish, width/inspection, independent split/copy, sparse 1/100/1,000, dense 512/1,024, long Unicode/unsafe, cold 22k, no-op/order, renderer batching/order, size/raw-gzip, engine and whole-application memory, ABI/peer and browser/hero. An excluded or missing mode is a gap, never a pass. No result here establishes that all guards can be simultaneously met, but source does not prove an impossibility either.

## Reconciliation with prior advice, after independent assessment

I agree with the accepted `retained-prepare-publish` decision's one synchronous executor, lazy unrequested summary, separate semantic/publication revisions and independent split lifetime. I agree with the 16 October reconciliation that current sparse wins and dense regressions are simultaneous, and with the E4 admission review that full-family parity is open. I disagree with treating a broad workload-win count, a neutral E2 comparison, or an exact native work deletion as a release verdict. The older final plan's profiles and `d6` figures are historical for different source/artifacts; its conditional emphasis on dense output remains useful but cannot assign E5 latency. The E3 hybrid's measured failure is a warning against adding metadata/candidate work without deleting enough production work, not proof that all hybrids fail. I found no authenticated old ignored profile in this checkout and used no invented timing from one.

**Next move:** finish the already-authorized frozen E5 timing/whole-memory assessment, without another source edit. If its full matrix validates a dense or other family gain and the whole-variant tradeoff is acceptable, retain it as a coherent component and choose the next bounded deletion from the remaining measured gap; closing dense parity in this one wave is not required for that retention. If results are inconclusive, preserve E5 independently and assess it with compatible components without claiming a win. Restore a prior working base only after an adverse tradeoff or a supported complexity-without-benefit decision, then profile exact shipping source for the next deletion. In every branch, keep PRs held until all seven families and product gates pass; no speculative architecture expansion is justified now.
