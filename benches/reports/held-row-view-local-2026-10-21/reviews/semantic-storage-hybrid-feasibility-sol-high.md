# Semantic storage hybrid feasibility: main, E2, and current

21 October 2026. Read-only comparison of pinned main `4e25a96a57462fef5ad0d19065a822695b480f60`, E2 `a829b86bfefcd0e39b6d947cb7a2571776cd06a0`, and the preserved current E6 source in `/Volumes/Depot/Developer/glyph/.cache/held-rerun-20261019/repo`. This report addresses semantic storage and revision ownership, not physical gather. I did not build, time, profile, edit source/Git, or use partial results from the live matrix.

## Decision

There is **no source-proven new short-paragraph storage hybrid to implement**. Main already has the same two-buffer semantic stage architecture and flat shape/cluster/positioned arrays. E2 changed the *flow lines and fragments* from two flat vectors to two 32-record copy-on-write ropes; a one-line, one-fragment label already uses one leaf per rope, and the iterator explicitly dispatches that leaf to a slice iterator. Warm short-label rebuilds can clear a uniquely owned leaf while retaining its capacity. Introducing a parallel flat short-flow representation would add a second persistent semantic format, conversion and branch authority without deleting a measured owner. That crosses the unapproved segmented/inline-storage design boundary. A smaller internal fusion of existing flow traversals remains imaginable, but the current evidence does not identify a sufficiently large, redundant pass to justify it as the next wave.

This conclusion does **not** say the short path costs nothing or that the performance gap is contractual. It says the proposed storage change does not yet have a concrete deletion. The E2 measured control already embodies the approved packed-dense/retained-sparse combination, so repackaging it as a new hybrid would not answer the dense parity problem.

## Short label versus long wrapped paragraph

For the authenticated actual Bitmap alpha↔bravo warm replay, each direction has **1,024 distinct 10-unit setters**, 1,024 full cluster builds, 1,024 HarfRust calls, 1,024 recomposed flow lines and 10,240 newly positioned glyph visits. Query preparation records **2,048 rope pushes, 6,144 rope iterator starts, 2,048 rope point queries and zero bulk retained-range records**. The source path and counts are consistent with one flow line and one fragment pushed per label, plus several reads of that tiny flow; they are work counts, not latency or leaf-allocation counts. The ledger is `E6/bitmap-native-replay/native-work-ledger.json`, native direct engine/frame replay with exact output; it excludes JS/host allocation, Wasm SIMD latency, GC, and whole-family parity.

On this short shape, each rope fits a single leaf. `RopeIter::new` chooses `Leaf(items[range].iter())`, without a tree stack; `RopeCursor` likewise borrows that leaf. `RetainedRope::clear` clears the leaf's Vec and resets its summary if the Arc root is unique. The double-buffer swap means each revision can reuse the retired candidate leaf. The exact replay does not record leaf allocations, so uniqueness and zero warm allocations are source-path expectations, **not measured facts**. If some retained range or external owner shares a root, clear drops it and later push allocates a new leaf; that is a legitimate long/sparse cost, not evidence of the dense short replay doing so.

For a long *wrapped* paragraph with many flow lines/fragments, the rope has roughly `ceil(records/32)` leaves plus branch nodes. Locating a source position or fragment prefix uses summaries and tree depth; retaining an unchanged interior suffix shares Arcs, while boundary leaves may copy. Main's flat vectors offer contiguous iteration and reserve/reuse, but retaining a long suffix copies each record. E2's extra node allocations and pointer traversal buy asymptotically narrower retained work. Exact performance depends on line count, dirty interval, fanout and memory locality. Existing long-edit wins make wholesale rope removal unsafe.

## Deletion inventory and candidate boundary

- **Already absent:** There is no rope for shape/cluster/positioned columns to remove. There is no E2-only stage double buffer to remove. There is no short-flow tree walk to specialize: the rope iterator already has a leaf slice path.
- **Potentially removable, but currently unpriced:** A short full rebuild still executes summary updates on two pushes, derives fragment positions through summaries, and starts several leaf iterators/cursors. A *single semantic executor* could fuse consumers that reread the same line/fragment pair, or remove a proved redundant query, while keeping the existing `FlowLayoutArena`/rope leaf and positioned SoA as sole owners. That is a local traversal deletion, not a second storage representation. The current native counts show visits but not which starts are semantically redundant or expensive; source inspection does not establish a safe whole-pass deletion.
- **Must not add now:** A `Vec` short-flow sidecar, inline record field beside rope, per-paragraph format flag, mirrored flat cache, or separately compiled tiny-layout executor would create a second authoritative representation and synchronization/rollback burden. Treat that as an unapproved storage migration. A scalar special case that bypasses Unicode/bidi/shaping or identity/masks would also fail the synchronous cold-output contract.

**Readiness:** no new semantic-storage implementation wave is admitted from this comparison. Preserve the E2 retained-flow/single-leaf path as the long/sparse strength and the existing flat SoA stages as the short/locality strength. After the full matrix is terminal and a source choice is recorded, the next executable question is whether a specific rope read in actual Bitmap short preparation can be eliminated from its producer/consumer chain without duplicating stage state. The existing ledger already supplies per-event push/iterator/point-query counts, so do not repeat generic counters. A bounded source-level audit would name each of the six iterator starts and two point queries, its consumer and whether it can share an existing cursor; only a complete eliminated pass with exact cold-output and long/sparse noninterference would justify a small wave. If all reads are necessary, retire this avenue. The separately prepared first shape-boundary observation is a different exact semantic question; it is not a storage hybrid or authorized suffix patch.

A structural limit cannot be inferred from E2/E5 latency alone. It would require same-contract stage and allocation timing on the exact distinct-label fixture, plus proof that remaining line/fragment traversals and stage columns are necessary and that the retained single-leaf path approaches the cost of a correct flat reference. Current evidence proves efficient short storage shape and substantial required semantic work, not the fraction of wall time attributable to rope bookkeeping.
