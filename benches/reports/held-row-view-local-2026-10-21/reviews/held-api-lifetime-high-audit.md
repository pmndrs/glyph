## Setter, query, rejection, and resource lifetime

`Text.#applyUpdate` (`src/three/text.ts:989-1027`) checks active/staged-mutation state, normalizes input, and calls bound `stageUpdate` before replacing `#desired`/revision. An ordinary validation or preparation error therefore throws at the setter while the accepted authored value remains. In the planner (`src/internal/render-planner.ts:780-874`), candidate preparation precedes state adoption; errors invalidate an unadopted Rust mutation and release candidate bindings. Once adopted, cleanup/dirty-listener failure is explicitly wrapped as `PostCommitError`; `src/internal/configured-handle.ts:897-942` and `src/three/text.ts:1917-1935` recognize that accepted-state case and do not roll it back. The public-path integration test `text-mutation-span-alignment.test.mjs:97,148,253,292,324,402` includes invalid setters, prepared reads/split, post-write failure and recovery. These assertions must be read with the E6 package-check receipt; source alone is not an executed E6 claim.

Reads and copies remain distinct: `Text.measure()` returns prepared measurement; `Text.glyphs()` owns columns; `readGlyphs` uses a synchronous callback with an expiring fixed-size borrow; `split()` copies layout/geometry/resource leases. Real public tests include `three-v1.test.mjs:3404,3583,7736-7949` and `text-mutation-span-alignment.test.mjs:148-252`. This is sufficient source/test design evidence for independence and expiry; the E6 installed archive is still the artifact under decision.

For publication, `RenderPlannerImpl.consume()` (`render-planner.ts:1120-1146`) adopts Rust first, lends a `BorrowedPlanLease` only during synchronous target acceptance, and always expires it. Rejection increments checkpoint generation without setting `engineNeedsRebuild` or scheduling a hidden retry; `adopt()` reserves invalidation for an actual Rust/TypeScript adoption defect (`render-planner.ts:1090-1118`). `GuardedPlanReader` checks lease activity and Wasm transport epoch/memory (`render-planner.ts:1791-1840`; `handle-state.ts:1275-1295`). The projection settles accepted overlays only on acceptance and disposes freshly resolved resources on rejection (`src/internal/create-engine.ts:384-410`); the Three and TypeGPU renderers stage host resources in `decode` and release discarded work (`src/three/command-buffer-renderer.ts:286-305,403-470`; `src/typegpu/internal/renderer.ts:71-254`). Public-path coverage includes borrowed expiry `three-v1.test.mjs:470-499`, Three explicit checkpoint recovery `:4258-4319`, and TypeGPU buffer/paint/anchor rejection `typegpu-integration.test.mjs:307-357,415-429,718-843`. The custom renderer's `commit()` remains an integrator callback: a host that partially mutates its own state then throws is outside what a package-side checkpoint can undo. This is a contract limit, not a demonstrated E6 defect.
