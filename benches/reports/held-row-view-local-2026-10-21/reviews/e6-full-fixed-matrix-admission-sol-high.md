# E6 fixed-matrix admission and source choice

21 October 2026. Fresh read-only native Sol6 High review of the frozen E6 archive `d2f7a01ffb47aeaf87499979310286f1c980b88389e20bd1fc0f39794a0fc18c`, its current source, and the main, published 0.1.0, and prior-E2 controls. This is a source-choice recommendation, not a source edit, package release, or merge clearance.

## Decision

**Do not admit E6 as the active whole variant for the parity goal.** Its complete-operation dense 512 and 1,024 p50s and p95s trail both same-machine main and published 0.1.0, and its 1,024 result is adverse to the measured E2 control. Cold mount, first-set, and unsafe long reflow also leave material control regressions. The extensive sparse, prepared-read, and independent-copy gains over main and release are real observations and must be retained in the architecture. E6 itself is a correct, recoverable combination candidate; its no-floor favorable rows must remain in the evidence. The present matrix does not justify keeping its direct-operand machinery active or selecting a narrow E6 direct mode.

Use the packed gather/ordered compiler and retained sparse paths as the active physical policy. The immediate source fallback is the E4 `59933674684f7b3aaebfa2fc2ce96d8ec3a8629a` HEAD, whose gather input-plan deletion is already in source; E2 `a829b86bfefcd0e39b6d947cb7a2571776cd06a0` remains the separately frozen measured control. E4's historical adaptive timings cannot be paired numerically with this fixed-policy series, so selecting E4 does **not** prove parity or an E4-over-E2 speed advantage. Preserve E6 at snapshot `6bc123abb9fdf07183988dcea12ccc1d1876d1ba` / `experiments/held-row-view-native-gated-20261021` and the frozen archive before retiring its ten dirty Rust-file changes from active source. A later combination may reintroduce a **proved** deletion, not the entire speculative direct branch by default.

## Work, complexity, size and lifetime

The E6 source is HEAD plus ten dirty Rust files, a net 2,045 additions and 232 deletions. Its E5-derived direct branch checks candidate eligibility, walks owners, keeps a second candidate workspace, allocates a 20-byte locator per selected record, resolves semantic/binding sources indirectly and retains packed fallback. E6's four-file row-view correction constructs one borrowed 17-slice view per loaded selected record/four-lane group within **the same** scalar/SIMD Codec interpreter. In the authenticated forward and reverse Bitmap publications, each has 10,240 source rows, 9,216 selected rows, 9,216 view constructions, 175,104 active f32/u32 loads, 589,824 compared physical bytes and 368,640 emitted bytes. Relative to E4, 117,760 actual gathered field writes are absent, but 184,320 locator bytes and two owner traversals are added. Counts show work substitution, not elapsed cost, instruction count, or SIMD utilization. Indexed source/record/batch order, canonical bytes, old/new overlap, and accepted-renderer generations still require their authoritative owners. A second physical format or executor is not justified by this result.

The E6 shipping shaper is **1,629,518 raw / 609,071 whole-file gzip bytes**, versus E2 **1,609,247 / 599,549**: +20,271 raw / +9,522 gzip bytes. It is also +3,992 raw / +1,596 gzip bytes over E5; package member counts and JS/declaration/peer members match E2/E5 except the shaper member. The engine-only 71-phase, eight-cycle maximum is **41,848,831 requested-live / 42,049,147 completed-call high-water bytes and 774 Wasm pages**, equal to E5 but +1,377,716 requested-live bytes and +46 pages versus E2. These figures exclude JS, font decoder instances, GPU memory, allocator fragmentation and transient internal reallocation peaks; they are not whole-app physical peak.

Correctness evidence is strong within its stated scope: 6,157 authenticated native replay events, 4,099 exact results, 1,977,392 result bytes; 593 Rust pass occurrences, 1,142 Node passes, exact shipping/named standard-section match, 55/55 minimum-peer tests, static SIMD presence, ABI/package member gates and CPU renderer-recovery all pass. The all-five-success CI run at `59933674684f7b3aaebfa2fc2ce96d8ec3a8629a` does **not** cover the dirty E6 source. The existing [browser and application-memory audit](final-browser-memory-gate-high-audit.md) correctly leaves archived-package browser pixels/editorial hero, downstream consumers and whole-application physical memory open. A package gate or native replay cannot close those obligations. The held stack remains draft, unmerged, untagged and unreleased; final advanced-main integration/revalidation is separate.

## Next coherent proof and possible wave

Retire the active E6 direct candidate, locator, direct Codec source arm, metadata-only mode, extra owner admission and test-only view counters as one source choice, while preserving the complete variant and its evidence. Keep synchronous setter errors and prepared queries, independent split/copy ownership, accepted-revision and in-flight renderer lifetimes, Rust semantic authority, 32-record sparse sharing, packed SoA/SWAR/SIMD, batching and logical order in the existing executor. Avoid a new public bulk API, shadow Unicode/cache, or segmented storage. Source fallbacks and final product gates should be evaluated on their exact future artifact; the present E6 receipt cannot be transferred to a changed source.

The best bounded next discriminator is the [short-shape boundary observation](short-shape-boundary-observation-brief-sol-high.md), **not yet an optimization**. The authenticated actual-Bitmap replay already proves 1,024 warm HarfRust calls, 10,240 shaped units, full cluster builds and 10,240 newly positioned rows in each direction before publication; publication makes zero HarfRust calls. For each of the 2,048 warm edits, record old `UNSAFE_TO_CONCAT`/cluster status at offsets 5–9, the first shape window before whole-run overwrite, new boundary flags, and the precise retry or guard reason. Compare the existing short Inter control without treating it as the Bitmap font. Use test-only hooks in the one existing shaper, preserve exact replay bytes, and remove the exploratory hooks after the decision. This is more discriminating than repeating generic counters or a timing loop and does not promise that five shaped units alone recover whole-operation parity.

If both old and new HarfRust boundaries certify a shorter suffix yet an avoidable guard still chooses `[0,10)`, a coherent source wave may delete that exact broad shape scope **inside** the existing executor. It must prove cold semantic/ID/measurement/copy/split equality, mixed Unicode/ligature/kerning/RTL/fallback and rollback behavior, exact physical/browser output, then run one fixed seven-family main/published/E2 matrix plus size and memory gates. If no earlier boundary is safe, retire suffix reuse for this cohort and name a different measured redundant producer/consumer pass before changing code. The existing ingress writer already writes to the retained Wasm arena; main and E2 already have double-buffered flat shape/cluster/position columns and a single-leaf short-flow rope. A new writer or parallel flat short-flow format has no current source-backed material deletion. Parity remains an engineering goal, not a disproved possibility or a reason to weaken the accepted contract.
