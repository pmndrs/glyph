## Algorithm and ownership

`OrderedPlanCompiler::write_changed_ranges` still selects and completely encodes each active range through the existing codec. After that encoding, a whole field write may be omitted only when there is no checkpoint/allocation/resize; prior batch, program, capability, schema, ID/generation and capacity remain compatible; the aligned range is inside both old and new live counts; and old destination bytes exactly equal the completed payload slice. Any failed predicate uses the ordinary write path. Semantic identity remains authoritative even when raster bytes happen to match.

Kept segments are compacted forward in the same payload Vec, remapping emitted offsets and truncating the unused job tail. No move occurs when offsets already coincide. The cursor cannot pass the next source segment or touch a prior job. Primary/session serialization retains its existing offset-rebase rule. New live tails, aligned capacity tails, changed paint and recovery checkpoints retain writes. Renderer rejection retains preparation but requires a later checkpoint, which disables elision.

Time remains O(encoded bytes + compared bytes + moved retained bytes), with O(1) additional metadata and no second arena/cache/executor. Encoding is not removed. The retired behavior is unconditional emission/serialization of equal physical field writes and the unused payload tail. One existing fallback handles all nonadmitted cases; no parallel implementation remains.
