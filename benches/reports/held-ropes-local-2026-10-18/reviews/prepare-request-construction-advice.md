## Recommendation and exact scope

The removable source-level work is construction of discarded **empty** list values on setter preparation and one transient text-mutation object when text changes. A file-private `const EMPTY_REQUEST_ITEMS: readonly never[] = Object.freeze([])` in `render-planner.ts` is suitable for package-owned empty request/list fields only. It is an immutable value constant, not a stateful cache: it has no key, revision, invalidation, or resource ownership and cannot authorize skipping any engine work. The existing `noRetainedStyleChanges` is a different typed constant for retained style-change state; a single request-list constant keeps request ownership local.

Concrete predicates, preserving existing evaluation order:

1. `compileStyles`: if `state.styleChanges.length === 0`, return `EMPTY_REQUEST_ITEMS` before `map`; otherwise execute the current map unchanged, including style-ID creation and `engineStyleValue` calls.
2. `#prepareTextCandidate`: set `preparedRemovals` to the constant only when `this.#preparationRemovals.size === 0`; otherwise keep `[...this.#preparationRemovals]`. The nonempty branch must remain a snapshot because the same members are removed and their prepared orders released after successful preparation. Keep `preparationChanged`'s current predicates and its early return.
3. Build `paragraphMutations` as the constant **only** when `state.prepared && preparedRemovals.length === 0`. In every other case retain the current removal map, removal-before-upsert order, and upsert predicate. This also avoids evaluating the two empty spread-array expressions in the common prepared case. Do not share a nonempty array.
4. For changed text, construct a single `PlannerTextMutation` with `paragraphId`, `start: 0`, `deleteCount: state.preparedText.length`, and `insert: state.desired.text`; pass that same object in the one-element `textMutations` array. For unchanged text use `EMPTY_REQUEST_ITEMS`. Retain a fresh array for actual text mutations. The current initial three-field object plus a spread into a second four-field object is redundant.
5. In this per-setter request, use the constant for `paragraphOrderMutations`; `constraints` when `geometry === undefined`; `regions` and `exclusions` when `geometry === undefined`; and `inlineObjects` when `geometryChanged === false`. Pass `geometry.regions`/`geometry.exclusions`, `geometry.constraint` in its required one-element array, and the result of `compileInlineObjects` unchanged on geometry changes. Do not broaden this to the publication `#compileFrame`, full-state forks/clones, resolved-resource leases, or geometry/style validation.

`state.styleChanges` already has a text-only fork/fast path for same-length scalar edits (`_updateText` 697–729), so a new font/style-validation cache would duplicate accepted state and add an invalidation problem. One fresh `PlannerFrameUpdate` request object per call, all nonempty mutation copies, synchronous engine preparation, and current callback placement remain required. The common prepared text-only path stays O(1) in request-list construction, with fewer source allocation sites; the authored string's wire encoding and other variable work are unchanged. V8 may eliminate some short-lived objects already, so heap or latency savings are unproven.

## Ownership and behavior audit

`PlannerFrameUpdate` fields are `readonly` arrays. `preparePlannerFrameUpdate` reads their lengths/elements into offsets and a transient prepared descriptor; `writePreparedPlannerFrameUpdate` writes bytes from them without mutation or identity comparison. `#writeFrameRequest` completes prepare/write synchronously and clears scratch in `finally`; the retained request arena contains bytes, not a JS frame reference. `PlanTransport.prepareParagraph` invokes the Rust call and any measurement callback only **after** that write. The no-view path records a result extent; the view path decodes a publication. Neither returns the request arrays. `stageUpdate` retains only request length and initial memory buffer, not the frame. Thus the proposed shared empty list does not appear to escape into caller-visible identity, a later publication, or a borrow lifetime. Its freeze also makes accidental future mutation fail locally.

Keep the empty/nonempty boundary exact. A nonempty `#preparationRemovals` must still be snapshotted before the request; moving deletion or `#releasePreparedOrder` before the Rust call would change failure behavior. The existing flow commits geometry revisions and desired/prepared state only after successful `prepareParagraph` and required measurement, then drains that captured removal list. `#writeFrameRequest` still invalidates the transport epoch, reserves/queries the arena as needed, and clears scratch on a write failure. `prepareParagraph` still marks an unadopted mutation before Rust, checks result pointer/header/status/capacity/fault, and invokes the optional synchronous consumer; rejected preparation still triggers the planner's invalidation/rebuild path. Do not move the construction branch across `compileStyles`, `compileGeometry`, or the `preparationChanged`/measurement-demand gate: those locations fix which side effects and throws occur before a request.

The wire writer uses field values, counts, and order. Empty arrays encode zero count/offset regardless of identity. Its optional-field fallback `?? []` is not a reason to omit fields here: these per-setter requests currently provide them, and omission could merely recreate empty arrays during encoding. No array consumer in the reviewed path uses a mutating method or tests array identity. The change needs no public API, ABI, result type, validator, engine executor, request-pointer reuse, or deferred setter.
