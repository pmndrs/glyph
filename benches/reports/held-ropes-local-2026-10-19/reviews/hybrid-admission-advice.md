# Physical admission and rope compaction: source-only advice

Scope: clean `6987418cc49495c60097801e0d675dec7ae84f77` checkout, 19 October 2026. This is an implementation choice analysis, not a selected change or a measured speedup. No build, test, benchmark, or prototype was run for this note.

## Constraint that changes the earlier suggestion

`prepare_retained_topology` admits each physical row, computes `instance_state`, records binding dirt and dirty physical slots, then chooses a second rope operation (`ordered_plan.rs:1099–1269`). Its all-dirty branch uses `RetainedRope::try_from_exact`, whose 32-record leaves and recursive half-leaf split produce a packed, balanced root (`retained_rope.rs:115–125,446–473`). `update_ordered_ranges` instead reconstructs changed leaves and the existing branch shape (`retained_rope.rs:338–374,1330–1420`). Calling that updater over `0..G` alone would leave previously fragmented/underfilled physical leaves fragmented. `InstanceState` is 16 bytes and its rope summary has only a record count (`ordered_plan.rs:75–89`), so a full candidate vector would add at least 160 KiB for this 10,240-row cycle before capacity and allocator overhead. Keep the exact builder's compaction guarantee explicit.

The native inter attribution says all 10,240 admissions, comparisons, and rewrites occur per cycle, with no clean-copy, retained-gap, or canonical semantic revalidation target. The eight-block timing gate shows the current HELD candidate trailing main: dense 1,024 p50/p95 is 17.738/20.033 ms for HELD versus 15.376/16.493 ms for main; dense 512 is 9.242/10.628 ms for HELD versus 7.617/9.656 ms for main. This cross-arm observation does not establish causality, and source inspection cannot assign the roughly 2.36 ms dense-1,024 p50 gap to this code. The saved CPU capture's inclusive `prepare_retained_topology` row is small; inlining prevents treating it as a hard bound, but the evidence does not establish a large opportunity.

## Option A: one ordered update, lazy leaf fill, conditional exact repack

Use one complete-range ordered traversal for complete scope; keep the current sparse interval admission and coalesced-range updater for sparse scope. Put the current admission checks and `instance_state` derivation in a shared callback invoked from the complete-range updater. It can append dirty physical slots in order and accumulate binding dirt locally. The callback returns `Keep` for equality and `Replace` for difference. Map an invalid retained mapping to the existing complete-topology fallback only after the provisional root and local dirt have been discarded; arithmetic/allocation errors remain errors. Publish `pending_instances`, `dirty_instances`, and binding dirt only after successful traversal. The existing updater already holds the old root on callback/storage failure; preserve its `Stop` prefix behavior for other callers.

**Root's proposed leaf kernel, source-reviewed and not executed:** lazily reserve one replacement `Vec` of `items.len()` on the first `Replace`. Append the unchanged prefix `items[..visited_index]`, then the candidate. Before each later visited row, append the untouched gap `items[replacement.len()..visited_index]`; append the original visited row for `Keep`, or the candidate for `Replace`. On leaf exit, including `Stop`, append `items[replacement.len()..]`. If no `Replace` occurred, retain the old leaf `Arc`. This keeps `replacement.len()` equal to the next output ordinal and never copies an old row that was replaced; unlike the initial 32-`Option<T>` idea, it adds no record-sized stack array and still uses one output `Vec` per changed leaf. `try_reserve_exact(items.len())` must succeed before any append; count only the original rows actually copied in the work counter. The existing test at `retained_rope.rs:2320` expects 128 old copies for 32 replacements across four leaves, so that accounting expectation must change while its traversal and output assertions remain. A `Stop` within a leaf leaves the current and later rows in the copied suffix. Callback or allocation failure drops the local vector and leaves the root unchanged because `update_ordered_ranges` assigns its replacement root only after full success (`retained_rope.rs:338–374`). I found no concrete source-level flaw in this leaf fill, subject to the stated ordinal invariant and normal verification.

For complete all-dirty output, check whether the _source_ root already has the exact packed leaf partition/tree shape; if so, replacing each leaf preserves that shape. If not, rebuild the provisional root with `try_from_exact`, reading its newly computed states and doing no second admission or `instance_state` derivation. This retains the current compaction result and the single semantic admission path.

Cost: packed all-dirty source takes O(G) reads and writes, O(G/32) new leaves/branches, and no old-leaf item copy or second derivation; the structural check adds O(G/32) node visits unless a trustworthy existing shape bit is available. Fragmented all-dirty source adds O(G) copy/repack and a second provisional root, so peak live leaf bytes can approach old + provisional + compacted roots. Sparse stays O(r log G + touched-leaf work) and all-`Keep` can share its original root. The existing `dirty_instances` list is still needed by `compile_batch` (`ordered_plan.rs:1439–1451`). **Deletion targets:** the complete scan followed by `try_from_exact`/second `instance_state` pass, and the old-copy-then-overwrite leaf branch for every changed leaf. Do not add a persistent `InstanceState` cache or change the packed SoA writer.

The main risk is that a structural check, append bookkeeping, and possible repack consume more than the removed scan/derivation. An exact-shape check must prove the recursive leaf partition, not merely total capacity or height. This option is a narrow candidate only if measured dense savings survive fragmented-root and memory gates.

## Option B: optimistic exact builder with bounded fallback policy

The existing exact builder accepts a per-index producer and publishes no root if that producer fails (`retained_rope.rs:115–125,446–473`). For complete scope, a shared admission helper could read each prior physical row and derive its next state inside that producer. Pre-admit row zero and hold its one candidate on the stack; begin `try_from_exact` only if it changed, consuming that held value for index zero. If any subsequent row is `Keep`, stop and discard the candidate, then run the existing mixed/sparse-preserving path. On the successful all-dirty path, the candidate is already packed and balanced, and no row needs a second derivation; the physical dirty list can be filled in order. Invalid mapping triggers the existing complete-topology fallback, distinct from allocation/arithmetic failure. Keep binding dirt and dirty slots provisional across the attempt. An all-`Keep` input aborts before candidate allocation and retains its original `Arc` root.

This needs no new publication executor and no separate G-sized state vector: the speculative `try_from_exact` root is the prospective output itself. It also avoids old-leaf copies for all-dirty output. Its weakness is adversarial mixed input: one unchanged row near the end can waste almost G allocations and derivations, then repeat work in the fallback. A fixed prefix probe or explicit work budget can limit expected waste but cannot prove all-dirty before the final row; no general one-pass algorithm simultaneously guarantees packed all-dirty output, untouched `Arc` sharing for arbitrary mixed input, and zero speculative work without buffering/revisiting. This makes option B less attractive unless the dense cohort is reliably all-dirty and the late-clean case passes a separate worst-case gate. **Deletion target:** the dense scan plus second `instance_state` derivation, while retaining the current mixed updater as fallback. Do not create a second semantic admission implementation; extract the same helper for both paths.

## Decision gate

For either option, first compare independent cold physical/command bytes, order, stable IDs, f32/u32 payloads, prepared queries, and accepted renderer generation; include invalid mapping, callback/storage error, `Stop`, abort, and subsequent commit. Exercise packed, heavily fragmented, all-`Keep`, one dirty leaf, sparse intervals, all-dirty, and late-clean complete scopes. Record admission visits, `instance_state` calls, leaf old-item copies, direct-fill count, exact-repack count, branch/leaf allocations, peak live bytes, and the existing ordered-work counters. Only then compare matched dense 512/1,024 and sparse p50/p95, optimized artifact size, upload bytes, and draws against the ongoing main/release/prior arm. Reject a result that just relocates work into repacking, emission, or host publication. The cached `ProgramDescriptor` full-mask lookup from `next-wave-advice.md` is independent and small; combine it only if its own byte oracle and lookup count prove the deletion.
