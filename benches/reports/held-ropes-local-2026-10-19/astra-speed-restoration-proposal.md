## Recommendation and limit

Proceed with the proposed coherent publication work-removal candidate, with two refinements: check exact tree shape only after successful complete traversal proves a nonempty all-dirty result; express fragmented-tree costs in terms of actual leaves/nodes, not universally `G/32`. Preserve the existing sparse path and exact dense packing. Combine the already-validated full-mask program-count shortcut after its byte oracle. A small additional SIMD finite-value predicate is source-and-codegen-grounded and compatible, but remains a separate optional admission decision.

**This is a credible work-reduction proposal, not an established way to recover the full dense gap.** The current exact dense builder already avoids old physical-leaf copy/overwrite. The proposal's dense saving is the second state derivation and separate admission/rebuild walk; lazy leaf filling enables that fusion without restoring copy/overwrite, and benefits mixed/sparse changed leaves and gather source leaves. Do not count an already-removed dense copy as a new saving. The named topology and mask frames are small. Preparation still dominates the diagnostic phase partition, and the available evidence identifies no safe large preparation deletion.

The contract stays one synchronous Rust preparation executor, prepared queries, independent split ownership, Rust semantic authority, batched logical paint order, current 32-record rope storage and packed SoA output. No new parser, global pool/cache, second executor or segmented storage is warranted. Separate PR311/issue181 cold-material and PR317/Three186 lifetime work are outside this source and this proposal.

## Wave 1: one physical admission and replacement walk

Current producer chain: `render-planner.ts:1233` prepares each bound setter through `handle-state.ts:1371`; `state.rs` adopts prepared text/layout. Publication's gather builds `PlanGlyph`, placement and semantic input lanes. `ordered_plan.rs:1099` admits retained physical mappings and compares `InstanceState`; `compile_batch` consumes sorted dirty slots at `ordered_plan.rs:1440`, and `write_changed_ranges` builds codec runs at `1735`. `plan_packing.rs:120` sends those runs to the same codec executor. Physical payload/patches then reach accepted host generations and GPU uploads. Removing a scan must not change any of these consumers' ordering or identities.

`prepare_retained_topology` currently derives `next` at line 1202, throws it away after comparison, then derives changed states again at 1247 or 1261. The all-dirty path invokes the exact builder; mixed/sparse uses the ordered updater. Keep constant-time fingerprint/lifecycle admission, batch-key/slot mapping and arithmetic checks: they decide whether the retained path is applicable, rather than redundantly parsing semantic text.

Recommended algorithm:

1. Keep sparse scope's existing input-to-physical admission and coalesced updater. Complete scope invokes the existing ordered updater over `0..G`. Its callback performs the shared mapping/batch admission, derives one next state, compares, appends ordered dirty physical slots and accumulates binding dirt. Return `Keep`/`Replace` as today. Do not duplicate semantic admission between branches merely to avoid a predictable scope branch.
2. Use provisional dirty/binding state. A soft retained-admission miss discards the provisional root and dirt before the existing full-topology fallback. Storage/arithmetic/callback failures retain their current error identity. `Stop` must not accidentally turn an admission miss into successful prefix publication. Adopt pending state only after full success.
3. In `retained_rope.rs:1352`, lazily create one replacement Vec on the first Replace, fallibly reserving the complete leaf length (at most 32). Copy the untouched prefix and append the new value. At each later visited index, append any untouched gap, then the old value for Keep or candidate for Replace. On Stop/end append the untouched suffix, including the stopped row. The vector length is the next output ordinal. An all-Keep leaf preserves its Arc, and no replaced old row is copied. The final node summary remains the existing summary producer. No 32-element Option array, shadow state vector, persistent cache or second updater is needed.
4. **Only after complete traversal proves nonempty all-dirty**, determine whether the source root has the exact builder partition and recursive half-leaf split. Packed source preserves that shape through replacement. Otherwise repack the provisional result with `try_from_exact`, consuming computed states, not rerunning admission or `instance_state`. Merely having full leaves, the expected height or enough total capacity does not prove the exact shape. Mixed/all-Keep/sparse scopes must not pay this extra full shape walk.
5. In gather, the cached validated `ProgramDescriptor` at `codec_gather.rs:811` already supplies counts. For `ALL_SEMANTIC_CHANGES` or the same `force_all` selection condition used at `codec.rs:430`, form the exact low-bit masks from those counts without `program_index` at 427. Preserve the existing dependency-derived mask path for partial changes. Reuse one authoritative count-to-mask rule, including the 32-bit boundary, rather than hand-copying a shift that overflows at 32.

Delete the complete admission pass plus second state construction, the changed-leaf copy-all/overwrite branch at `retained_rope.rs:1382`, and the redundant full-mask program lookup. The complete-topology fallback, sparse mapping path, partial dependency masks, sorted dirty slots and canonical output writer serve different valid inputs and remain. The native dense case removes 10,240 second state derivations; it still requires all 10,240 comparisons, replacements and codec records. Gather's 5,120 all-mask records can avoid their second lookup. Source proof does not translate these counts into an elapsed estimate.

Let `K` be existing leaves, `h` height, `r` dirty ranges and `L` touched leaves. Complete traversal is `O(G+K)` and creates `O(K)` changed node shells plus final leaf storage; exact packed input has `K=ceil(G/32)`. Fragmentation can increase K toward G. All-dirty shape inspection is `O(K)` worst case, often earlier on a mismatch. Fragmented all-dirty additionally costs `O(G+K)` traversal/copy/repack and `O(G/32)` compacted nodes. Old, provisional and compacted roots may coexist; the two new copies of 10,240 16-byte states alone total 320 KiB before old storage, capacity and node metadata. Sparse remains conservatively `O(rh+32L)` plus its existing admission; no complete-root scan is added. This is linear dense work with better coefficients, not a new asymptotic claim.

The currently used dense exact builder already writes new values directly (`retained_rope.rs:459`). Lazy fill prevents the proposed fused updater from reintroducing old-row copying and reduces copying for changed gather/mixed leaves; it does not remove a current dense `InstanceState` copy. The current generic updater keeps the old root on failure (`338–370`), but callback side effects are not automatically rolled back. Explicit local dirt ownership is therefore necessary.

Reject the optimistic exact-builder-then-retry-on-Keep alternative as the default: a final clean row can waste nearly a full root and repeat admission. It has no general dominance over the proposed algorithm. Do not replace the measured writer with a new full temporary state vector to solve that tension. If fragmentation costs fail, preserve the correct candidate and revise within the existing storage design rather than silently dropping compaction or hiding a fallback's repeated work.

## SIMD and locality: verified, limited, and optional next work

I ran only a short root-authorized disassembly, with pinned `wasm-dis version 129 (version_129)`, against authenticated named SHA `cfb3213f4b7acc111ef057621081b102e25f64fdd2df8e0c5e6c09b0e2ee36b3`. Existing named parity proves its executable equals shipping. `astra-simd-codegen-evidence.json` records input/WAT hashes and decoded target instructions; `astra-shaper.named.wat` preserves the text. These are real decoded instructions, not raw 0xfd-byte counts, runtime instruction counts, JIT ARM disassembly, throughput or PMU observations.

- The current codec is actually vectorized. `ordered_plan.rs:1735` groups consecutive changed input ordinals; `plan_packing.rs:181` calls `execute_buffers`; `codec.rs:1024` processes `record_count & !3` in four-record groups then scalar tails. The optimized `execute_program` at WAT line 313253 contains vector loads/stores, f32x4 add/sub/mul/lt, bitselect, conversion and shuffles. Its static body has 25 v128.load and 19 v128.store occurrences. These counts establish presence only, not the number executed by a fixture.
- `line_kernels.rs:13` probes four scalar bidi levels, then scans 16 levels at a time. Actual `bidi::analyze_into` contains i8x16.ne/bitmask and a 16-byte load at WAT 463322. Justification's four-block flag scan (`line_kernels.rs:82`) is present in `justification_adjustment` at WAT 24461 onward, with four 16-byte loads/bitmasks. Short labels can remain entirely on scalar portions; wider/unrolled scans cannot automatically improve this dense fixture.
- `state.rs:7185–7246` explicitly packs pairs of UTF-16 units into u32 comparison words before scalar seam alignment. This is source-level packed/SWAR discovery, not a Unicode parser. The helper was inlined/optimized out as a separately named function; this review does not claim an isolated compiled wider-load sequence for it or claim that it is maximally vectorized. Retain its scalar oracle and malformed/surrogate seam tests.
- `codec_gather.rs:408` stores fields as align(16) four-element blocks with contiguous per-field Vec storage; `ShapeArena` uses separate contiguous glyph/cluster/advance/offset columns (`shaping_state.rs:56`). Codec loads consecutive values from those lanes. Rope leaves keep 32 contiguous records, with leaf/tree iteration already specialized. These are concrete locality properties. Arc branches still require indirection and allocation, and fragmented leaves raise metadata traffic. No cache hit rate, cache-miss reduction or maximum utilization is proven without hardware-counter evidence.
- Vector output stores are specialized for tightly packed F32/U32 widths 1/2/4 (`codec.rs:1348`); width 3, U16 and padded schemas use the existing per-lane output fallback at 1408. Do not change packing/ABI merely to improve SIMD utilization. Actual run-length/program mix is not counted in the current native receipt. Grouping must not cross batch/physical order boundaries or compute unrelated rows merely to fill lanes.

**Optional bounded kernel:** `codec.rs:1429` converts one v128 to four scalar words and calls scalar finite classification. The optimized body at WAT 314484–314546 retains four f32x4.extract_lane operations and scalar absolute-bit comparisons. A bitwise vector test can classify all lanes: mask each word by `0x7f800000`, compare with that mask, reduce any true lane, and negate. This exactly rejects positive/negative infinity and every NaN payload; it accepts finite normals, subnormals and both zeros. Keep the existing scalar path and NonFiniteOutput error. This removes four extracts and scalar comparisons per reached vector F32 store check, with a vector mask/compare/reduction in exchange. It introduces no allocation, state, format or semantic executor. It is not a promised speedup, and may be immaterial beside memory/interpreter overhead.

Admit this only with a real Wasm scalar-reference oracle across each lane, +/-infinity, quiet/signaling NaN payloads, largest finite, subnormals, +/-zero, arithmetic overflow, 0–3 tails and inactive buffers; preserve failure/publication atomicity. Confirm final optimized code removes scalarization and check raw/gzip size. Before selecting it, establish the actual codec program/input-run mix and how many four-record groups reach an active F32 store; static instruction presence is not a frequency gate. It can be preserved and combined with Wave 1 after that work proof and independent correctness, without a helper-only timing trial. U16/width-3 scatter specialization and larger SIMD unrolls are lower-priority, evidence-dependent possibilities, not recommended implementation work now.

## Allocation, GC and house style

Do not equate Rust allocator traffic with JS GC. Wave 1 should reduce copied records and duplicate derivation; it generally retains one Vec plus Arc shell per changed leaf and branch reconstruction. Its packed dense node-allocation count need not fall, and fragmented repack can increase it. The existing shape arena move changes ownership without allocating a replacement glyph copy, but current-versus-prior whole-package timings do not isolate its latency or allocator effect.

The source already avoids transient publication/Uint8Array/WeakMap ownership on no-view preparation (`handle-state.ts:1407`) and uses shared empty request lists (`render-planner.ts:1250–1295`, `compileStyles:2218`). Remaining changed-setter objects include the caller-owned normalized snapshot (`2154`), metrics, provisional preparation state (`796`), mutation and request. Those have distinct validation, rollback and resource-lease roles. Returning to in-place mutation, global pooling or a style cache to save allocations would need a demonstrated lifetime-safe replacement. Repeated own-key/object validation at different callable surfaces is not by itself proof of redundant validation: identify who can author each actual object before deleting it.

A later small JS publication construction cleanup could remove intermediate filter/map/spread arrays in `#compileFrame` (`render-planner.ts:1324–1346`) by visiting the already-snapshotted pending list once and building the two required ordered mutation arrays. It would preserve snapshots, output order and lifecycle/order semantics. This is a source-level allocation opportunity, not a selected dense cure: at most publication-scoped transient arrays are removed, not the per-setter ownership graph. Retain only if an exact allocation/work receipt and size/cold-output proof justify including it in a coherent later wave. Do not claim the JS profile self time as time spent allocating those arrays.

## Admission and restoration decision

First establish independent output and work removal, then one consolidated completed-wave measurement boundary. The implementation brief should carry these falsifiers:

1. **Semantic and physical oracle:** independent cold recomputation of complete physical/command bytes, ordered stable IDs, f32/u32 inputs and outputs, placement generations and prepared measurements/inspection. Use actual Inter and Bitmap fixtures without conflating their record counts. Keep malformed UTF-16, contextual shaping, font fallback and count-changing edits on existing proofs.
2. **Rope/admission adversaries:** all-Keep, empty, one replacement at each leaf edge, multiple dirty islands/gaps, Stop before/inside/after a changed leaf, last-row Keep, packed and highly fragmented roots, non-exact tree shape despite full leaves, mapping miss after substantial progress, fallible Vec/callback error, abort, rejection, retry and subsequent accepted commit. A flat reference/cold compiler, not the modified updater, owns expected output. Fixed-size Arc allocation still uses existing Rust allocation semantics; do not promise recoverable OOM for every allocator operation.
3. **Ownership:** old accepted roots and in-flight physical bytes remain valid through candidate failure; local dirty/binding changes do not leak into fallback. Source/root disposal and independent split remain independent. Renderer rejection preserves preparation. Empty membership keeps the publisher lifetime. Existing errors propagate without hidden retries.
4. **Work and memory counters:** state derivations, admission/comparison visits, old rows copied, changed leaves, shape-check visits, repacks, node/leaf allocations and live/completed-call peaks. Packed all-dirty should remove the second derivation without restoring old-row copies; sparse should not acquire O(G) work. Record codec run lengths and scalar-tail records if asserting vector utilization. Record allocation rate/GC events only through a separately authorized honest measurement; current after-GC snapshots cannot substitute.
5. **Downstream:** exact accepted host buffer content, draw/instance/order parity, real WebGPU/WebGL2 readback and patch/upload bytes, including zero settled-idle traffic. The existing four-archive six-phase/two-backend parity and zero 30-frame idle uploads are a current baseline, not proof for a new implementation. Three's single min/max span and TypeGPU range cap remain potential sparse widening; no dense gap is explained by that fact alone.
6. **Consolidated performance/delivery:** freeze exact source/package/named input, run full fixed families against same-machine main, release and current HELD, reuse one candidate sample set, report absolute p50/p95/N/modes/exclusions and drift. Keep prior's 13 slower identities visible. Include memory scope and raw/gzip shaper/JS/declarations. Current shaper is 1,601,557 / 596,277 Node-gzip bytes versus main 1,462,005 / 541,363, so a new branch/monomorphization must justify delivery cost. Use one compression method per delta.

If Wave 1 plus any independently proven compatible kernel reduces work but elapsed differences remain inconclusive, preserve it under a descriptive source ref/archive with hashes, correctness, raw results, memory and size costs. Do not discard it because it misses an old 1 ms/5% floor, and do not call noise a gain. Preserve correctly scoped compiler alternatives too; combine only after a fresh exact-input authentication, never by assuming missing old artifacts survived. A correctness failure, measured regression, or fragmented-root memory failure is a different result and must stay distinct.

If the dense gap persists, the next decision needs an actual repeated preparation operation or owned-JS allocation path that can be removed while preserving synchronous preparation, not simply the largest profile phase. This review does not establish such a large deletion. The stack remains held/unmerged; completion requires the seven-family results, not a promising local kernel.
