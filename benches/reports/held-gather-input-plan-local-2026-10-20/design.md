# Gather/input-preparation kernel wave: bounded source decision

20 October 2026. Read-only design review of the held E2 source at `/Volumes/Depot/Developer/glyph/.cache/held-rerun-20261019/repo` (live HEAD `8061d791…`; the E2 shipping archive is `28fd0413…`, source checkpoint `a829…`). **Decision: a bounded program/mask input-plan wave is justified for implementation and one consolidated wave gate, provided the implementor preserves the failure fallback below.** It can retire repeated per-record Codec program lookup, dependency-mask derivation and eligibility scans for adjacent records sharing a program and change mask, and can delete the measured 12,288 semantic f32 reads made by failed position-only attempts in each retained edit publication. It does not retire the general gather, field writes or one-wide-run compiler. Its expected speed is unquantified; preserve a correct inconclusive result for a compatible later wave. This is an optimization candidate, not a parity claim or a request for helper-by-helper timing.

## Evidence that bounds the decision

The corrected exact native replay, `bitmap-native-work-ledger-02/native-work-ledger.json`, passes 6,157 events and exact result bytes. Each retained edit publication has 10,240 accepted positioned source rows, 10,240 gathered source rows, 9,216 selected records, and 1,024 recordless rows. Its single 9,216-record Codec run remains wide: 589,824 physical bytes compared, 221,184 suppressed as equal, and 368,640 emitted. The corrected observer counts 109,568 f32 dependency reads versus the old observer's 97,280; the added 12,288 are position-only attempts that later return false. It counts 97,280 f32 writes either way. The scalar ledger does not measure latency, allocation, shipping Wasm SIMD frequency, cache misses, or JS/renderer work.

The separately authenticated E2 current-1024 named profile (`held-wave2-20261020/evidence/current1024-profile-authentication.json`, `current1024-profile-data/exclusive.md`) uses 10 warmups and 80 timed callbacks with no timed reads. Exclusive sampled CPU is 835,835 µs under preparation, 358,876 µs under publication, and 99,122 µs unattributed. Within publication, `update_retained_position_only` has 10,499 µs self, `update_fields` 28,291 µs self, and the retained-rope update node 32,916 µs self. These are sampled self costs across all 80 callbacks, not wall-clock phase reductions or a complete gather total. This profile shares the E2 artifact with the ledger, but was not paired with the later three-arm profiled phase run. The latter (`paired-phase-architecture-decision.md`) puts HELD's setter p50/p95 at 9.391/10.617 ms and publication at 3.732/4.693 ms, versus published 0.1.0's 1.043/1.666 and 10.235/12.241 ms. Sequential profiled captures and main's long tail prohibit a precise causal gap coefficient. The unprofiled seven-family E2 acceptance remains the target: dense 1,024 p50/p95 19.762/22.341 ms versus main 16.844/18.395 and release 17.100/18.684.

## Actual source owners and attempted deletion

`state.rs::append_planner_gather` supplies each paragraph's active `positioned` glyphs, semantic SoA slices, translations and masks to `CodecGatherWorkspace`; the exact cached gather key and clean-owner checks precede a retained walk (`state.rs:2537-2665`). `CodecGatherWorkspace` owns the selected `PlanGlyph` vector, source rope, placement/mask lanes and aligned f32/u32 field lanes (`codec_gather.rs:394-427`). `append_retained_stream` borrows an immutable source snapshot through a rope clone, then advances source and record cursors; the clone shares the tree and is not a glyph-row copy (`codec_gather.rs:565-704`). `update_retained_source` checks source identity and mask, tries the position-only helper, then resolves binding, selection, Codec program and topology before `update_fields` (`codec_gather.rs:707-905`). The helper accepts only the five position/placement bits, retained identity, a selected prior record with unchanged structural properties, and input masks whose selected u32 operands are solely semantic placement slot and selected f32 operands are semantic (`codec_gather.rs:907-1034`).

The exact avoidable term arises because that helper loops over required f32 inputs in program order, reads each semantic value, and returns false at a later non-semantic source (`codec_gather.rs:966-981`). The TypeScript program builder deliberately orders semantic f32 geometry and paint first and appends binding f32 inputs afterward (`packages/glyph/src/internal/codec-program.ts:432-461`), so a required binding input can reject after earlier semantic reads. `ValidatedCodec::input_masks_for_changes` computes per-buffer and then per-input dependency masks from validated program metadata (`codec.rs:419-452`); the decision is knowable before reading any glyph field. A bounded deletion could, for one program and one change mask, derive bitsets of required non-semantic f32 inputs and required u32 inputs other than placement slot, reject the position-only attempt with two bit tests, and only then read semantic values. The old per-field scope-failure checks and their discarded reads would go. This needs no public ABI, persistent sidecar, extra field columns or second executor. A program change or mask change must refresh the local classification; mixed fonts, capability sets, variants and masks cannot borrow a prior classification.

The coherent form is **one cursor-local last-key input plan**, computed on a program/mask transition and shared by the position-only attempt and its general fallback. It avoids a new persistent `ValidatedCodec` cache. A per-record standalone preflight scan would add a full scan to successful rows, so it is excluded. In this trace there are 12,288 discardable reads but 97,280 required f32 writes, 20,480 u32 writes, 9,216 selected plan rows and the unchanged wide Codec run. The helper's 10,499 µs sampled self total is a scope fact, not an upper bound on this whole wave: the plan also affects program lookup and `input_masks_for_changes` (2,875 µs sampled self) and may affect surrounding dispatch. A reduction in complete-callback time must be measured at the coherent boundary; no arbitrary percentage floor or parity-sized coefficient is imposed.

The other candidate, hoisting `gather_fields` into field-major spans, also lacks the required proof here. Full `append_from` caches its last font binding and program, selects each glyph, keeps recordless source rows, pushes declared values and required zero padding to aligned four-lane columns, then emits plan metadata (`codec_gather.rs:1380-1486,1616-1677`). The corrected ledger's 46,080 f32 and 46,080 u32 default fills belong to the initial **fresh** publication, not the retained edit publication at the dense target. The retained edit path uses `update_fields` (`codec_gather.rs:1680-1745`), which only writes inputs selected by per-record dependency masks; it has zero default fills. Field-major publication would need to stage per-row selection/binding/program/mask and preserve source-to-record correspondence across recordless rows and rope failures. It would add a temporary descriptor pass and locality claims would remain unmeasured. E3's already preserved complete-frontier reset variant was correct but slower against its direct prior and both controls. Repeating a reset or deleting zero padding from the retained path would target work that this edit does not perform.

## Precise implementor brief for the one input-plan wave

Own `codec_gather.rs::RetainedGatherCursor`, `update_retained_source`, `update_retained_position_only`, and their existing program/mask resolution. Add a cursor-local optional `ResolvedInputPlan` keyed by capability set, prior `PlanGlyph` technique/variant, and the exact `u16` change mask; it holds the validated program reference, f32/u32 required masks, and a position-only eligibility bit. Reset it where the cursor's existing cached binding/program are reset at an owner boundary (`codec_gather.rs:631-639`). Do not add a global table, per-glyph sidecar, new column or new executor. Keep `ValidatedCodec::input_masks_for_changes` the sole dependency authority. Its result is reused for the general path only after binding selection and `same_storage_topology` prove that the prior program still matches; `selection_changed` or `ALL_SEMANTIC_CHANGES` must still force all declared inputs. The existing fast-path program lookup/mask call, selected-input scope loop and discarded semantic reads are the exact old operations targeted for retirement on a repeated eligible key. Preserve existing last-binding/program caching in full `append_from` and sparse fallback.

Pseudocode, with all state local to the existing retained walk:

```text
for each retained owner: clear last input plan along with binding/program cache
for each source row in the existing rope callback:
  keep zero-mask identity/placement branch exactly as today
  if mask is position-only and prior record/identity/topology guards hold:
    plan = last plan if key=(capability, prior technique, variant, mask) matches
           else resolve the same ValidatedCodec program and input_masks_for_changes;
                classify all required u32 inputs as placement-slot-only and
                all required f32 inputs as semantic-only; save this one plan
    if plan is eligible:
      read each required semantic f32 once; write current aligned lanes,
      placement and PlanGlyph metadata through the existing helpers; Keep
    else: fall through WITHOUT speculative semantic reads
  resolve binding and selection through current general path
  if selection/topology differs: preserve current rebuild/stop behavior
  masks = all declared if selection changed or all-semantic mask,
          else reuse the matching plan's masks or derive them once
  call the same update_fields, placement/mask/PlanGlyph/source update
```

The key must include a program identity and the exact mask; a homogeneous font alone is insufficient. `ValidatedCodec::program` and mask lookup may fail and must return the existing `ProgramMissing`, not a guessed default. Determine plan eligibility by scanning only the program's declared inputs on a key miss, with checked bit shifts bounded by `MAX_REGISTERS`; do not compile 32 or 65,536 mask variants, duplicate the Codec reverse-dependency tables, or introduce const-generic renderer pipelines. `ProgramDescriptor.inputs` are validated for count, not every semantic field index (`codec.rs:1613-1622`). If a selected semantic f32 field is outside the producer's recognized semantic domain, take the old helper/fallback route so an invalid custom Codec keeps its `SourceFieldMissing` behavior and error precedence. For production-owned positioned tables, prove at `PositionedGlyphArena`'s producer that every required normal semantic lane has its row or documented empty optional default; do not add a per-record schema walk. If the implementor cannot preserve the original error precedence without extra hot-path validation, retain the old route for that key. Use the existing tests for recordless/mixed variants, then add only an independent case that changes the late binding operand and verifies cold physical bytes plus error/rollback behavior. Keep source and record cursors, rope COW selection, aligned four-lane field storage, and compiler run unchanged.

Complexity is O(program input count + buffer count) on a key change, O(1) eligibility on a matching key, then the same O(required inputs) reads/writes on successful rows. Worst-case alternating programs/masks can equal or exceed current work by a small local classification; no extra row-sized allocation is permitted. Space is one cursor-local plan, O(1) with respect to records. The expected gain is fewer repeated program/dependency decisions and no discarded f32 loads on the measured failed attempts. Binary size may rise from the plan/classifier code and must be measured; there is no source basis for claiming a SIMD or cache-miss reduction. The aligned SoA lanes and 9,216-record SIMD-eligible Codec run remain in place. No setter or renderer work is added.

Keep this work in a tight coherent commit and measure once at its consolidated boundary with a frozen archive. If correct but performance-inconclusive, retain the whole variant for compatible later work; if it harms a required family or size/memory/lifetime gate, keep it as evidence but do not select it as the live source. E2 is `28fd0413…` / `a829…`; E3's correct but slower whole variant is preserved at `734dae75` and must not be restored as part of this wave.

## Correctness and acceptance gate

The only safe preflight order is after the existing identity/topology guards and before speculative semantic reads. The general fallback must still perform `binding.select`, topology checks, full masks for new identities or changed selection, and `update_fields`. `SourceFieldMissing`, `ProgramMissing`, allocation failure and invalid semantic shape must remain reachable at the same authorized boundary; preflight must not turn a missing program into a silent retained skip. The current fast path's successful semantic reads may fail, and those failures must remain errors. A rejected attempt may defer semantic-source errors to the general path, so an oracle must check error type and accepted-state invalidation, not only successful bytes. If exact error precedence differs, retain the original route for that key.

Cold independently constructed positioned layout, IDs, Unicode/flow and prepared query results must match after **each** setter, including same-value, UTF-16, mixed-font, recordless, narrow/full/zero masks, selection changes and independently split siblings. After publication compare exact gathered fields, plan glyphs, placement/masks, physical buffers, patches, order and resource bindings against a cold root, plus sparse borrowing and renderer rejection/retry. Failure injection must cover reserve/allocation and later source errors without accepted-state corruption. Inspect optimized shipping Wasm for retained four-row SIMD runs and final binary/JS size; record live/peak memory and allocation churn. Gate one frozen candidate against **both** same-machine main and published 0.1.0 over all seven families, absolute p50/p95 and downstream browser/hero/API/ABI/peer/lifetime checks. A narrow helper result is never dense parity by itself. Preserve any correct inconclusive whole variant for compatible future combinations.
