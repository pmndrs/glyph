# Direct operands: declared-field error equivalence

20 October 2026. Source-only correctness addendum to [the direct-operand hybrid design](direct-operand-hybrid-design.md). No product source, build, test or timing work was performed.

## Finding

**Yes: a valid dynamic Codec can declare an input that its active operation graph never loads, while today's gather still reads and can reject it.** `codec.rs:1614–1685` validates declared input counts, operation field indices and complete output stores, but does not require every declared input to feed a store. `operation_buffer_masks` (`codec.rs:703–747`) can also skip a Load operation when its output buffer is inactive. The existing test descriptor at `codec_gather.rs:5965–6030` is a concrete structural witness: it declares four f32 and four u32 inputs across semantic/glyph/strike/resource scopes, but its only output loads f32 field 0. On a fresh selected row, `gather_fields` (`codec_gather.rs:1713–1775`) reads **all eight declared sources** in f32-then-u32 field order before `PlanGlyph` append. If, for example, the declared strike f32 field is absent, it returns `SourceFieldMissing`; a direct reader that follows only the live `LoadF32(0)` would publish successfully. This is a real correctness hole, not a performance caveat.

Retained updates have a narrower but still relevant rule. `update_retained_source` (`codec_gather.rs:798–990`) forces all declared input bits when selection changes or the positioning mask is `ALL_SEMANTIC_CHANGES`. Otherwise it uses `ValidatedCodec::input_masks_for_changes` (`codec.rs:419–452`), which unions inputs feeding affected buffers. `update_fields` then reads those required bits in declared f32-then-u32 order, **even if a later ordered run never executes that row or masks a buffer**. The position-only path (`codec_gather.rs:999–1130`) has its own legacy out-of-domain semantic handling to preserve its earlier read/error order; the current E4 input-plan review explicitly retains that fallback. A direct implementation must not replace these gather-required masks with Codec execution masks.

## Safe first-wave admission, without materializing fields

Use a **conservative source-totality certificate** for direct mode. Before authorizing a metadata-only gather, prove that _every declared input of every program reached by selected rows_ is readable for the current positioned owner and selected binding. Checking every declared descriptor, rather than only active Load operations, covers fresh, `ALL_SEMANTIC_CHANGES`, selection-change, narrow retained masks, clean-copy rows and future active-buffer choices. The certificate is an eligibility check only: a failed or uncertain check routes the entire preparation through the existing packed gather, which remains the authority for `SourceFieldMissing` and its exact read/error order. The certificate must never itself reject the public request.

The proof can use **existing source shapes and constructor invariants**, without reading or storing f32/u32 values. For each semantic descriptor, check exactly the arrays that `semantic_f32`, `derived_semantic_f32` and `source_u32` will access: active glyph length, referenced positioned f32/u32 column length, packed foreground column for derived channels, and the existing empty-optional rules for effects/colors. An unknown/out-of-domain semantic index, including E4's `legacy_semantic_field`, is _not certified_; run packed gather. For glyph/strike/resource descriptors, require the corresponding `FieldTable::field_count() > field`; `FieldTable::new` (`font_binding.rs:25–60`) provides a complete slice of its declared `row_count`, and `FontRenderBinding::new` (`font_binding.rs:106–160`) ties glyph, strike and resource table row counts to the domains returned by `select` (`font_binding.rs:212–246`). The direct locator must carry the very same selected tuple used in the gather proof. A missing field, unproved selection/binding, inconsistent owner shape or arithmetic uncertainty means **fallback**, not a new error. Check each owner/program/binding shape when encountered and cache only within that preparation; do not add a full source-value pass or a persistent validation shadow.

This certificate is deliberately stronger than the current gather-required mask. It may route a valid narrow-mask frame with an unused, missing declared field to packed mode, where that frame may still succeed, but cannot turn a rejected publication into success. It does not change Codec descriptor validation or ban custom programs. If the certificate's per-owner/binding cost is too high, an alternative is to invoke the existing `source_f32/source_u32` helpers in **their original field order** for every gather-required bit and discard the values before direct compilation. That exactly preserves read failures but duplicates active source reads; it is a correctness fallback to measure, not a claimed speed optimization. Do not use a new approximate table validator that returns `InvalidRequest` directly or computes a different error order.

Eligibility must be decided before dropping packed columns or committing direct metadata. A provisional walk may discover uncertainty, but it must reset and rerun packed gather; any provisional binding, source or locator allocation error should likewise fall back so the packed path determines the public result. Avoid a direct `ResultTooLarge` from sidecar allocation masking an earlier packed `SourceFieldMissing`. Once certified, source lookup can still use the same fallible helpers at Codec loads as a defensive check; an unexpected failure invalidates the prepared root and is a test failure of the certificate, not permission to synthesize zero.

## Observable boundary and tests for the implementation wave

`GatherError::SourceFieldMissing`, missing binding/program and invalid source shape map through `state.rs:8274–8290` to `EngineError::InvalidRequest`; allocation maps to `ResultTooLarge`. A missing field during publication is externally observable as a rejected update, even though the earlier HELD setter's paragraph preparation has already been accepted. `prepare_update` invalidates the root on error (`state.rs:1990–2080`), and no packed physical plan may be committed. Moving an error into a later Codec load can change the status if an allocation failure intervenes, or permit a row copied/filtered by the ordered compiler to escape the read entirely. Conservative fallback preserves the established packed behavior for those uncertain cases. It also keeps E4's position-only `legacy_unknown_semantic` branch as the owner of its unusual error precedence.

Add a validated custom program with one used semantic f32 input and one **unused missing** glyph, strike, resource and out-of-domain semantic input in separate cases. Verify fresh selected gather and warm `ALL_SEMANTIC_CHANGES` reject, while a narrow retained mask follows the old required-mask outcome; include an inactive-buffer/clean-copy case, position-only legacy field, simultaneous malformed source plus allocation pressure, and selection changes. Compare the direct candidate against an independent cold packed engine for public status, root invalidation/rollback, prepared setter state and exact accepted physical output. Count fallback/admission separately so the warm 512/1,024 target is proved to enter direct mode with its real Codec and bindings. This refinement is required before implementation review; it does not reopen the direct hybrid experiment or claim a measured latency result.
