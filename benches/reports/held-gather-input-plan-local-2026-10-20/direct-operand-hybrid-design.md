# Direct retained-SoA operands in the single Codec executor

20 October 2026. This is a source-only design amendment to [the system diagnosis](fresh-system-hybrid-diagnosis.md), made while the frozen E4 timing matrix is running. It proposes **one bounded implementation experiment**, not a measured speed result. The current input-plan archive remains the baseline; no product source, Git state, build, test, profile or benchmark capture was changed for this report.

## Decision

Implement a _direct operand mode_ for warm, same-count, all-owner-dirty publication. Retain the current selected-row `PlanGlyph`/slot/mask columns, source rope, ordered batching, physical packed layout, patches and **one validated Codec operation interpreter**. In this mode, the existing selected-source walk writes a small row locator instead of full f32/u32 gathered field columns. The existing Codec scalar and four-lane SIMD operation loops load the declared operand from the paragraph's positioned SoA or selected font table through a typed cursor. The packed field mode remains for sparse, decorations, count changes and other non-admitted frames. This changes an internal operand-load boundary; it does not revise the synchronous setter, public TS/Wasm API, public `ValidatedCodec::execute` method, physical schema or renderer acceptance contract.

The experiment removes a _real_ intermediate producer/consumer pair. It may still lose elapsed time: direct loads are scattered, metadata needs an extra write/read, the source walk may perform additional selection, and SIMD input assembly replaces contiguous `v128_load`. A whole tile is a fallback locality experiment, but it still writes the full field values and adds calls; it is weaker as the first attempt. No pre-measurement percentage gate is imposed. Preserve a correct inconclusive branch for a later compatible combination.

## Existing contracts the implementation must keep

- [Gather](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/codec_gather.rs) lines 130–184, 232–303, 450–520, 654–1130: `GatherSource` is one row per positioned source, including recordless rows; its rope summary counts selected fragments. `GatherRange` tracks source and selected-record offsets per paragraph. `append_retained_stream` proves stable source identity, selection, storage topology, updates selected `PlanGlyph`, placement slots, semantic masks and changed-output intervals, and falls back on a retained miss. `GatherSource.selection` packs strike/resource but **not** `strike_row`. `update_retained_position_only` has a narrower dependency path; its output mask is the positioning change mask, not a comparison of old/new gathered field bits. Ordinary changed-source output masks are also written from positioning masks. Full field writes are therefore separable from mask production, but source validation/errors and selection still need preserving.
- [Source resolution](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/codec_gather.rs) lines 2161–2315: `source_f32`, `source_u32` and derived semantic helpers read current positioned semantic columns or glyph/strike/resource binding tables. They include optional defaults, placement slot, sRGB conversion and field-missing errors. **Reuse these exact helpers** in the direct cursor. Do not reimplement their arithmetic or assume only the built-in program. [Selection](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/font_binding.rs) lines 87–92 and 212 onward supplies `strike`, `strike_row`, `resource`.
- [Plan input](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/plan_input.rs) lines 6–49 carries globally indexed `PlanGlyph`, slot and mask slices. The [ordered compiler](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/ordered_plan.rs) lines 1695–1810 groups physical rows by batch, can copy committed clean bytes, and calls `execute_run` only for a contiguous run of **global** input indices. Its `input_start` and physical `run_start - aligned.start` are different coordinates. Keep global IDs, batch order, active-buffer masks, old/new byte comparison, patch offsets, buffer generations and clean copies in this owner. Never move physical ordering into the direct source.
- [Packing](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/plan_packing.rs) lines 122–208 currently slices every field `[input_index..input_end]` and calls `Codec::execute_buffers`. [Codec](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/codec.rs) lines 189–253, 384–405 and 1015–1350 has current-record `LoadF32/LoadU32` operations, checked output shape/capacity, dependency-masked active operations, four-row SIMD groups and scalar tails. No cross-record operand exists. Add a typed internal input variant _under_ this boundary; both modes use the same validated descriptor, operation loops and store logic. The public packed `execute` surface and public `CodecExecutionError` need no change.

## Admission and exact mission coverage

At [state](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/state.rs) lines 1865–1930, admit direct mode only after the existing gather key matches the current root/codec, `checkpoint` is false, `prepare_retained_order(Gather)` succeeds, there are no decorations or lifecycle/order changes, every active paragraph appears exactly once in the deduplicated `order_sort_scratch` frontier, and each `gather_range.source_count()` still equals the positioned source count. The all-owner predicate is a **semantic mode guard**, not a density percentage. It admits the ordinary warm 512/1,024 all-label edit with the same count and one publication; it is not restricted to cold initialization, checkpoints or rejected frames. The E4 native replay actually records 1,024 visited owners, zero retained range skips, 9,216 selected and 1,024 recordless source visits in each warm edited publication, consistent with this guard. The exact new guard must be instrumented on that frozen trace before claiming it was exercised. `sparse_output_intervals` at `ordered_plan.rs:132` already treats `[0..P]` as full output while preserving retained topology and patch duties; direct mode is an input supply choice, not permission to skip physical comparison or patch generation.

The guard can be evaluated from current owner/frontier data before field production. If selection or topology changes during the metadata walk, abandon the direct attempt and run the existing packed rebuild under the current error/rebuild rules. Do not publish a partially direct plan. Sparse frontiers use packed mode from the outset. Dynamic custom Codec programs remain eligible only when the same source helper and fallible descriptor path can resolve their fields; unsupported fields must fail with the same `InvalidRequest` status rather than silently use zero.

## Owned representation and implementation seams

Add one `Vec<DirectRowLocator>` beside the existing selected `glyphs`, slots and masks in `CodecGatherWorkspace`. A concrete first layout is five `u32` words: `paragraph_index` (index of existing sorted `planner.paragraphs` for this preparation), local `glyph_index`, `binding_index` into the current registered font-binding slice, packed `selection` (strike/resource) and `strike_row`. It is **20 bytes per selected row**, 184,320 payload bytes at P=9,216; actual `Vec` capacity, padding and allocator overhead must be reported separately. It holds neither a second glyph/semantic representation nor font-table values. Recordless sources get no locator. It is filled in the same retained source/selection walk that updates `PlanGlyph`, and is indexed by the existing global selected record ID. The current branch that skips binding selection for zero/position-only masks must fill the locator too; that may add up to one `binding.select` per affected selected row. Count these calls. A retained row locator is overwritten/validated when reused; `binding_index` is never trusted across a different preparation. No source-rope point query or owner binary search occurs per Codec load.

The locator avoids an O(log G) rope rank lookup and owner lookup on every operand or run. A no-sidecar variant could use `RetainedRope::index_for_fragment` (`retained_rope.rs:409`) once per run and stream `cursor_from`, but would still have to recover `strike_row`, which `GatherSource` omits, and could repeatedly resolve rows across physical batch runs. The 20-byte sidecar is the more direct bounded experiment. At the same P, the present E4 producer writes 117,760 32-bit field values, 471,040 bytes; the sidecar is materially smaller. Keep the sidecar's capacity for adjacent direct frames only while measured memory/transition gates permit; its length and binding indices are preparation-scoped. If direct mode is dropped, free its capacity.

Split `CodecGatherWorkspace::begin_retained` into a metadata validity/reservation path and the existing packed-field path; direct mode must neither reserve nor write f32/u32 `AlignedField` blocks. Split `update_retained_source` and `update_retained_position_only` at their field materialization step so the _same_ identity/selection/topology/mask logic can update metadata in both modes. Do not duplicate the entire retained interpreter. The direct path must fill a locator for **every** selected global record, including a selected row with a zero semantic mask, because ordered clean-copy and active-run decisions are made later. `append_from`, decoration append, suffix splice and ordinary sparse retain keep their packed behavior. No field array is exposed as valid in direct mode.

The internal handoff can keep the public `PlanInput` struct intact. Pass `Option<&DirectOperandSource>` alongside `PlanInput` through crate-private `RenderPlanCompiler::prepare_owned`, `OrderedPlanCompiler::prepare_scoped`/context and `plan_packing::execute_run`; the public prepare callers pass `None`. In direct mode, `PlanInput` still supplies real glyph/slot/mask slices and empty field slices, and only `execute_run` switches its operand source. `DirectOperandSource` borrows the current locator, positioned arenas, sorted paragraph owners and font bindings during `prepare_owned`; it does not outlive the call or enter the borrowed plan lease. Rust's split borrows should be explicit: finish mutable gather/paragraph metadata updates, then borrow the gather and paragraphs immutably while mutating only `planner.plan`. If the current `&mut PlannerState` helper blocks this, narrow it rather than clone the positioned columns.

Inside the private Codec input boundary, use a closed `Packed(SemanticInputBatch)` / `Direct(DirectRunCursor)` input variant. The direct cursor is prepared for one global row or four consecutive global rows and holds up to four `RowContext`s on the stack; each contains the resolved `LayoutPlanInput` view, glyph index, binding reference and exact selected tuple from the locator. Resolve the contexts **once per SIMD group**, not once per operation. `LoadF32/LoadU32` uses the same program input descriptor and `source_f32/source_u32` helper as packed gather. Scalar loads transfer exact `f32::to_bits()`/u32 bits into the existing register. SIMD loads assemble the four scalar bits into one v128 (lane insertion or a 16-byte local); arithmetic, dependency skips, stores and zero-to-three scalar tails remain the existing operation bodies. A four-lane assembly costs four potentially scattered source reads and register/stack work versus one aligned `v128_load`; do not present SIMD opcode presence as runtime utilization or speed. A run starts at the _global_ `input_index`, while physical output starts at `output_record`; no local tile base changes identity or patch coordinates.

Validation first checks the same capability/program/output schema/capacity and declared field counts as `validate_execution`, plus `input_start + record_count <= locators.len()` and current owner/binding indices. Direct field reads remain fallible; use a private source-error wrapper through packing/ordered compiler so `GatherError::AllocationFailed` maps to `ResultTooLarge` and missing/invalid source maps to `InvalidRequest` as [state's current mapper](../../held-rerun-20261019/repo/packages/glyph/rust/shaper/src/engine/state.rs) lines 8237–8290 does. Never widen the public Codec error enum merely to transport this internal failure. A late source error may occur after staged physical bytes were touched; `prepare_update` already invalidates the root on preparation error (state lines 1990–2080). Test ambiguous malformed inputs for status and rollback. If exact multi-error precedence is a contract, preflight the relevant descriptors before any physical write; a full duplicate field read is not the default.

## Work and memory accounting: what is deleted and what moves

For the **E4 warm edited publication only**, the native scalar ledger records 97,280 f32 and 20,480 u32 source reads, with exactly matching writes to gathered fields: 117,760 32-bit values = **471,040 source-read bytes and 471,040 full-field-write bytes** at that producer. Direct mode deletes those full-field writes and the Codec reads of the corresponding full-field arrays. It **does not delete** the source value reads; it moves active ones to Codec load time. It adds a 20P-byte locator write during selection and, with row-context reuse, approximately 20Q locator-read bytes where Q is the number of executed rows across runs (Q can exceed P if a row is revisited). At P=9,216 and one full run, those logical payloads are 184,320 bytes each. On this ledger the gross gathered-field write reduction after locator write is 286,720 bytes; it is **not** a net traffic or latency forecast. Metadata selection, glyph/slot/mask writes, physical output comparison (589,824 bytes in the E4 trace), suppressed equal bytes (221,184), emitted patches (368,640), renderer upload and setter preparation remain.

Let L be active Codec load operations across executed records, counting repeated loads of a field. Packed mode performs roughly `4L` bytes of field loads after producer reads/writes; direct mode performs roughly `4L` bytes of source/table loads instead, plus row context and lane assembly. The ledger does not expose L or cache misses, so neither is assigned a made-up value. The direct reader may repeat a derived semantic computation or binding table access that the producer previously did once; dependency masks may also avoid loading fields whose gathered slot was written for a changed input but whose output buffer is inactive. Instrument selected calls, source/table reads, duplicate loads, row-context resolutions, SIMD groups/tails, run count, and bytes/capacity of locator and retired fields. This is a coherent producer/consumer deletion with a measurable cost exchange, not a promise to make a two-phase retained pipeline as cheap as old deferred batching.

Old packed field capacities must remain untouched until the direct preparation has passed Rust commit; otherwise failure could expose a false retained cache. Replace the current `gather_cache`/`prepared_gather_cache` key-only state with one typed cache state, `{key, columns: Packed | MetadataOnly}`. Existing `commit_update` lines 2290–2294 auto-promote a prior key when no prepared cache exists; that must propagate the **mode** only on legitimate reuse, never authorize stale columns. Direct commit marks metadata-only and then retires full f32/u32 `AlignedField` capacities. Packed sparse admission requires `Packed`, while adjacent warm all-owner-dirty direct admission accepts either mode. The direct locator is preparation-scoped; its capacity may remain in the workspace for the next dense frame, but no stale binding indices may be read. Transition `direct -> sparse` cold-rebuilds fields and may transiently coexist with locator capacity; `sparse -> direct` keeps the packed arrays until successful direct commit. Report live and peak requested bytes separately from physical buffer and JS/GPU memory. The cold rebuild is a real shifted cost to compare, not a free fallback.

## Required bounded implementation and validation

The first implementation should touch `codec_gather.rs` (metadata-only retained mode, locator, shared source helpers), `state.rs` (exact guard, typed gather-cache mode, borrow/lifetime and commit retirement), `plan_packing.rs`, `ordered_plan.rs`, `render_plan_compiler.rs` (private provider plumbing) and `codec.rs` (one input variant at operand loads and direct validation). Keep the existing packed path as the reference; do not add a parallel executor or a public surface. A review should reject duplicated operation loops, full field arrays plus sidecar as a steady-state mode, a per-field binding search, O(P) shadow positioned columns, or a guard that only fires on cold/checkpoint frames.

Before timing, use an **independent cold engine** as the physical oracle after each guaranteed prepared boundary: compare text/Unicode/bidi/flow/layout, stable IDs, measurements and independent split views, then exact packed buffers, patches, draw order, bindings and host-visible result after publication. Exercise built-in and custom programs with semantic/glyph/strike/resource fields, recordless rows, different strike rows, mixed program runs, one-to-three scalar tails, active-buffer dependency masks, nonfinite and missing fields, selection flips, count changes, late retained miss, decoration fallback, allocation failure, abort and renderer rejection/checkpoint retry. Compare warm direct→direct, direct→one sparse edit, sparse→direct, and alternating 1/100/1,000-label edits; verify old full columns are retired after direct commit, rebuilt before sparse use and never falsely cache-valid. Include a warm same-count 512/1,024 all-owner-dirty witness proving the guard, one validated Codec executor and exact physical bytes.

Only then freeze a named archive and run the established same-machine seven-family p50/p95 main, published and direct-prior matrix with its exclusions/calibration, optimized raw/gzip Wasm, scoped allocations and browser pixels/uploads. Attribute a win or loss separately to setter and publication. Dense parity against both controls while preserving sparse/read gains is the acceptance target; a correct inconclusive variant remains available for combinations. This experiment cannot remove HELD's 1,024 synchronous setter preparations; if its measured publication savings do not close the whole gap, a separately authorized scoped batch contract is the explicit route to old no-read amortization.
