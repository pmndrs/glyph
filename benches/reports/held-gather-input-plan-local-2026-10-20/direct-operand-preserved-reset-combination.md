# Combining the saved complete-frontier reset with direct operands

20 October 2026. Source-only ruling on preserved commit `734dae75e9d39cd90f0e60c2244aa488b5b64bf2` (`experiments/held-shared-layout-hybrid-measured-20261020`) against the [direct-operand design](direct-operand-hybrid-design.md) and its [error-equivalence addendum](direct-operand-error-equivalence-addendum.md). No product, Git, build, test, profile or benchmark work was performed.

## Ruling

**Use the saved reset's *full-owner metadata writer* as the first direct-operand experiment, but do not copy its threshold, shaping change or old packed-field behavior.** This is one coherent wave: on a warm, same-count, undecorated, all-owner-dirty frame with an exact cached key and source-totality admission, rebuild the existing selected metadata/source rope once, write the bounded direct locator, and run the **same validated Codec and ordered physical compiler** with direct operands. The E3 reset is a compatible producer simplification here because direct mode already has to establish a locator for every selected row and will cold-rebuild packed columns on a sparse successor. It is *not* evidence that reset alone wins time. The old E3 measured regression still warns that rope/allocation and full metadata work can dominate after field writes are removed.

This choice narrows the first implementation relative to retrofitting `update_retained_source` and `update_retained_position_only` with a second metadata-only branch. Their retained identity matching, position-only input plans, rope COW range updates and suffix-rebuild machinery stay intact for the packed sparse path. A later measured direct-retained variant can be built if reset costs remain material; preserve both complete variants rather than quietly replace the earlier evidence.

## Exact saved source and what transfers

The preserved diff changes `state.rs:1869–1944` and adds `PlannerState::prepare_dense_complete_gather_count` around line 2817; it does **not** change `codec_gather.rs`, `codec.rs` or `ordered_plan.rs`. After an exact cached key, non-checkpoint retained-order admission and a complete owner frontier, it scans positioned masks, counts old source rows with `ALL_SEMANTIC_CHANGES`, and chooses reset at **at least half** the old source count (count-changing owners count their old rows). It then skips `gather.begin_retained`, calls `gather.begin` and `append_planner_gather(... retained=false)`, and omits the sparse changed-output scope. The same preserved commit also changes a short-run shaping window; that setter-side branch is unrelated and must not be imported into this direct publication experiment. E3's native/cold physical checks passed in their scope, yet its full field-materializing package measured dense512 p50 10.720 ms and dense1024 p50 19.519 ms against direct prior 9.816/18.497, and untimed allocator diagnostics showed +4,469 allocations and +960 reallocations per warm cycle. Those are whole-variant observations, not a causal measure of this reset branch ([saved packet](../../held-rerun-20261019/repo/benches/reports/held-shared-layout-hybrid-local-2026-10-20/README.md), obtainable at the preserved commit).

The new direct guard should use **all active owners exactly once, stable source counts, complete positioned mask columns, no lifecycle/order/decorations, exact gather key, and no checkpoint**, plus the [declared-field totality certificate](direct-operand-error-equivalence-addendum.md). Complete masks matter because fresh `append_from` defaults a missing per-source mask to `ALL_SEMANTIC_CHANGES`, whereas the retained update defaults it to zero; package-owned positioning normally supplies one mask per glyph, but direct admission should assert that shape rather than silently change behavior. Do **not** import E3's half-full-mask threshold: deleting full field arrays is valuable even when a wide position/color change yields narrow masks, and the current direct design is intentionally a full-owner mode. The E4 native edited publication already reports 1,024 visited owners, zero retained range skips, 9,216 selected and 1,024 recordless source visits; instrument the actual new guard before claiming it fired. Count-change admissions from E3 remain a separate candidate; this first direct wave stays same-count to keep global locator and transition proof bounded.

## What the reset deletes, and what it adds

On its admitted frame, the reset avoids `RetainedRope::update_ordered_ranges` COW/range machinery, prior-source identity and selection matching, retained position-only classification, `ResolvedInputPlan`/dependency-mask lookups for field writes, and late retained suffix splicing. The direct path does not need those field dependency masks for materialization; the ordered compiler still uses the original per-record semantic change masks to determine active output buffers. The reset's fresh `append_from` path must **still** select every source glyph, preserve recordless source entries, resolve program/resource topology, build every selected `PlanGlyph`, slot and mask, and append source-rope leaves. It may replace in-place metadata edits with full new vector/rope writes and allocations. A direct locator adds 20 bytes per selected row under the proposed first layout. Unlike E3, the new metadata-only `begin`/fresh append does not reserve, zero-fill or write f32/u32 `AlignedField` columns; those were 471,040 field-write bytes on the E4 warm edited replay and potentially more in E3's full reset. Source operands are read by Codec later, with the repeated/scattered-load and SIMD assembly costs already stated in the direct design. No net traffic or speed claim follows without a frozen whole run.

Use a single mode parameter in the **existing fresh selected-row writer**, not a second interpreter: `begin_direct_metadata` clears/reuses metadata capacity without reserving field blocks; `append_from` shares binding selection, program, `plan_glyph`, recordless `GatherSource`, masks, paragraph `GatherRange` and fallible reserves, but emits `DirectRowLocator` in place of `gather_fields`. `append_planner_gather` still iterates current renderer order and records each owner range. The source rope is retained in the first implementation, even though a reset on each direct frame might later make it dispensable; deleting that structure simultaneously would change more ownership and failure behavior than this combination needs. Packed sparse/cold publication continues through the untouched retained/fresh field writer. One typed `{key, Packed | MetadataOnly}` cache state prevents `commit_update` from treating stale columns as reusable. The direct locator and font-binding indices are only valid for one preparation; keep or drop capacity according to measured memory, not as an unseen persistent data model.

## Masks, physical output and failure boundaries

The fresh writer's `append_from` stores `input.semantic_change_masks[glyph_index]` (or its existing all-changes default) for selected rows, while retained `update_retained_source` writes that same current positioning mask. The reset must keep this exact mask and source/record coordinate accounting; do **not** replace it with “all changed” merely because every owner is dirty. Fresh `plan_glyph` recomputes current selection/resource/placement; recordless rows advance source but not selected record. If a selection/topology mismatch would have forced retained suffix rebuild, the complete reset already resolves the current source from scratch. E3's cold-root checks support this metadata equivalence for its admitted cases, but the new direct variant still needs an independent cold comparison for mixed bindings, recordless selection and every selected global ID.

The saved branch passes `output_scope=None` to `RenderPlanCompiler::prepare_owned`; `OrderedPlanCompiler::prepare_internal` (`ordered_plan.rs:498–565`) then retains or rebuilds topology under its existing rules. This **can widen ordered work**. With a retained exact `[0..P]` interval, `sparse_output_intervals` also turns the scope into `None`, so full-output-dirty admission follows the same full selected-row comparison body. But an all-owner frontier can still have selected rows with zero masks or only bounds changes; ordinary retained gather can then pass sparse selected intervals. Reset passes `None`, causing `prepare_retained_topology` (`ordered_plan.rs:1169–1280`) to scan all prior physical instances, and it disables `compile_bindings`' sparse clean-span reuse (`ordered_plan.rs:2021`). The subsequent changed ranges and `active_buffers_for_range` (`ordered_plan.rs:1589–1650, 2670–2730`) are derived from the actual instance state and unchanged per-record masks, so reset does **not** automatically force every buffer active. It may nonetheless produce more admission comparisons, repacking, draw-span work or broader patch coalescing. The E4 ledger proves all 1,024 owners were visited and one 9,216-record Codec run occurred, but does not explicitly prove one exact `[0..P]` selected-output interval; instrument that scope on the candidate. This is a cost/risk to measure, not a correctness license to replace masks with `ALL`.

The ordered compiler still owns batch order, active-buffer masks, old/new physical-byte comparison, patch records, in-flight buffer generations and clean-copy decisions. Direct `execute_run` receives a **global** selected input index and distinct physical output offset; no reset-specific Codec or patch executor is permitted. The exact final physical bytes, valid patch application and renderer-visible ordering must match a cold oracle; the emitted patch list can legitimately differ in coalescing from the retained route, so do not assume byte-identical patch records without an explicit contract and test.

The source-totality check must precede selecting metadata-only mode. Any uncertain custom descriptor, unknown semantic field, binding/selection uncertainty or provisional locator allocation failure routes through the **current packed path** so it, not the new certificate, decides public errors and old read order. If a previous direct commit retired packed columns, the successor uses a cold packed rebuild, as already required by the direct design. A prior direct certificate proves all declared inputs total for its selected bindings/owners under that root/codec key; a new binding/codec or new owner must be rechecked. Test this transition's status against the independently cold packed engine, especially narrow masks and missing fields. The saved reset discards old gathered **values** when it calls `begin`; a direct metadata reset may do the same, provided any fallback cold-rebuilds packed values rather than treating the old key as `Packed`. It need not copy or preserve old field values for rollback: on preparation error `state.rs` invalidates the root, while prior committed physical bytes and borrowed leases remain under the ordered plan owner. Retain old field **capacity** until direct Rust commit if needed for a same-call packed fallback, then retire it; never mark cleared/stale fields cache-valid. This supersedes the earlier direct report's retained-writer assumption that old gathered values remain untouched through commit.

## First-wave brief and acceptance

Implement the direct full-owner reset in `state.rs` plus a metadata-only branch of the **existing fresh** `codec_gather.rs` writer, the 20-byte locator, private provider plumbing through `render_plan_compiler.rs`/`ordered_plan.rs`/`plan_packing.rs`, and the one Codec operand-load variant. Keep the current E4 input-plan optimization in packed retained mode. Do not import E3's short shaping, 50% tally, count-changing mode, full field reset, or an extra executor. This is a coherent replacement for the first-wave retained metadata implementation suggested in the earlier direct report, **not** an additional benchmark series or a promised winner.

Before timing, compare warm direct→direct, direct→one sparse edit, sparse→direct, and alternating sparse/dense at 1/100/1,000 labels against a cold engine after each prepared boundary. Verify exact masks, selected/recordless correspondence, `PlanGlyph`/slot identity, Codec scalar tails and four-row groups, active-buffer dependencies, all declared-field error outcomes, physical bytes/patch application/order, abort and rejection/retry, old-field retirement and cold rebuild allocations. Then freeze one artifact for the already specified seven-family main/published/direct-prior gate. If dense publication improves but whole dense remains behind because 1,024 synchronous setters dominate, the result still informs the separate public batch-contract decision; no hidden setter deferral is allowed.
