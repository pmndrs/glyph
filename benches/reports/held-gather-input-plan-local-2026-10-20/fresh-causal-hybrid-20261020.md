## Where each architecture buys time

Old main's `render-planner.ts::_updateText` validates and records desired state, then `#compileFrame` gathers dirty content states and sends semantic mutations in one publication request. A query may prepare sooner, but a no-read 1,024-setter sequence amortizes the Rust frame boundary and root setup across the batch. The published package has its own authenticated archive; its exact source is not inferred from Git main. HELD's current `#prepareTextCandidate` calls synchronous `PlanTransport.prepareParagraph` for each accepted setter. Its frame carries lifecycle/order while semantic mutation arrays are empty. This gives each setter a prepared, queryable semantic revision and a stable source for independent split, but pays 1,024 preparation boundaries in that no-read workload. A previous same-fixture, profiled diagnostic found main/release/HELD E2 median setter loops of 1.281/1.043/9.391 ms and publication of 11.259/10.235/3.732 ms; medians do not add, this is not an E4 timing comparison, and profiler overhead/clock prevent helper-level attribution. It does show the scheduling inversion predicted by source.

HELD's 32-record ropes, retained identity/source correspondence, queued owners, Unicode preflight, local shaping and flow continuation, packed same-length discovery, lazy inspection and sparse output scopes cut work when dirt stays local. Current E4 whole rows illustrate where: edit and sparsely borrow one of 1,000 labels p50/p95 is 0.180/0.270 ms versus main 0.227/0.318 and release 0.216/0.303; width inspection plus publication is 4.673/5.673 versus 8.804/9.450 and 9.822/10.250. These are whole-path observations, not proof that a particular rope method caused every win. A count-changing front edit, Unicode context, root reorder or host upload can still propagate broadly; rope sharing does not make the final packed result sublinear.

Dense work exposes both costs. In the completed E4 arms, 512-label rewrite p50/p95 is 9.228/10.652 ms versus main 6.999/7.741 and release 7.411/7.957; 1,024 retained Text publication is 18.589/21.017 versus 15.245/16.415 and 15.397/16.491. Main-arm software calibration drift is 8.3%, so small differences need caution, but these are material gaps. The current source still visits selected source rows and compiles contiguous physical bytes after per-setter preparation. The actual Bitmap native scalar replay of 6,157 events exactly matches 4,099 encoded results and exposes the scale: each warm forward/reverse publication visits 10,240 source rows, including 1,024 recordless; reads and writes 97,280 f32 plus 20,480 u32 gathered slots; executes 9,216 Codec records; derives/compares 9,216 ordered instances and 589,824 physical bytes; suppresses 221,184 equal bytes and emits 368,640 changed plan bytes. Thus the input-plan edit's 12,288 fewer f32 source reads per direction are a genuine deletion, while the 471,040 bytes of field writes and their later Codec loads remain. Native counts do not time SIMD, allocation, JS, GC or GPU. An `Ω(output bytes)` floor remains for the changed physical data, but there is no proof that HELD parity is impossible.

The old architecture is fast for deferred, batched no-read setters; HELD is fast for prepared reads, sparse edits, root locality and independent copy. Neither can be used as a blanket answer. A public batch scope that defers semantic preparation could recover old no-read amortization, but changes synchronous setter error/query guarantees and is outside this brief. Any internal optimization must preserve those guarantees.

## Producer/consumer test for the next hybrid

The existing producer `CodecGatherWorkspace::{append_retained_stream,update_retained_source,gather_fields,update_fields}` resolves selected binding/program and writes full f32/u32 SoA fields. `GatheredPlanInput` passes those columns through `plan_packing::execute_run`; one validated `Codec` operation interpreter reads them into scalar or four-row SIMD registers. The ordered compiler owns global selected indices, physical batch order, active-buffer masks, old/new comparison, patches and accepted buffer generations. `GatherSource` includes recordless source rows and selected fragment counts, but omits `strike_row`; `PlanGlyph` has no source owner or binding locator. Therefore a direct Codec reader needs an explicit current-row locator. Merely tiling gathered values moves the same 471,040 warm producer writes to tile scratch and adds calls; it is a locality experiment, not a deletion.

I select **one internal direct-operand experiment on the retained complete-owner path**, with packed mode as the complete fallback. For a warm, same-count, undecorated frame with an exact root/Codec gather key, no checkpoint or lifecycle/order change, and every active owner once in the prepared frontier, the gather walk keeps source correspondence, selected `PlanGlyph`, placement slots and current semantic masks. It emits one selected-row locator rather than the full field values. A private Codec input variant reads each declared operand using the existing `source_f32/source_u32` helpers from the positioned SoA and selected binding tables. The existing scalar/four-lane operation loops, output stores and ordered compiler remain the only executor and physical authority. The locator can initially use five checked `u32` coordinates (paragraph index, local source index, binding index, strike/resource selection, strike row): 20 bytes per selected row, or 184,320 logical bytes at 9,216 rows. Its contents are valid only for that preparation call, while capacity may be retained under a measured memory budget. There is no second positioned layout or persistent renderer image.

This _deletes_ full gathered-field writes on the admitted path and the Codec's loads from those fields. It _moves_ active source/table reads to Codec load time; it adds locator writes/reads and may repeat a source read when multiple operations use one input. Four-row SIMD now assembles four potentially scattered operand lanes instead of one contiguous `v128_load`; existing four-lane arithmetic and stores still run. The Bitmap ledger shows 2,304 eligible groups and zero scalar tails in the warm run, but neither actual runtime utilization nor direct lane-assembly latency is measured. Preserve the contiguous packed path for sparse, cold, count-changing, decorations, custom uncertainty and transitions. A direct→sparse transition rebuilds full packed columns and may temporarily carry locator capacity, so its p95 and peak bytes are explicit acceptance checks.

Use the existing retained source walk, extended to establish a locator for every selected global row of admitted owners, even when a glyph's semantic mask is zero. Keep the same exact output intervals when they are narrower than full `[0..P]`; all owners dirty does not prove every output row dirty. The `GatherRange` source/selected coordinates, recordless rows and current masks stay unchanged. Before changing code, prove this walk can fill all selected locators without a second owner/selection pass or per-operand rope search. If it cannot, stop this variant and evaluate the complete metadata reset as a separately named variant, not an unmeasured substitution. This condition keeps the deletion honest.

The prior `direct-operand-hybrid-design.md` identifies the correct intermediate producer/consumer and private Codec seam. Its addendum correctly finds a semantic trap: a valid dynamic program may declare an unused or inactive input that today's gather still reads and rejects. Direct execution of only live `Load` operations could wrongly succeed. Admission therefore needs a conservative **source-totality certificate** for every declared input of each reached program and selected binding/owner, using existing column/table lengths and constructor invariants without reading field values. Unknown semantic fields, uncertain shapes, selection, binding or allocation fall back to the packed authority; the certificate never issues a new public error. Preserve f32-then-u32 gather-required read/error order in packed fallback, including position-only legacy semantics. An unexpected certified direct read failure invalidates the root as an invariant failure. Instrument actual certificate admission on the 512/1,024 Bitmap fixture; structural plausibility is insufficient.

I do **not** choose the saved E3 complete-frontier reset as the first direct producer. The combined-reset note makes a coherent implementation case: fresh metadata can fill all locators in one pass and avoid retained COW/identity work. It also passes `output_scope=None`, potentially broadening ordered admission and clean-span work when all owners are dirty but selected output is narrow. E3's full-field reset plus unrelated short-run shaping measured slower than direct prior and added 4,469 allocations/960 reallocations per warm cycle; those counts cannot isolate the reset, yet they defeat a claim that reset is a free simplification. The direct operand deletion and reset's allocation/topology effects should first be isolated. If the retained locator proof fails or its COW cost dominates after exact counters, use the preserved E3 metadata pattern **without** its half-mask threshold, short shaping change, count-change admission or packed field writes, and compare it as a complete alternative. Neither route is admitted on a 5% threshold; a correct inconclusive variant stays available for compatible combinations.

## Ranked implementation brief and stop conditions

1. **Finish E4's existing gate and preserve its source.** Wait for the already running direct-prior arm; inspect terminal manifests, exact candidate reuse, modes/exclusions, absolute p50/p95 and calibration. Do not launch a new measurement or infer a three-arm verdict from the two completed arms. E4 is a small, source-proven input-read deletion that remains compatible with the direct experiment.
2. **Implement one direct retained-operand branch under exact eligibility.** Own `codec_gather.rs` metadata/locator and typed `{key, Packed | MetadataOnly}` gather-cache mode in `state.rs`; pass a call-scoped borrowed provider through `render_plan_compiler.rs`, `ordered_plan.rs` and `plan_packing.rs` to one private input variant in `codec.rs`. Keep the public `ValidatedCodec::execute`, Wasm ABI, physical schema and renderer APIs unchanged. Do not duplicate Codec operation loops. Resolve row context once per four-lane group and one scalar tail, not per operation; keep global selected IDs separate from physical offsets. Delete only the admitted full-field materialization and corresponding packed loads. Retire stale packed capacity only after successful direct Rust commit, never mark metadata-only as packed on cache-key promotion. Failure/late miss uses the existing root invalidation and packed fallback rules; no partial direct plan is published.
3. **Prove independent outcomes before timing.** After each guaranteed setter boundary compare cold recomputation for text, Unicode/bidi, shaping/flow, stable IDs, measurement, inspection and independent split. After publication compare exact packed physical bytes, patch application, batch/order/decorations, active buffers, leases and host-visible output. Cover recordless rows, differing strike rows, mixed and custom programs with unused missing fields, inactive outputs, nonfinite values, SIMD groups and 1–3 tails, selection flips, front/middle/tail count changes, direct→direct, direct→sparse, sparse→direct, alternating 1/100/1,000, allocation error precedence, abort, rejection/checkpoint retry and lease expiry. Counter proof must show the target guard fires, full field writes/loads disappear, no second whole source pass appears, ordered work/patch bytes do not silently widen, and only one Codec executor runs.
4. **Freeze one artifact and evaluate the whole fixed seven-family contract.** Compare exact saved candidate samples against authenticated current main, published 0.1.0 and direct prior with p50/p95, exclusions and clock disclosure. Include long edit/Unicode/shape/flow; dense 512/1,024; width/cold/inspection; unchanged ingress; sparse/root publication; selected copy/split; tails/memory/delivery. Report setter and publication separately as diagnostics, while accepting by complete operation. Gate optimized raw/gzip Wasm and JS, package/declarations/ABI/peers, scoped live/completed-call peak plus transition peak, and WebGPU/WebGL pixels, uploads and lifetime. Preserve sparse/read gains and require no unresolved material regression against either main or release. If direct publication improves but dense remains behind, attribute the residual to independently measured setter work before choosing another patch. Do not weaken synchronous setters or start post-parity boost waves without demonstrated parity.

The ranked choice is an experiment, not a speed promise. A failed locator single-pass proof, certificate/rollback mismatch, lost SIMD economics, wider ordered work, transition p95, memory or delivery regression rejects it even if one isolated publication number improves. The next alternative is the separately measured metadata-reset/direct combination; a public scoped batching contract requires an explicit product decision outside this fixed contract. No merge, release, tag or demo merge follows from this report.
