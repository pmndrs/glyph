## Findings

No actionable production defect found in the reviewed slice.

`codec.rs`: `execute_program` retains `validate_execution` before writes and invokes scalar scratch only for a nonempty tail. `execute_scalar_records` owns the former single operation match and output loop; its output ordinal remains `output_start + input_record`. SIMD scratch is initialized once only after `completed != 0`. There is one executor per target path, no retained/global cache or `MaybeUninit`, and no changed published signature or ABI. The validator checks sources before targets (including self-target arithmetic and all `SelectF32` operands), resolves stores by buffer ID, prohibits duplicate lanes and requires full lane coverage. The backward `operation_buffer_masks` resolves store IDs to **buffer indices**, clears a target's consumers before propagating to every source, including self-target and both select branches. Thus, under a fixed active mask, every selected operation reads a current record/group definition and every active output lane has a current store before emission. Inactive slots may retain prior scratch, but their stores and output writes are skipped. Existing output-capacity checked addition/multiplication precedes execution; scalar/SIMD offsets remain bounded. The finite check remains at each active F32 store, preserving prior completed-record/group prefixes and no rollback. Zero mask, no tail, and padded inactive bytes retain the old paths.

`render-planner.ts`: `#compileFrame` still snapshots pending texts. Removal Set order precedes lifecycle upserts in snapshot order; the same pending pass independently emits `orderDirty` entries even without `lifecycleDirty`. The six always-empty fields and absent mutation lists use the existing frozen `EMPTY_REQUEST_ITEMS`; nonempty mutation arrays remain invocation-owned. `PlannerFrameUpdate` fields are readonly, and `PlanTransport.#writeFrameRequest` prepares and writes synchronously, then clears its scratch without retaining the frame. `frame-wire.ts` reads lengths/items without mutation. The revision, acknowledgment, checkpoint generation, root handle, failure/retry and accepted-state cleanup paths are unchanged by this diff. No callback or await occurs during construction.

The native literal-byte oracle now also runs a subsequent distinct-program call. Its expected bytes come from fixture arithmetic, including self-target/redefinition, both select arms and untouched inactive/padding sentinels. The new shipping-Wasm oracle uses real registered font/binding/codec requests: it borrows semantic glyph IDs before publication, then computes expected physical F32/U32/U16 bytes from separately authored glyph columns and literal arithmetic. Result buffer and patch tables supply only the actual bytes being checked. Counts 0..11 cover repeated groups/tails and empty output; both select arms are asserted. The old shipping Wasm control passed all 13 registration tests, establishing that the new tests are viable against the existing artifact only.

A second shipping-Wasm test registers finite `f32::MAX` and `2` constants, reaches arithmetic overflow through a valid codec and asserts public `invalidRequest`, zero revision/buffers/patches. It resets the invalidated root and checks a valid same-text retry with five exact 2.5f32 records. That is a reachable status/recovery proof; the lower-level failing-record/group write prefix remains covered by the native test rather than exposed by this publication result.
