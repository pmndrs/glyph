## One conditional coherent deletion

If a current-source discriminator shows meaningful time in Three state construction/snapshotting for _eligible_ string assignments, add one package-private plain-text entry through the existing configured controller and its Three caller. Gate it on an existing entry, both old/new plain strings with no spans, identical non-text desired properties, unchanged presentation and base/scoped order, and unchanged binding identity. The Three setter has already validated the caller's string before this route. Have the controller send the existing `{text}` retained update, then update its package-owned `#state` only after planner acceptance; retain its existing `PostCommitError` accepted-state handling. Keep the full-state route for all other edits. No public GlyphConfig method or parallel Rust executor is needed.

For the gated cohort this would retire `coreTextState`'s fresh envelope, material-binding lookup and empty-span projection, plus `withOwnedTextPropertySnapshots`'s shallow copy/property checks and `reusablePlainTextUpdate`'s comparison/object assembly. It does **not** retire `replaceDesiredString`'s caller validation, `forkResolvedTextWithText`'s reference increment or prior-lease release, `retainedTextMetrics`, `#prepareTextCandidate`, wire encoding, or Rust preparation. The source bound is O(1) JS per owner plus any empty-span dispatch; dense fixture text is only ten UTF-16 units per owner, so there is no supported O(glyphs) JS saving. Old profile rows are upper context for whole functions, not an estimate of removed work. A new branch and internal entry increase code size and proof cost. Reject this candidate if the discriminator shows the gated work is small relative to mandatory preparation or if eligibility is low.

Ownership/rejection proof is central: the configured controller's `#bound` and leases must remain the same on the gated path; its `#state` and accepted-property inputs must reflect a successful text update, including a `PostCommitError` after Rust accepted state. A precommit fault must leave both old states unchanged. Three `#entries`, desired revision, pending measurement and `stagedDesired` must advance exactly as today. Reject the fast route for changed presentation, inherited material, ordering, font, transform, style/layout/constraints/flow, spans, raster ratio, or detached/boundary transitions. Never defer the synchronous setter preparation or change prepared queries, split copies, batching/order, renderer rejection, or public error identity.
