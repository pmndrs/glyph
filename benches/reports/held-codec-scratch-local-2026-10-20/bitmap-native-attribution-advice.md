# Bitmap dense1024 native attribution: bounded advice

**Decision advice.** After the frozen matrix, make one test-only, authenticated producer-byte bridge into the existing native dense-Inter publication test. This is feasible without a Wasm diagnostic ABI, shipping flag/export, second executor, shadow GLB/Codec parser, or hand-authored Bitmap program. It would measure the native engine's successful production-Bitmap Codec run lengths, selected buffer masks, and F32-store group opportunities for the dense1024 input. It would **not** measure actual Wasm SIMD execution or latency.

The current native observation is a surrogate: `state.rs:12760-12770` matches the bench's 1,024 `alpha/bravo NNNN` labels, but its setup at `state.rs:18439-18466,18511-18583` installs `validated_codec` with one F32 store and synthetic all-glyph availability. Its 10,240 source rows and one active store (`state.rs:12949-12953`) cannot be transferred to Bitmap. The installed bench's `stress.bench.ts:123-141` edits all 1,024 Texts and calls `scene.updateMatrixWorld(true)`; `fixture.ts:242-264` supplies font size 16 and exact width 160, and `fixture.ts:49-60` loads `inter-bitmap-16.font.glb` through the installed package. The separately observed 9,216 visible instances must be an oracle checked for the exact package under test, not assumed from the native test.

## Minimal bridge and owners

1. **TS producer, package test/support script only.** Against the _same installed package root used by Labs_ (`fixture.ts:10-26`), load the same GLB using that package's `glyph.fontFace(... bitmap({strikes:[16]}))` path (`fixture.ts:49-60`). Emit the exact Codec wire bytes through the existing `defineThreeConfig().encode({integration, ids}).descriptor` → `compileCodec` route used by a configured handle (`src/internal/configured-handle.ts:125-129`; `src/internal/handle-state.ts:350-358`); the descriptor comes from `src/three/internal/define-config.ts:27-42` and `src/three/codec.ts:112-161`. Emit `fontBindingBytes(loadedFont, ids)` (`src/internal/font-binding.ts:51-58`) with the same `CodecIdScope`; identities are deterministic hashes (`src/internal/render-id.ts:24-50`). `threeCodecBytes()` is a convenient cross-check only if it compares byte-identical to the configured handle's descriptor in this registration state. Do not serialize a newly assembled JSON approximation. The production bitmap body is `src/raster/bitmap.ts:162-176`; its five F32 buffers plus page buffer are `:150-156`, and its binding columns derive from GLB strike records at `:178-247`.
2. **GLB projection, existing reader.** Emit the GLB's `shapingSfnt`, `glyphExtents`, and `glyphExtentsAvailability` as exact binary sidecars via `readRuntimeFontArtifact` (`src/internal/font-artifact-reader.ts:32-74`), or the validating artifact reader (`src/font-baker/validator.ts:46-55,374-399`). This matters: the current native helper fabricates extents and availability (`state.rs:18422-18437`), so changing only the Codec would still count invisible glyphs. Emit the literal alpha/bravo label lists and their requested style/width settings from the same dense1024 fixture definition, or assert byte-for-byte equivalence to the native construction; no independent reimplementation of the Bitmap compiler or GLB format.
3. **Native consumer, `cfg(test)` only.** In `rust/shaper/src/engine/state.rs`, give the dense-Inter test a Bitmap variant that feeds those sidecars to the existing `ShaperRegistry::register_font`, `codec_wire::parse_codec`, `font_binding_wire::parse_font_binding`, `TextEngine::register_codec` and `register_font_binding` paths (`state.rs:18422-18469`; `codec_wire.rs:54`; `font_binding_wire.rs:39`; Wasm registration uses the same parsers at `wasm.rs:263,308`). Retain the existing mutation/measure/publication sequence at `state.rs:12795-12911`; replace its synthetic font and custom Codec setup, rather than building a second runner. Ensure the selected technique/program IDs and default indexed Three capability match the emitted bytes. Assert native visible/packed Bitmap rows equal the installed scene's separately captured 9,216 count for each relevant cycle; fail on mismatch rather than interpreting different run counts as production utilization.
4. **Counter owner, existing `cfg(test)` work path.** `plan_packing.rs:122-220` has the actual `active_buffers` argument and obtains the selected validated program after a successful `execute_buffers` call. Its current `record_successful_codec_run` counts length, four-record eligibility, tails, and active F32 Store operations (`work_attribution.rs:226-254`). To report _which_ active masks occurred, extend that same test-only record with a bounded `(program_id, active_buffers, record_count, invocations)` bin (or equivalent bounded mask bin), and assert zero overflow; do not infer masks from aggregate operations. For each successful run, also assert/recompute active F32 stores from the parsed program's `StoreF32` operations and selected buffer IDs exactly as `plan_packing.rs:200-219` already does. Report the run histogram, mask histogram, eligible groups/tails, and active-F32-store-group operations; compare the latter with `12 × eligible groups` only as an upper bound for the full Bitmap F32 descriptor, never as an observed count.

**Artifacts and authentication.** Keep the generated Codec, binding, shaping, extents, availability, and workload sidecars together with a small manifest: source GLB SHA-256, installed package root/version or content digest, producing source hashes, each sidecar SHA-256/length, ABI version, transform mode, and sampled/total visible instance count. A deterministic regeneration check should compare every byte and hash before native tests consume them; native tests assert the manifest hashes and parsed program identity/store count. Store the one-off matrix attribution result and exact input hashes under E2, and put any durable generator/fixtures under the package's test/support ownership, not a shipping entry. The GLB inspected here is SHA-256 `acdca408ed169c7aa1c2791dbbc2982afa1939c56fbc59ef43cc38f7ff366c14`; the installed package still needs its own exact authentication at capture time. A fixture built from current source is evidence for that source, not automatically for a different installed canary.

**Limits.** This producer-byte bridge avoids a custom Bitmap Codec and uses real GLB shaping/resource data, but the native test still reconstructs the TextGroup update sequence. The 9,216 instance check, text/style/width equality, selected program identity, output buffer/patch checks, and run-bin consistency are therefore necessary equivalence oracles. If those fail, call the result a matched native fixture rather than actual dense1024 runtime utilization; exact app-wire replay would be a larger separate task. Native `codec_simd_eligible_groups` is eligibility (`work_attribution.rs:95-104`), not evidence that the shipping Wasm `simd128` path ran. No elapsed, GC, cache, or algorithm-selection conclusion follows from these counters.
