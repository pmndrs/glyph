# SIMD StoreF32 finite classifier: scoped proof advice

Read-only source/evidence review of the held checkout at `291fb51ce5e61ca6903b67459872923ccab4ceee`, with the current staged/unstaged wave preserved. No source, fixture, build, test, timing, or profiler work ran for this advice. The seven-family timing matrix was active. This is a conditional proof plan, not implementation selection or a performance claim.

## Decision boundary

A future isolated change can have a sufficient correctness argument **without an export, diagnostic ABI, forged NaN input, or parallel executor**: mathematical equivalence of integer exponent classification for every 32-bit pattern, plus producer-reachable exact-byte/error checks through the actual shipping Wasm and its existing engine API. Those two parts prove different things. The mathematics covers quiet/signaling NaN bit patterns that the public producer rejects. The real-Wasm cases prove the modified private helper is exercised by reachable finite inputs and arithmetic results, including generated nonfinite values. They cannot expose the failing group's internal scratch prefix after publication rejects the frame. Source control flow and the existing crate-local prefix contract must cover that timing detail; native tests alone do not execute the `wasm32+simd128` branch.

Selection remains conditional on actual Bitmap utilization and the frozen matrix. Bitmap's production descriptor has five F32 buffers—origin (2 stores), size (2), UV origin (2), UV size (2), color (4)—and one U32 page buffer (`src/raster/bitmap.ts:151-179`). Thus the classifier applies to Bitmap when those buffers are active. It does **not** follow that Bitmap1024 performs the custom Inter fixture's 2,560 SIMD groups or one active F32 store. Current `plan_packing.rs:203-220` and `work_attribution.rs:226-254` count successful run lengths and active F32 Store operations per eligible group under `cfg(test)`; `state.rs:12760-12965` exercises a custom Inter program with one active F32 store, not the real Bitmap program. No saved Bitmap1024 value for `codec_active_f32_store_group_operations` was found in E2. A minimal future bounded discriminator is one production-Bitmap1024 preparation/publication attribution using those existing counters (or equivalent read-only inspection of that producer), recording each successful run count and active F32-store group operations. Only after that count and the completed seven-family result should the root decide whether this kernel merits an isolated candidate. Count is opportunity, not elapsed cost.

## Exact replacement and equivalence

The sole deletion target is `codec.rs:1444-1449`, `simd_f32_is_finite`: it currently transmutes a `v128` to four `u32` lanes and calls scalar `f32::from_bits(bits).is_finite()` for each. Retain `simd_u32_lanes` for the output fallback at `codec.rs:1420-1439`; it has other callers. A candidate helper can compute `i32x4_all_true(i32x4_ne(v128_and(value, u32x4_splat(0x7f80_0000)), u32x4_splat(0x7f80_0000)))` using the Wasm SIMD intrinsics already available in this module, with the additional `i32x4_all_true` import. This is an integer bit test, with no float comparison, conversion, lane extraction, or NaN payload interpretation. The precise intrinsic names and compiled placement still need verification on the selected candidate's pinned toolchain.

For each binary32 word `b`, `f32::from_bits(b).is_finite()` iff its eight exponent bits are not all ones, i.e. `(b & 0x7f80_0000) != 0x7f80_0000`. The `v128_and` computes that mask independently per 32-bit lane; `i32x4_ne` yields nonzero exactly for finite lanes; `i32x4_all_true` is true exactly when all four are finite. Integer signedness is irrelevant to equality. Sign, fraction, and NaN payload are ignored by both predicates. This establishes all bit patterns, including ±zero, ±subnormal, ±normal, ±infinity, and any qNaN/sNaN sign/payload, without requiring any NaN to cross a production input boundary. Crucially, the helper only observes `value`; `values[store_slot] = value` remains the original `v128`, so accepted output bits stay unchanged. `execute_simd_records:1323-1329` still calls the helper at each selected `StoreF32`, returns `NonFiniteOutput` before assigning that store slot on failure, and calls `write_simd_outputs` only after every selected operation for the four-record group. Earlier completed groups may have written bytes. Scalar tails keep their existing `f32::is_finite` path. For `G` four-record groups and `S` selected F32 stores per group, classification remains `O(G·S)` and constant scratch space; this proposal changes only the constant work per store. Do not hoist the predicate across stores or change operation masks, even if a whole-group precheck looks attractive: that would change failure timing/partial-prefix behavior.

`validate_program:1613-1782` rejects nonfinite F32 constants and proves typed, initialized Store sources and complete output lanes. `operation_buffer_masks:698-729` propagates selected-buffer use backward through definitions. `execute_program:1015-1048` validates shape/capacity, invokes SIMD for `record_count & !3`, then scalar for the tail; `plan_packing.rs:122-194` receives package-owned field slices and calls `execute_buffers` with the producer's active mask. Public `config/codec.ts:808-812`, `internal/font-binding.ts:299-317`, and Rust `font_binding_wire.rs:249-258` reject nonfinite constants/binding columns. A native raw-NaN fixture can check a scalar classifier, but cannot prove the shipping SIMD helper; a copied test-only classifier also cannot authenticate the shipping source. Do not invent an export merely to inject raw NaNs.

## Reachable real-Wasm proof cases

Extend the existing `tests/integration/shaper-registration.test.mjs:1216-1566` route: authenticate/instantiate the built shipping `text-shaper.wasm`, register a validated Inter font, author finite glyph F32 binding columns with `fontBindingBytes`, register a valid program through `renderCodecBytesFromPrograms`, prepare text, borrow the glyph identities, and compare published physical patch bytes against independent literal IEEE-754 little-endian words. Borrowed glyph IDs select authored columns; the Codec does not generate them. For per-position cases, choose distinct glyphs, assert the borrowed IDs are distinct and in range, and then assign values by those IDs. Repeating `AB` shares two binding rows and cannot independently select four SIMD record lanes. Keep the existing `0..11` count sweep for normal outputs, emphasizing 4, 5, 8, and 11: one group; group plus scalar tail; two groups; two groups plus three-record tail. A zero-count success confirms no store, and counts 1–3 cover scalar-only behavior. Read complete physical bytes including strides/padding as the current test does.

For exact accepted bits, use separate direct LoadF32→StoreF32 values authored through finite binding columns (or finite `ConstantF32` immediate words when the same value for all records suffices): `0x00000000`, `0x80000000`, `0x00000001`, `0x80000001`, `0x007fffff`, `0x807fffff`, `0x00800000`, `0x80800000`, `0x7f7fffff`, `0xff7fffff`. Assert registration/borrowed identity and compare raw output bytes to those literals. Do not put arithmetic before the signed-zero store: e.g. addition can change its sign. The JS fixture writes binding columns with `DataView.setFloat32`, while Rust decodes with `f32::from_bits` and rejects only nonfinite values; verify input bytes immediately after authoring where the exact subnormal/zero bit claim matters.

For errors, keep operands finite and create results in Codec arithmetic: `MAX * 2` and `-MAX * 2` yield ±infinity; `(MAX * 2) * 0` yields NaN; `(MAX * 2) - (MAX * 2)` yields NaN. Use one offending record at each of SIMD positions 0, 1, 2, 3, then two positions, with other records producing finite `1.25 * 2` outputs. Place the offender in a later four-record group for an 8/11-record request, and at index 4 or 10 to exercise scalar tails at counts 5/11. The glyph binding must make the selected position genuinely distinct. `StoreF32` must be the first reached store of its buffer in the candidate program when testing rejection, and an additional later StoreF32 operation can guard operation order; expected public result is rejection with no accepted publication. The existing five-record `MAX * 2` rejection → `resetRoot` → valid 2.5-byte retry proves recovery and should be retained or generalized. A NaN _result_ may be canonicalized; assert rejection, not its payload or sNaN identity.

The public engine exposes `invalidRequest`, revision/publication state, and accepted patches, but rejection does not expose the Codec scratch prefix. Therefore a public test cannot claim whether the failing four-record group had internal writes or whether earlier groups had a prefix in scratch. The source placement above and crate-local `later_overflow_preserves_only_the_completed_output_prefix` (`codec.rs:2783-2827`) specify the behavior; that native test currently expects five scalar records before record 5, while a Wasm-SIMD execution would have only the first four-record group complete. The integer-predicate equivalence plus unchanged call site preserves that distinction. If future code moves store timing or group writes, this proof is no longer sufficient and needs an exact-source Wasm internal oracle, not a shipping ABI addition.

After an authorized isolated candidate, run the focused real-Wasm byte/error cases and existing native mask/prefix tests, then inspect its authenticated named optimized Wasm against the packed shipping member. Confirm the helper's four scalar finite-classification extraction sequences are removed in the actual `execute_program` path and the new integer mask/compare/all-true sequence is present, while the four existing scratch zero fills remain outside executor loops. A global `f32x4.extract_lane` count of zero is **not** required because output fallback may still extract lanes. Check final artifact size and required package/downstream/cold/rollback/browser gates at the coherent boundary; one frozen seven-family timing comparison owns performance admission. Static opcode deletion, counters, and mathematical correctness do not establish latency, utilization frequency on their own, or GC/peak-memory benefit.
