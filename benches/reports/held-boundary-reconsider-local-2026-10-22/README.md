## Boundary and cost judgment

The producer path is `packages/glyph/src/internal/render-planner.ts` `#prepareTextCandidate` → `packages/glyph/src/internal/handle-state.ts` request/result handling → `packages/glyph/rust/shaper/src/wasm.rs` parser and `measure_paragraph_with_shaper` → staged query result and `commit_measure` → scene publication. The full-replacement setter prepares one text mutation synchronously; `pending_preparation_ids` clears after each setter, while `unpublished_preparation_ids` accumulates committed owners until publication. Existing buffers and plans persist. This path neither performs duplicate text shaping nor scans the entire root on each setter. Main amortizes a transaction across owners; HELD's public setter must finish synchronously, so a private compact full-replacement descriptor cannot simply defer or coalesce preparation.

A hypothetical no-sidecar descriptor would still require value bounds, revision/generation fencing, Rust validation, shaping, flow, positioning, failure/status ordering, commit, and TypeScript adoption. It would revise the native Wasm ABI and demand matching artifact, rollback and downstream proof. No such product contract or runtime source changed here. The [independent cost review](evidence/current-cost-review.md.raw) finds the HELD setter's JavaScript + allocation + host-runtime self samples total 151,580 µs over 80 callbacks, **not an envelope** for a descriptor: `other Wasm` includes parser, entry, validation and commit. Distinct named self samples are `frame-wire.js` 39,668 µs, Rust `parse_update_request`/`parse_text_mutations` 4,207 µs, named measure entry/wrapper 16,127 µs, `validate_planner_inputs`/`validate_text_mutations` 29,501 µs, and `commit_all`/`commit_paragraphs` 13,833 µs. These are descriptive exclusive profiler weights, not removable elapsed milliseconds; inlining and unresolved nodes limit attribution.

The cluster path offers a genuine but unpriced algorithmic trade-off. Full single-source-run replacement chooses `ClusterArena::build` over the stable-topology copy/overwrite route. The latter copies prior SoA lanes then rewrites touched rows; the former reserves and pushes new fields and rebuilds index/layout units. Fewer copies do not prove lower complete-operation latency. The sampled HELD cluster subtree is about 1.67 ms/callback inclusive, but essential work is mixed in and the main tail blocks causal comparison. No small header/query optimization or cluster switch was selected from this profile. Exact owned allocation counts/bytes were not measured here; no process-memory total is used as evidence.
