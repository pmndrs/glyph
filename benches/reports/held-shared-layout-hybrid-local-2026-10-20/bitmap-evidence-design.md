## Decision

Commission **one untimed, exact-input native replay of the real `createTextBatch(1024)` Bitmap cycle**, conditional on a short authentication gate. Capture the bytes already authored by the package's schema writers and registration paths, replay them through the existing Rust parsers and `TextEngine`/`ShaperRegistry`, and count work at the existing semantic, Codec, ordered and physical owners. Use a within-lease snapshot of the existing package publication solely to authenticate replay output. A publication-only capture cannot expose the earlier `PositionedSemanticGlyph` masks, selected Codec inputs, retained correspondence or equal physical segments suppressed before `PATCH_WRITE`; patch totals alone cannot choose an ownership wave. Conversely, the native custom outlined-Inter fixture does not supply this Bitmap evidence.

The discriminator answers whether the observed dense publication work is driven by actual changed selected inputs and required physical bytes, or by a much larger amount of equal physical output repeatedly mapped/encoded before being suppressed. It **does not** establish removable latency, grant a product patch, or change the fixed seven-family parity requirement. No percentage or 5% floor is an admission rule.

## Bounded capture and authentication

Use the exact installed package fixture: `benches/labs/package/fixture.ts::createTextBatch(1024)` loads `inter-bitmap-16.font.glb` with strike 16, font size 16 and exact width 160; `stress.bench.ts` changes every label between `alpha NNNN` and `bravo NNNN`, then calls one `scene.updateMatrixWorld(true)`. Capture initial construction/publication and one complete forward and reverse edit/publication cycle, including every setter in order. No timing, profiler, altered input, or re-created font model.

An opt-in private observer at existing producers may copy: shaping registration's SFNT, extents, availability and decoration metrics (`src/shaper.ts`); exact compiled Bitmap font-binding bytes, Codec bytes, font-stack handles and root setup (`internal/handle-state.ts`); and the _written_ request-arena slice after `writePreparedPlannerFrameUpdate`, including every preparation and publication request (`internal/frame-wire.ts`, `handle-state.ts`). Hash these inputs, fixture GLB, package archive/Wasm, source commit and diagnostic diff. Do not infer text from labels, synthesize wire structures, or parse a parallel schema. Replay registration with `ShaperRegistry::register_font`, `font_binding_wire::parse_font_binding`, `codec_wire::parse_codec`, then use `frame_wire::parse_update_request` and the existing engine prepare/commit entry points in the captured order. The native parser and Codec are the only semantic authorities. If exact setup or lifecycle cannot be replayed through those existing paths without adding a shadow model or ABI, stop the diagnostic before collecting counts.

For authentication, copy the package's existing borrowed `PlanPublication` patch/payload and semantic result inside its valid lease at the existing private consumer. This is an output witness for replay, **not** a separate publication-only study. Check request success/revisions, selected output records, batch/order/resource identities where stable, draw/glyph counts, patch application to baseline buffer generations, and final physical buffers against the package cycle. Native/Wasm byte differences must be explained or the replay rejected; `inspectDraws` count equality alone is insufficient. The opt-in package image has a new source identity and supplies no frozen-shipping timing claim. Do not persist a runtime hook, cache, public export or diagnostic ABI.

## Counter scope and decision outcomes

Count in one native `cfg(test)` replay only. At positioning, record source glyph count, selected versus recordless glyphs, stable-identity correspondence, exact semantic-mask histogram and per-bit totals for both edits. At gather, record retained versus suffix-rebuild rows, selected record count, Codec dependency-derived input masks, and actual before/after values for selected f32/u32 input columns under the same identity (bitwise f32 comparison). At ordered compilation, record instance comparisons/rewrites, active buffers by schema, records sent to `execute_run`, payload bytes copied from prior, initialized, executed, and compared. At the existing equality guard, distinguish equal suppressed segments from unequal segments; at the existing `PATCH_WRITE` records, count emitted bytes by buffer/schema and alignment expansion. Do not add per-row persistent storage or alter the shipping encoding path. A captured count is a fact about this fixture and cycle, not a cost estimate.

Outcomes are structural, not governed by an arbitrary ratio:

- If selected inputs and emitted physical bytes change across most of the actually visited records, the dense gather/encode/write work has an output obligation. This closes the proposed physical-output ownership wave for this fixture; direct the next parity question to independently measured setter preparation or another source-proven complete operation, without declaring fixed-contract parity impossible.
- If many records are mapped or encoded but their selected inputs or final segments are equal and the equality guard suppresses the resulting writes, identify the exact producer→consumer span and one old operation that could be deleted while retaining identity, Codec dependency, rollback, borrowed-plan and batch/order proof. Only then consider a coherent ownership/layout experiment with a fresh cold physical oracle and same-machine full-operation controls. Counts alone do not approve it.
- If semantic masks are narrow but patch bytes are broad because of alignment, batch/key movement or buffer generation, classify those bytes against the required physical destination. A layout idea must first prove it removes an old path without shifting the work to host updates; otherwise stop.
- If authentication fails, counters differ by cycle, selected inputs cannot be compared under valid identity, or no complete old path emerges, stop with the actual Bitmap ledger and no product wave. Do not rerun a timing arm to rescue a hypothesis.

The independent cold oracle for any later product candidate is a fresh engine/root built from the final authored Bitmap state, compared with the incremental final selected records, normalized ordering and complete physical buffers after applying patches. A second cold instance must not borrow prior retained state. Add seeded Unicode/long edits and rollback/split/lease checks to a _candidate_ gate, not to this one-fixture diagnostic. Same-machine main, published 0.1.0 and live `28fd` complete-operation p50/p95, size, memory, ABI/peers and browser hero gates remain after a candidate is selected.

## Source basis and limits

`codec_gather.rs::append_retained_stream` consumes positioned masks, retains recordless source identities, skips selection for zero masks, and maps Codec fields through dependency masks when necessary. `ordered_plan.rs::compare_retained_instance`, `active_buffers_for_range` and `write_changed_ranges` independently admit ordered slots, construct aligned buffer payloads, compare them to committed bytes, and emit `PATCH_WRITE` only for unequal segments. `plan_view` borrows those records. `work_attribution.rs` is native `cfg(test)` and already has some count seams, but its outlined Inter fixture is not the package Bitmap fixture. The committed `independent-ingress-audit.md` and `independent-next-decision-addendum.md` found no whole redundant live path from source alone. This capture tests the missing actual-input premise; it does not overturn that source finding or reopen E3.
