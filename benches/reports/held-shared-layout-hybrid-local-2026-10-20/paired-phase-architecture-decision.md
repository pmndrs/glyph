# Paired phase architecture decision — 20 October 2026

## Decision

**Close this architecture selection line without a product patch.** Keep the authenticated E2 package (`28fd0413…`, live source `a829…`) held and the correct but slower E3 hybrid preserved at `734dae75` / `experiments/held-shared-layout-hybrid-measured-20261020`. The bounded three-arm experiment identifies where work moved, but neither the source nor the native ledger establishes a complete redundant producer/consumer owner that can be deleted while preserving synchronous prepared queries. A second dense gather mode under the current owners is already represented by E3 and lost its direct-prior comparison. This is a stop for this proposed algorithm, not a parity finding or an impossibility claim. No further capture, calibration, code wave, or boost wave follows from this diagnostic.

## Mechanism and deletion audit

The phase shift matches the two source contracts. In old main, `render-planner.ts::_updateText` records authored/semantic dirt, and `#compileFrame` collects all changed paragraphs into one deferred Rust frame. Published 0.1.0 is authenticated as its own package, not asserted source-identical to main. In HELD, `_updateText` calls `#prepareTextCandidate`; each of the 1,024 setters calls `PlanTransport.prepareParagraph` and `TextEngine::measure_paragraph_inner`, which validates, prepares and positions that paragraph before returning. Later `#compileFrame` carries renderer lifecycle/order with empty text/style/geometry mutation lists, and `prepare_update_inner` gathers and publishes the accepted revisions. A subsequent measure, inspection, or independent split must see that revision. Thus the old setter and HELD setter boundaries perform different semantic duties; the complete callback is the equivalent operation in this fixture. The faster HELD publication is a real stage advantage, but it does not by itself cancel the required synchronous preparation cost.

I tested the first proposed deletion target against its actual producer and consumers. `#prepareTextCandidate` already sets `semanticViewMask` to zero for unqueried text; `PlanTransport.prepareParagraph` records only the result extent when it has no consumer, and Rust appends a measurement sidecar only when the view mask requests one. There is no unconditional sidecar to retire for this dense no-read path. `measure_paragraph_inner::validate_planner_inputs` validates reachable text/style/UTF-16/lifecycle inputs, constructs the candidate and Unicode/edit information used by `paragraph.state.prepare`, then adopts the prepared revision. `prepare_semantic_inputs` routes records for that paragraph; its single-paragraph path avoids the multi-paragraph sort. The checked transaction, immediate failure/rollback and queryable positioned state cannot simply be postponed to publication. The exact Bitmap replay reports 1,024 HarfRust calls, 10,240 UTF-16 units, 1,024 cluster builds and 10,240 positioned rows per edit phase; those counts describe required accepted semantic work until a producer-consumer deletion is proved. Its `mem::swap` arena transfers are ownership moves, not copied glyph rows. Removing no-view result handling, preflight, or the positioning stage would either repeat work elsewhere, lose caller validation, or break the accepted setter contract.

The second proposed deletion target is publication gather. `state.rs::append_planner_gather` feeds `codec_gather.rs::CodecGatherWorkspace` from positioned semantic columns. `append_from`, `gather_fields` and `update_fields` resolve font binding, selection, recordless rows, Codec program and glyph/strike/resource/derived semantic inputs into selected `PlanGlyph` records plus flat field lanes. `GatheredPlanInput::plan_input` hands those lanes to the existing one-wide-run compiler. The corrected exact replay has 10,240 accepted positioned source rows and 10,240 gather source rows, of which 9,216 select records and 1,024 remain recordless. The one 9,216-record Codec run compares 589,824 physical bytes, suppresses 221,184 equal bytes and emits 368,640 changed plan bytes. It records 109,568 f32 reads, including 12,288 reads from attempts that later took fallback, and 97,280 f32 writes. These operations have different semantic and physical duties; equal byte suppression occurs after candidate encoding and does not prove that earlier program-specific field production was redundant. The emitted bytes and selection are required for this fixture. A borrowed positioned-column view would need an authenticated way to replace gather-owned `sources`, selected glyphs, or field lanes while preserving selection, binding/program identity, recordless correspondence, sparse reuse, transactional failure, and wide Codec grouping. Current source/ledger does not supply such a replacement proof. Keeping both sets of columns as a cache would raise live/peak memory and GC pressure, and per-setter renderer-specific preparation would lengthen the already dominant setter phase.

Consequently neither candidate meets the requested standard of one source-proven, complete owner deletion. The published arm's stable whole p50 and main's noisy tail do not justify claiming a precise causal gap coefficient. The phase result supports a workload-level explanation, not an implementation brief for an unproved shared-SoA rewrite. A new E3-like coarse dense reset under these same owners would repeat the already measured slower experiment.

## Bounded next state and reopening condition

Preserve E2 and E3 as above, with the real held stack draft/unmerged. The seven-family parity target remains open. The next implementation wave should be admitted only if a new, independently inspectable producer/consumer proof names the specific old allocation/pass retired in the _same_ source change and shows why queries after every setter, sparse borrow, split independence, recordless/multi-font output, and renderer rejection/retry retain their semantics. For a publication view, the relevant retirement would be one or more `CodecGatherWorkspace` owned source/field arrays and their `gather_fields`/`update_fields` producers, replaced by a single borrowed or directly consumable representation with no duplicate live columns and no loss of the wide Codec run. For a preparation change, the retirement must be a genuine duplicate of `validate_planner_inputs`/candidate work, not the required candidate preparation itself. This is a proof threshold, not a request for another open-ended timing series.

Any future concrete product candidate then needs independent cold layout/IDs/Unicode/flow after **each** setter; exact cold physical buffers, patches, order and bindings after publication; abort, allocation failure, rejection/retry, borrow and independent-split behavior; a frozen shipping package and authenticated named Wasm; and one complete same-machine unprofiled main/published seven-family p50/p95 comparison with size, live/peak memory, peer/API/ABI/lifetime, and browser/hero output gates. Preserve correct inconclusive whole variants for future compatible combinations. No arbitrary percentage floor applies, and post-parity boost count remains zero.
