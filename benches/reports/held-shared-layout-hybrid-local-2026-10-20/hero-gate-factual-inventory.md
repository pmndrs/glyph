## Named workflow contract and safe invocation facts

Root guidance in `AGENTS.md` says to use the pinned toolchain (`mise exec -- pnpm …`), inspect named workflows with `scripts show <name>`, and invoke them as `scripts run <name> -- [arguments]`. The workflow parser strips the conventional `--` before forwarding (`benches/scripts/workflow-arguments.mts:3-6`); `workflows.mts:132-139` prints source, requirements, writes, and usage. Do not pass a generic `--help`: the presentation workflow is a Node runner and its argument parser does not make `--help` a metadata-only operation (`workflows.mts:141-148`; `run-presentation-workload-matrix.mts:4-20`).

For a future fresh E3 presentation screenshot gate, the declared workflow is `benchmark:presentation-screenshots` in `benches/scripts/capture-presentation-workloads.mts:1-13`. It captures every workload on WebGPU and WebGL2 using MTSDF by default, writes ignored `benches/.cache/presentation-screenshots`, requires GPU-enabled Chromium and authenticated benchmark fixtures, and the common probe honors `PRESENTATION_WORKLOAD` (`run-presentation-workload-probe.mts:19-20,100-105`). A focused editorial invocation shape is therefore `PRESENTATION_WORKLOAD=editorial mise exec -- pnpm scripts run benchmark:presentation-screenshots`; this focuses workload selection while retaining the script's two MTSDF backends. This workflow captures screenshots; it does not compare candidate and main screenshots or establish historical fidelity.

For the maintained full workload matrix, `benchmark:presentation` (`benches/scripts/run-presentation-workload-matrix.mts:1-30`) selects `--workload`, `--technique`, `--backend`, and `--typegpu`. Static parser-defined options (not an execution recommendation) allow, for example, the `editorial` workload and each listed backend/technique. It renders all cells if selection flags are omitted. Browser readiness checks are in `run-presentation-workload-probe.mts:135-159`; it records a pinned shaper artifact SHA-256 if `PRESENTATION_SHAPER_ARTIFACT` is supplied and rejects a run where the pinned artifact was not fetched. `PRESENTATION_BASE_URL` reuses an externally managed app URL (`:26-37`), but browser route/proof behavior still requires an explicit baseline/candidate design.

The `benchmark:demo` workflow (`benches/scripts/run-presentation-demo-matrix.mts:1-8`) runs the timed Presentation demo on both WebGPU and WebGL2. Its probe URL uses `workload=off-axis-3d` (`benches/scripts/run-presentation-demo-probe.mts:42`) and contains presentation-control / browser-error checks. It is not an editorial hero screenshot workflow.

## Lifetime and final-gate boundary

The existing presentation workload probe covers live canvas identity and configured-renderer state across its observation interval, and has explicit canvas handoff/backend-switch and GPU frame timer retirement logic (`benches/scripts/run-presentation-workload-probe.mts:164-215,402-474,495-565`). This provides browser lifecycle observations for that presentation harness. The demo probe separately checks playback controls, focused shortcuts, renderer canvas retention, and browser/render errors (`benches/scripts/run-presentation-demo-probe.mts:53-103,128-162,225-262`).

These checks do not by themselves establish every public package lifetime boundary: caller-owned font, text, handle/root/engine disposal and post-dispose API behavior need to be matched to the current public API contracts and current release declarations/source. The prior packed inventory's Wasm disposal export names/arities (`api-abi-inventory.md:1005-1084`) establish exports and arities only, not semantics or complete lifecycle correctness. The prior review says no concrete current API, ABI, peer, or lifecycle defect was confirmed, while explicitly identifying itself as source evidence rather than runtime proof (`api-abi-inventory.md:1634-1636`).

Consequently, the final required API/ABI/peer/lifetime gate remains distinct from the browser gate. Browser evidence available in E3 (ASCII cold phases and dynamic-layout cells) does not cover this hero/editorial visual scope. An accepted new local baseline requires root/human to define the target composition and comparison contract; the repo supplies no historical hero identity to recover. No runtime claim is made here.
