# Independent Bitmap setter ingress audit

20 October 2026. **Finding: no source-proven, material ingress/adoption deletion is admitted for the real 1,024-label Bitmap setter.** This is a read-only source audit of the frozen E3 worktree plus the authenticated E2 source profile, not a timing or runtime-count claim. The direct E3-versus-`28fd` arm is terminal and disfavors E3 live admission. No product source, build, test, profile, matrix file or Git state was changed.

The concrete workload is `benches/labs/package/fixture.ts::createTextBatch(1024)`: authored Inter Bitmap font, size 16, width 160, plain strings `alpha 0000`… toggled to `bravo 0000`… and one later scene publication. It is not the native outlined Inter/Codec fixture. Its bound setter chain is:

1. `three/text.ts:934,975–1022`: `text` calls `set`, checks the update, creates a frozen plain-string desired state via `replaceDesiredString`, then stages it through the bound publication. `replaceDesiredString` scans UTF-16 surrogate pairs at `:2155–2165`; this supports its specific public `RangeError` and offset. Same-value text exits before staging.
2. `three/text.ts:1567–1590,1858–1954,1971–2006`: publication resolves inherited group/material/order, creates a core state, then invokes the configured controller. For the fixture's empty spans, `mapTextSpanBindings` returns its shared empty array (`config/text-span-owner.ts:181–202`). `resolveTextPresentation` caches the immutable result after checking actual parent/group properties; removing that check without an invalidation proof would miss external Three mutations. No sibling-wide traversal occurs here: `paragraphOrderRank` reads this Text's `renderOrder` (`three/text.ts:2367–2370`).
3. `internal/configured-handle.ts:888–944,1022–1105`: property snapshots reuse accepted identity; `reusablePlainTextUpdate` passes only the changed `text` to `RetainedTextImpl.update`. This path does **not** rebind all fonts/material/transform leases for each Bitmap edit. The general rebind branch remains needed for changed bindings/presentation and cannot be retired from a plain-text-only observation.
4. `internal/render-planner.ts:698–859,2100–2130,2156–2188,2219–2265`: `textOnlyUpdate` checks inline-object offsets and length-sensitive style feature ranges, then `forkResolvedTextWithText` shares the existing lease owner. Aggregate limits are maintained by counts, not a scan of all pending labels (`:1372–1429`). The same-length plain edit has no style change or geometry dirtiness; `#prepareTextCandidate` emits a single full-span text mutation and empty style/constraint/region/exclusion/inline arrays (`:1234–1320`). It must adopt the prepared revision before returning; the later publication owns order/physical output separately.
5. `internal/frame-wire.ts:279–445` and `internal/handle-state.ts:1371–1410,1655–1689`: `preparePlannerFrameUpdate` computes the exact ABI section offsets/length, writes into the retained request arena, and `prepareParagraph` calls the Wasm measure entry. `writePreparedPlannerFrameUpdate` zeroes the entire bounded request before populating it; a deletion would need reserved/padding/invalid-request proof. There is no per-setter heap-owned final wire buffer on this path.
6. Rust `engine/frame_wire.rs:41–170`, `state.rs:1379–1568,6221–6380,4373–4509,4555–4595,2144–2192`: the parser validates borrowed sections; engine checks root/codec/revisions/lifecycle, then validates mutations and retained style ranges before semantic writes. Preflight prepares one text/Unicode candidate. `ParagraphState::prepare_text` swaps or consumes that candidate, and `prepare_unicode` reuses transferred analysis; tests at `state.rs:16095–16180` explicitly guard no reanalysis. Same-length commit mirrors changed units/IDs into the inactive buffer for subsequent setters (`:4570–4595`). `commit_measure` then adopts the prepared revision without advancing the renderer publication revision. This is one Rust authority, with separate error and renderer lifetimes.

**A real but unpriced constant-work opportunity remains:** `ThreeRootPublication.#stage` still constructs `coreTextState` and resolves material/presentation for each changed label, while `ConfiguredTextController.update` makes a shallow property-snapshot envelope and reclassifies a plain-string update before passing `{text}` to the planner. A new internal Three→configured shortcut could delete those envelopes/lookups for a tightly guarded plain-string cohort, but it would introduce another cross-owner entry and substantial state/error/lifetime proof. The authenticated `28fd` profile reports sampled JS under these functions, yet it does not measure statement-level removable time; the largest known dense gap is milliseconds per full cycle. This is source-supported **existence of constant work**, not source-supported material benefit or an admitted implementation. If a later whole-operation discriminator finds that this cohort dominates enough to matter, preserve public surrogate/error checks, current presentation/order observation, `PostCommitError` adoption, accepted lease ownership, and the existing Rust prepare/adopt tail; otherwise do not add a fast lane.

**Repeated work found, but not a safe deletion:** Three's `assertPairedSurrogates` and Rust's `validate_text_mutations` both inspect the inserted UTF-16 units. Rust then decodes those units into the candidate buffer in `apply_text_mutations`. The first check gives the immediate public error with an exact text offset; the Rust check defends an ABI boundary that can be called without Three, and all-input preflight must reject a bad batch before partial semantic adoption. The later decode constructs owned Rust text. Removing either validator, or declaring the JS check authoritative over untrusted wire bytes, changes an error/trust contract; fusing validation with candidate construction would require a transaction-wide rollback proof and an observed material cost. For this fixture each authored string has ten units and one mutation, so source alone gives no reason to expect this tiny repeated scan to close a 2–3 ms dense gap. The Wasm allocation phase split and sampled CPU scope cannot establish its removable latency.

**Other candidates inspected and rejected at source gate:** there is no per-setter style/geometry reserialization after initial creation, no full lease rebind in the configured plain-text fast path, no repeated Unicode analysis after preflight transfer, no root-size aggregate-limit scan, and no generic `O(N)` sibling rank lookup in the setter. The full-span text mutation is an actual chosen representation: even though the alpha/bravo prefix differs, the authored setter supplies a complete new string, and the Rust reconciliation derives the changed interval. A different producer diff would need its own cost, UTF-16 boundary, style/identity, failure and public-error proof; this audit does not admit one. Repeated request-header write/zeroing and layered mutation guards exist, but their constant-sized per-call work is unquantified and cannot responsibly be named the primary target.

**Decision under the accepted synchronous contract, updated for the completed matrix:** Do not start a rank-1 ingress rewrite from this audit. The direct E3-versus-`28fd` arm did not earn E3 live retention: preserve its whole correct source under a named recoverable ref/archive, then restore the prior live branch after source-choice verification. The next bounded diagnostic, if still useful after preservation, is the matched actual-Bitmap setter/publication allocator split in the architecture report; it selects a source ownership question, not a latency winner. If phase/source evidence finds no complete old path to delete and indispensable HarfRust/flow/positioning dominates, disclose the accepted contract price; parity cannot be asserted from aggregate row wins or declared impossible without a lower bound. Changing when preparation becomes observable would require a human contract decision.

The remaining causal gap is exact actual-Bitmap semantic work/allocator-site attribution. The frozen Wasm has no production work-count ABI, and `work_attribution.rs` is native `cfg(test)` only. A producer-native replay is worth building only after exact schema-backed request bytes and font binding are captured and compared with package output. Do not use custom outlined Inter counters as Bitmap facts or add a shadow parser/model just to fill this ledger.
