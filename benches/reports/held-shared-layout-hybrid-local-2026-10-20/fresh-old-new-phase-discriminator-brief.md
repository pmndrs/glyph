Its `sampledMs.stages` classifier is **not** a setter-vs-publication phase split; E2's previous split required manual fresh ancestry anchors. To obtain comparable wall-boundary evidence without changing any package, make one diagnostic-only harness edit in `benches/labs/package/edit-sized-publication.profile.mts` **before** any of the three captures: in `updateBulk`, take `performance.now()` immediately before the setter loop, immediately after it, and immediately after the scene publication. Accumulate one setter-loop duration and one scene-publication duration per timed iteration, with a separate warmup sink and no clock call inside an individual setter. Record these 80 paired values, their p50/p95, and the unassigned callback/observer residual in `summary.json`. Keep the existing outer whole-callback timer and V8 profile. Do not add reads, `glyph.shape()` alternatives, cold comparison, descriptor walks or allocation probes inside the timed callback. One fixed observer patch and one fixed harness SHA apply to **all three** arms. This patch changes a benchmark observer, not package source or package bytes; its timer overhead is a diagnostic limitation and cannot replace the original unprofiled acceptance matrix.

Before each capture hash the chosen archive and the frozen harness/workflow/fixture sources. ## Sample ancestry and boundary checks

For each raw CPU profile, select fresh phase roots from that profile's own V8 tree. The preferred roots are the `set text` accessor in the installed Glyph `dist/three/text.js` and the external Three `updateMatrixWorld` call, both direct descendants of the same `updateBulk` harness node. E2's earlier authenticated capture had roots 7 and 53 under node 6; those IDs are **not** reusable. Validate exactly one root of each kind, same parent, disjoint descendant trees, and positive sample coverage. Feed that capture-specific ancestry JSON to `benchmark:cpu-profile-summary`/`benches/scripts/support/cpu-profile-summary.mts` (its `--ancestry` option) with the exact archive and manifest. Report preparation, publication and unattributed sampled CPU; use the independent wall-boundary durations as the primary phase comparator. Sampling trees may include a detached runtime/GC stack or native work that no longer descends from either root, so unattributed time stays explicit.

If main or minified published JS changes the V8 shape (accessor inlined, multiple direct nodes, renamed frame, or missing direct parent), **do not reuse E2 anchors or assign samples by substring**. Keep the wall-boundary durations from the fixed observer, report CPU ancestry unavailable for that arm, and stop all source-level/within-Wasm attribution. If the fixed observer itself fails to conserve the whole callback within timer-resolution/recording overhead, or the current code path does not execute one scene publication per iteration, classify the phase experiment infeasible; preserve the raw capture and do not infer a phase gap. `classifyCpuProfileStage` can label `wasm://` samples generally but the un-named old/release functions remain `other-wasm`; allocator calls, request/result bytes, GC pause cost, private Three buffer writes, GPU uploads and Rust-native per-stage latency are **not counted** by this workflow. `--expose-gc` collects once before the timed loop, not a per-phase allocation ledger.

The phase names describe **call boundaries, not equivalent semantic duties**. Main and release setter loops mainly stage changed JS state; their scene publication performs deferred Rust semantic preparation. HELD's setter loop performs 1,024 synchronous `prepareParagraph` transactions and its publication consumes the accepted revisions. The comparable outcome is the complete 1,024-setter-plus-one-scene callback and its final output. A setter-phase excess in HELD may be balanced by a publication-phase saving; subtracting setter durations alone would mistake work movement for a regression. Show all three phase and whole-operation distributions side by side, plus the older unprofiled E2 matrix as a separate acceptance reference. One profiled run is a directional mechanism discriminator, not a p50/p95 parity gate.

## Output oracle and decision boundary

The existing `bulk-write` post-timing checks require every authored final string, nonzero glyph counts, committed states and `measureGlyphs()` output; the summary records initial/final draw and glyph topology. Require **each** arm to finish with 1 draw and 9,216 glyphs (or stop and explain a legitimate version-specific topology difference), exactly 1,024 final strings, no `textGroup.error`, and no timed reads. Keep the already authenticated Labs matrix/browser results attached as stronger version-level context. The current profile does **not** compare exact physical buffer bytes across packages or independently cold-recompute all layout columns. If this diagnostic leads to a product wave, require a separate independent cold layout/physical output oracle before acceptance. A harness-only, post-profile cold fixture can compare shared public glyph placement columns within each archive, normalizing only version-specific handles/stable IDs; do not describe a coarse glyph count as that oracle. If such a cold check requires a different public surface in published 0.1.0, record the mismatch rather than silently drop that arm.

The decision is bounded to one complete capture per arm and one review. If the same complete output is shown and HELD's _whole_ callback excess comes mainly from the setter boundary while main/release publication work is correspondingly higher, the first product question is a named setter-side repeated preflight/sidecar whose removal preserves immediate prepared reads. If excess remains in HELD publication with authenticated source counts showing repeated gather/encode of equal output, the first product question is a shared positioned-column consumer that **replaces** a gather owner and keeps the wide Codec run. If both stages contribute, select only a wave that deletes a proven owner from the accepted path; a phase delta alone is not a deletion proof. If the profiled phase differences are small, unstable, contradictory between main/release, dominated by unattributed/host work, or have no source-proven removable owner, stop this line with E2 held and E3 preserved. No arbitrary percentage threshold, new timing series, product patch or boost-wave count follows from an inconclusive capture. Final parity still requires fresh same-machine unprofiled complete-operation controls across all seven families and the independent correctness, ABI, lifetime, size, memory and browser gates.
