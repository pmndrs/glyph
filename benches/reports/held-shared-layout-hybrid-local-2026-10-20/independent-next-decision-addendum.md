# Independent next decision after the three-arm E3 matrix

This is a read-only source gate on the restored `a829`/`28fd` package tree. It supplements, and does not revise, the authenticated `independent-architecture-reset.md` and `independent-ingress-audit.md` receipts. Root is independently authenticating the restored package. No product implementation, allocator split, build, profile, or timed run was performed for this addendum.

## Decision

**Skip the matched E3/`28fd` allocator phase split.** The correct E3 implementation is preserved, but its direct prior arm is worse on dense 512, dense 1,024, and sparse edit-and-borrow. Splitting E3's extra aggregate diagnostic allocations between setters and publication would describe a rejected branch, not identify an allocation site, removable operation, or the live `28fd` parity gap. Leave `transaction-ledger-proposal/split-dense-phase.patch` unapplied. The E2 authenticated `28fd` profile already separates sampled CPU under setter and publication anchors; its samples are not removable elapsed time.

The live-path **producer→consumer deletion gate also fails on source evidence currently available**. I found no entire repeated semantic or physical production pass that can be removed with the accepted setter/query/split behavior and one executor. Do not start a new product wave from this audit. This is not a proof that parity is impossible: actual Bitmap changed-field and physical-byte counts are unavailable, and no causal elapsed contribution has been assigned to a candidate deletion.

## Actual Bitmap route and ownership

`benches/labs/package/fixture.ts::createTextBatch(1024)` creates 1,024 retained Text nodes using `inter-bitmap-16.font.glb`, font size 16 and exact width 160. `stress.bench.ts` alternates `alpha NNNN` and `bravo NNNN`, calls each synchronous setter, then one `scene.updateMatrixWorld(true)` and checks the group error/text count. The text lengths match; identical length does not establish retained glyph identities, selected records, masks, codec fields, or physical bytes.

The setter's `RenderPlanner.#prepareTextCandidate` sends a text mutation through `PlanTransport.prepareParagraph`, and Rust `Engine::measure_paragraph_inner` prepares and adopts the paragraph's positioned state without gather or render-plan compilation. In a later scene publication, `state.rs` handles the pending prepared owners. `prepare_placement_slots` maps their already positioned segments to root/session slots; that work owns cross-paragraph slot identity and session translation rows, not a second shape/flow calculation. `append_planner_gather` reads each paragraph's active positioned glyphs, semantic SoA fields, change masks and translations. It attempts retained gather when the cached key, owner order/count and decoration conditions permit; otherwise it resets and appends. `CodecGatherWorkspace::append_retained_stream` pairs source identities and selected records. Its zero-mask branch avoids font binding/codec selection; position-only changes use a narrow path; other changes select the binding and map only codec inputs required by the semantic mask. A late mismatch stops into a suffix rebuild, preserving transactional correctness.

`RenderPlanCompiler::prepare_owned` consumes the gathered `PlanInput` once. `OrderedPlanCompiler::prepare_internal` admits retained or complete topology, then prepares batches, physical patches and bindings. Retained complete scope still compares every physical instance because source masks do not establish batch/key/slot identity or physical equality. Sparse scope limits admitted rows when an authenticated interval exists. The exact-shape repack is conditional; source notes already establish it is a first/fragmented-state path, not a per-sample cost to delete. `write_changed_ranges` uses codec dependency masks to select active physical buffers; it then builds patch payload, copies prior bytes when valid, executes changed runs, and compares completed bytes to committed buffers before emitting `PATCH_WRITE`. The equality guard already suppresses identical host writes. `plan_view` borrows patches/payload and conditional resource/buffer/draw tables; the target consumes this synchronously, after which the lease expires. Aborted or rejected publication must leave committed semantic/physical state and buffer generations valid.

These are distinct ownership transformations: positioned semantic columns → selected codec inputs/records → ordered instances and batch mapping → encoded physical bytes and patch/lifetime records. They can have overlapping scans, but neither the source nor the authenticated actual Bitmap evidence proves a whole transform redundant. Fusing two owners would have to retain recordless-source selection, sparse correspondence, codec dependency handling, batch/slot admission, fallible rollback, borrowed-plan lifetime and cold physical output. That is a redesign without a deletion proof, not this wave. In particular, the existing generic rope already reuses unique leaves, the changed-leaf vector is final storage, and `Staged<T>` retains pending allocation; their removal is not available work.

## Narrowest evidence that could reopen a physical-output wave

The one remaining bounded ownership question is: **for the actual 1,024-label Bitmap alternation, how many prepared glyphs have a nonzero semantic mask, how many selected codec input/physical buffer columns change, and how many bytes are ultimately emitted as host patches?** If nearly all affected physical bytes change, the gather→encode→write path is likely required output work, and no dense physical-product wave is justified. If most encoded bytes compare equal while `28fd` repeatedly maps or encodes them, inspect one exact producer→consumer span for a deletion that preserves mask/identity/fallback proof and removes its old path entirely. A count alone cannot admit a product patch; a cold independent physical-byte oracle and whole-operation same-machine controls remain necessary.

The frozen E2/E3 images do not expose those per-stage actual Bitmap counts. `work_attribution.rs` is native `cfg(test)` and its custom outlined Inter fixture is not this package fixture. A later _diagnostic-only_ attempt must capture the existing producer's exact request bytes and font binding through its schema-backed transport, authenticate that replay against the package fixture/output, then use the existing native Rust parser/attribution. Alternatively, an opt-in private publication capture may read the existing borrowed plan's patch table within its lease, but it changes the package source identity and cannot be called frozen-shipping timing. Neither route may introduce a shadow Unicode model, guessed request schema, public/diagnostic ABI, or a new persistent cache. Do not commission this capture until a precise source candidate predicts a useful counter threshold; this audit found none.

**Stop condition now:** keep `28fd` live, preserve E3 whole under its named ref/artifact, and report the fixed-contract parity gap as unresolved. No next product implementation is selected. If the project wants to pursue parity further, first name a whole removable owner/path or explicitly reconsider the accepted synchronous preparation contract with the human. The current evidence does not support claiming that contract makes parity mathematically impossible, nor does it support another small timing rescue wave.
