## Clean findings and reasoning

- `state.rs::validate_planner_inputs` calls `validate_text_mutations` before either production `utf16_boundary_after_mutations` closure is created (lines 6191–6196 and 6233–6239). The existing-paragraph closure captures the same borrowed committed `units` and `paragraph_text` batch; the absent-paragraph closure captures the same empty committed slice and batch. Their `u32` length conversions remain checked. Style validation receives these immutable text borrows and only mutates style scratch; Rust's borrows prevent a text edit or batch mutation between validation and predicate use. The removed helper loop repeated `check_text_mutation` and final-length discovery, and could not reject a reachable mutation after the preceding validation. `validate_text_mutations` still checks every mutation's range and `u32` length overflow, insertion scalar validity, surrogate boundaries, and seams before any pending text write. `apply_text_mutations` still uses `check_text_mutation` when it eventually applies edits.
- The helper retains out-of-range rejection, both valid endpoints, prior/current unit lookup at interior offsets, and `valid_utf16_boundary_pair`. On the validated input domain, the `u32` length has the same value as the old recalculated `usize` length. Its only other call is the new test. No new error variant, public result, ABI, allocation, or retained cache is introduced.
- `style_state::validate_style_ranges` retains authored and effective numeric order/bounds checks, then reuses an authored boundary result only for an equal effective coordinate. Every distinct effective coordinate still calls the classifier. The authored checks short-circuit on failure, so skipping an equal effective call cannot turn an invalid boundary into success. Font-stack, root, and feature checks and their `FrameFault` identities remain in the same order. `validate_style_value` supplies identical authored/effective coordinates; retained styles can supply different ones, which remain checked.
- Predicate authority is internal and pure: `state.rs` constructs both preflight predicates from the helper; `style_state::validate_text` constructs its own from `lib.rs::valid_utf16_boundary`, which reads only the text and offset. The two `StyleArena` preflight methods are only called from the inspected state preflight in production. The `FnMut` type is generic, but no third-party callback contract is exposed. The new style test's recording closure is test-only and does not establish an external callback obligation.
- The new independent UTF-16 sequence oracle in `validated_mutation_boundaries_match_materialized_utf16` checks sequential edits, inserted surrogate pair, all final offsets and one past-end against `valid_utf16_boundary` on an explicitly materialized expected sequence. The distinct-coordinate style test checks actual predicate call order and a rejected invalid effective endpoint. Existing full-suite cases exercise deleting half a surrogate before writes, retained style errors and root range errors, text-only and style-upsert preflight, and late invalid paragraph atomicity.
