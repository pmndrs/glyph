One portable technique, many renderer choices

The hardened contract makes a raster technique reusable without putting Three.js, TypeGPU, TSL, WGSL, or GPU objects into core. The technique owns data and a portable policy body. Each engine owns its numbered policy, shader selection, resources, geometry, material or pipeline, and submission.

Outcome

What is portable

Technique identity, schema, named bindings, constrained immutable resources, geometry declaration, policy-body factory, compiled binding bytes, and optional shader-language subpaths.

What stays engine-owned

System-buffer names, capability sets, policy-handle names, program namespace, shader selection, GPU realization, material/pipeline construction, transforms, upload and retirement rules, and submission. Numeric IDs are derived by the shared branded hash helper.

Current acceptance evidence

The external example runtime-bakes Inter, compiles and registers its portable binding, realizes named geometry and policy buffers with TypeGPU, submits indexed instanced WebGPU draws, reads RGBA pixels, updates retained text, and proves that the pixels change. The recording device remains a deterministic CPU oracle.

First-party parity

Bitmap repeated strikes, the MSDF atlas/range pair, and Slug repeated page groups now compile through the same portable resource contract as an external technique. Three retains only shader/material and GPU realization.

Runtime, host, session, renderer, and canvas topology

The core hierarchy ends at an abstract plan target. Canvas, texture, renderer, render pass, and GPU device objects remain renderer-owned. The target tells one session whether its candidate actually committed, so the session—not application revision arithmetic—owns one acceptance frontier.

The cardinality graph

Canvas rule: one session has exactly one target. That target may own several canvases only as a lockstep group: prepare every member before any accepted-state commit. A post-prepare partial backend failure marks the whole group lost and requires a session checkpoint. If canvas A may advance while canvas B remains on an older plan, use separate sessions.

Concrete deployment maps

Single canvas

Recommended: one of each. Share ordering, batching, capacity, and acceptance.

Two independent canvases

Share font bindings and a device pool; split sessions because acceptance can advance independently.

Mirrored lockstep output

Prepare both before committing either. If a physical commit partially fails, mark both lost and request a complete session checkpoint.

Transferred OffscreenCanvas

Move the whole engine and renderer into the worker; messages carry authored state, so the borrowed path remains available.

Worker shaping, main-thread rendering

The source endpoint resolves every referenced resource, then transfers owned plan bytes plus an authenticated digest/descriptor manifest. The receiving endpoint validates both, realizes and commits the renderer transaction, and transfers the plan buffer back with its correlated result. Only then does the target resolve acceptance and advance the session fence.

Two renderer integrations

Split hosts for policy and teardown ownership, not per canvas. The runtime deduplicates each font's Wasm registration.

What the target API permits

There is no core Device class. Core exposes a host and a renderer-implemented target contract. The host owns portable policy/font registrations and sessions; the target reports renderer commit. The overloaded word “binding” is the source of confusion: host.bindFont() creates a portable engine binding and resolver, not a WebGPU bind group. Two canvas targets can consume that same portable binding while their renderer either shares one same-device realization or creates two context/device-local realizations. Numeric wire keys are host-scoped; physical caches are separately scoped by renderer resource domain, authenticated payload identity, and variant, so equal numbers cannot alias across contexts.

When should you split each owner?

Use another runtime

Split for another JavaScript realm or worker, another Wasm build, a hard memory/failure boundary, or truly independent teardown. Do not add a runtime merely for another canvas, policy, or document; it duplicates Wasm and registered shaping bytes.

Use another host

Split when policy registrations, renderer integration ownership, plugin trust, or teardown must be independent. A second canvas alone does not require it because the host owns no physical GPU objects.

Use another session

Split when text sets need independent revision/acceptance frontiers, resource retirements, capacities, scheduling, or failure isolation. Keep text together when cross-text ordering and batching matter; the engine cannot batch or order across sessions.

Use another device pool or target

Split GPU realizations per GPUDevice or WebGL context. Split acceptance per independently advancing canvas or texture. WebGPU canvases configured with one device may share a pool; lockstep surfaces may share one composite target and session frontier.

Recommended public ownership shape

Load the portable font before a runtime exists. Attach the integrator-only host to a runtime owner, bind the font through leases, and bind one renderer-owned target to each session. Canvas and GPU objects stay behind the target.

Root remains the useful application barrel. Portable names such as Font, FontStack, defineFont, loadFont, txt, span, paint, layout, measurement, technique, and baker contracts remain available from @pmndrs/glyph. Runtime, host, session, policy, plan-reader, and renderer-implementation types live in /core. An integration may re-export a root type only when its own signatures use it; it does not mirror the barrel. This removes runtime ownership from Font, and removes IDs and revision arithmetic from the public integration path without changing the compact numeric wire format. The raw frame compiler becomes package-internal test/fuzz infrastructure; a worker uses AsyncPlanTarget and returns its plan buffer with the commit answer to the same target-bound session.

Zero-copy is the default. PlanTarget consumes the borrowed A/B publication and makes publish() synchronous. Only AsyncPlanTarget receives one exact-range standalone copy and returns a Promise. The bounded transfer pool reuses only exact-byte-length returned allocations, so the candidate always spans its complete backing and no oversized subview helper can create a second copy. That buffer is transferred—not cloned—to the worker and returned with acceptance. Before the async call, the session resolves every referenced portable payload; canonical Font backing is never detached. The host infers the session return type from the target factory and rejects target reuse before allocating Wasm state.

What the renderer's target actually does

// Renderer-owned target; illustrative target API.
function createPlanTarget({ control, pool, canvas }) {
  const device = pool.device;
  pool.attach(control); // one device pool tracks every attached session

  return {
    delivery: 'borrowed',

    accept(candidate, signal) {
      // candidate.origin namespaces mutable session buffers.
      // Font payload identity pools immutable resources across sessions.
      const pending = pool.prepare(candidate, {
        acquirePayload: (referenceId) => candidate.acquirePayload(referenceId),
      });

      try {
        const pass = device.beginCanvasPass(canvas);
        pending.encode(pass); // uploads, resources, geometry, pipelines, draws
        device.submit(pass);  // synchronous enqueue/transaction boundary
        signal.throwIfAborted();
        pending.commit();     // swaps live state only after complete success
        return { accepted: true };
      } catch (error) {
        pending.discard();    // destroys only uncommitted candidate objects
        return { accepted: false, error };
      }
    },

    dispose() {
      pool.detach(control);
    },
  };
}

// Device replacement is one pool event fanned out to every live session.
pool.onDeviceLost(() => {
  pool.stopAccepting();
  pool.rebuildPhysicalObjects();
  pool.resumeCheckpointRequired(); // required state is tracked per control
  for (const control of pool.controls) control.requestCheckpoint();
});

A plan resource retirement releases the session's lease. The pool destroys a texture, supplied geometry buffer, or other immutable realization only after its final device-local lease ends. This ordinary target reads a lease-bound borrowed publication whose methods throw after accept(), prepares and submits renderer work, commits renderer state, and answers before returning. GPU execution may finish later; that does not require copying the plan or awaiting popErrorScope(); later WebGPU validation/device faults enter the renderer's lost/checkpoint path. A worker round trip instead uses AsyncPlanTarget: core copies only the exact Wasm publication range, the target transfers that standalone buffer and its pre-resolved resource manifest without another clone, the receiver validates and commits, and then transfers the same allocation back with the correlated result. A missing payload uses a separate exact-range transfer copy; a canonical Font backing view is never detached. The returned acceptance advances the session fence; a lost worker leaves it unchanged. For a lockstep target, every surface prepares before any accepted-state commit; partial backend commit makes the whole group lost.

Disposal without finalizers

Runtime disposal deterministically cascades sessions and hosts; stack and binding leases protect Font backing and renderer resources. An unused Font needs no finalizer: when its wrapper becomes unreachable, its backing is unreachable too and ordinary GC collects both. Runtime lookup maps are weak and release Wasm registration at lease zero; a strong cache exists only inside an explicit application-owned FontLibrary. font.dispose() provides deterministic early release while the wrapper remains reachable and rejects new bindings.

import { createTextRuntime, FontRegistry } from '@pmndrs/glyph';
import { textRuntimeShaper } from '@pmndrs/glyph/core';
import { glyphExample } from '@pmndrs/glyph-example-raster';

const runtime = await createTextRuntime({ registry: new FontRegistry() });
const adapter = await navigator.gpu.requestAdapter();
if (!adapter) throw new Error('WebGPU is unavailable');
const gpuDevice = await adapter.requestDevice();
const device = new TypeGpuExampleRendererDevice({
  device: gpuDevice,
  width: 768,
  height: 192,
});
// Constructor: TextEngineHost + compileRenderPolicy + host.registerPolicy.
const engine = new ExampleTextEngine(textRuntimeShaper(runtime), device);

// Per font: load shaping/raster data, compile its portable binding, realize resources.
const font = await runtime.loadFont({
  input: { baked: bakedFontUrl },
  raster: { technique: glyphExample, options: { paletteSeed: 7 } },
});
const binding = engine.registerFont(font);

// Per fallback list, then once per independently revisioned text scene.
// The wrapper allocates IDs callers never need to invent.
const stack = engine.registerFontStack([binding]);
engine.openSession();

// Per text instance: the wrapper owns paragraph/style/flow/region IDs.
const title = engine.createText({
  fontStack: stack,
  text: 'Hello Glyph',
  fontSize: 48,
  width: 768,
  height: 192,
});

const first = await title.render();
const firstPixels = await device.readPixels();
if (first.draws.length === 0 || !firstPixels.some((value, index) => index % 4 === 3 && value !== 0)) {
  throw new Error('expected a visible GPU frame');
}

// A later edit updates the same retained instance and session.
title.update({ text: 'Hello retained Glyph', foregroundRgba: 0xff40_a0ff });
const second = await title.render();
const secondPixels = await device.readPixels();
if (second.draws.length === 0 || !firstPixels.some((value, index) => value !== secondPixels[index])) {
  throw new Error('expected the retained update to change GPU pixels');
}

// Teardown: the wrapper disposes its session and host; runtime is the outer owner.
await title.dispose();
engine.dispose();
font.dispose();
device.dispose();
runtime.dispose();
gpuDevice.destroy();

ExampleText is the application text object and the source of mutations; the session is the retained compiled state. The wrapper creates its branded paragraph/style/flow/region identities, emits the complete initial mutation batch on the first render(), diffs later update() calls, and publishes a paragraph removal from dispose(). This is the current baseline only; the target API replaces its raw session bookkeeping with the target-bound lifecycle above.

Three wraps this bookkeeping in Text. new Text({ font, text, style }) creates the application instance; adding it to a TextGroup establishes batch ownership. Assigning text.text, text.style, text.contentBox, or calling text.set(...) queues the corresponding minimal mutations. An attached text.layout() can shape and measure that desired state immediately without traversing matrices or realizing draws. Three's normal render traversal later publishes the full plan and transform table.

Policy timing: a policy describes what this renderer/device can consume, so it belongs to host initialization—not font loading and not the frame loop. A font contributes a portable policy body, but the renderer assembles that body into its own policy program. If the renderer supports several technique programs, it installs them together in the same host policy before opening sessions that use them.

The application update loop: author, measure, then render

Late binding keeps construction and scene edits cheap: creating or editing a Text does not shape. The call that needs an answer performs the work. For an attached Three object, layout() runs the paragraph-scoped measurement query immediately; a later normal Three render traversal publishes the renderer plan. The measurement candidate is retained by the same batch/session, so the first render does not need a second measurement query.

Attached Text

Use text.layout() after adding the text to any parent. Parenthood provides ownership; the parent need not already be in a rendered scene. The result describes local layout and commitState() remains pending until render traversal accepts the full plan.

Detached measurement

Use new Paragraph(...).layout(constraints) when no scene object or batch owner exists. A completely parentless Text.layout() throws at that call boundary instead of inventing a hidden renderer lifetime.

What late binding preserves: construction, edits, and graph reparenting remain inert until an answer is requested. Measurement can run before frame one because it needs only local paragraph state and batch ownership; transforms remain renderer-owned and are consumed only when the full render plan is published.

Desired layout and accepted rendering are separate answers

layout() always measures the current desired paragraph. commitState() reports whether that desired revision has entered an accepted render plan. This distinction is visible when a caller deliberately chooses a fixed glyph budget: content beyond the budget is valid text, so measurement answers for it, while the renderer keeps the last complete draw until the desired content fits.

const label = new Text({
  font,
  text: 'abc',
  capacity: { size: 8, policy: 'fixed' },
});
scene.add(label);
renderer.render(scene, camera);

label.set({ text: 'abcdefghijklmnopqrstuvwxyz' });
renderer.render(scene, camera); // controlled refusal: the scene traversal continues

label.layout().glyphCount;      // 26: current desired local layout
label.commitState();            // { status: 'pending' }
label.error;                    // undefined: the fixed budget is not an engine defect
// The previously accepted three-glyph draw remains visible.

label.set({ text: 'ab' });
renderer.render(scene, camera);
label.commitState().status;     // 'committed': recovery is recomputed, never latched

The fixed budget is checked from the desired text-length upper bound before shaping the render candidate. Malformed authored inputs still throw at new Text(...) or text.set(...); the budget path does not turn bad schema or plan data into a runtime fallback.

Capability objects contain capabilities, not IDs. compileRenderPolicy() assigns their ABI identities by descriptor order; a one-profile frame omits capability selection. Authored module-lifetime policy and buffer constants use id(kind, stableName). Runtime-created binding, stack, and session handles use host.id(kind, stableName). The string exists only at ID construction; both helpers return a branded number, register its provenance, and reject a hash collision. Wire records and lookups carry the number. A renderer may cache the one string attribute name that maps a numeric policy-buffer ID to its shader input, but it does not concatenate protocol identities per frame.

2. Compile the loaded font and realize resources

const compiled = compileRasterFont(font, host.wireIdentities);
if (!compiled) throw new TypeError(`no portable program for ${font.technique.id}`);

const INITIAL_RESOURCE_GENERATION = 1;
const resources = [];
for (const [name, keys] of compiled.declaredResources) {
  for (const key of keys) {
    const resource = compiled.resources.get(key);
    if (!resource) throw new Error(`compiled font omitted ${name}`);
    resources.push({
      id: host.wireIdentities.resourceId(key),
      generation: INITIAL_RESOURCE_GENERATION,
      name,
      resource,
    });
  }
}

const bindingId = host.id('font-binding', `my-renderer/${font.font.handle}`);
const stackId = host.id('font-stack', 'my-renderer/body');
const pendingResources = device.prepareResources(resources);
try {
  host.registerFontBinding(bindingId, font.font.handle, compiled.binding);
  try {
    pendingResources.commit();
  } catch (commitError) {
    try {
      host.disposeFontBinding(bindingId);
    } catch (rollbackError) {
      throw new AggregateError([commitError, rollbackError],
        'resource commit and binding rollback failed', { cause: commitError });
    }
    throw commitError;
  }
} catch (error) {
  pendingResources.discard();
  throw error;
}
host.registerFontStack(stackId, [bindingId]);

compileRasterFont() is cached cold work per LoadedFont. Its declaredResources map answers “which concrete keys satisfy each schema role?” and its resources map answers “what portable payload does each key name?” A Bitmap font can therefore list several atlas-page keys for one many role; a Slug font can list several page keys whose values are fixed-member groups. “Key” is only the stable identity joining the binding, plan, and renderer cache—it is not another object the user creates.

prepareResources() belongs only to glyph-example-renderer. It checks each id/name/generation and payload against the selected shader schema, creates TypeGPU vertex and index buffers for the supplied geometry, and returns a one-shot commit(). Validation cannot partially mutate the live device. If another candidate commits first, the generation guard rejects the older candidate and destroys its unowned GPU objects.

Three does the equivalent work without this method name. ThreeTextEngineCoordinator calls compileRasterFont(), validates each portable payload and Three shader/material registration, and retains the resource-to-program association. When a publication arrives, ThreeTextRenderPlanExecutor prepares textures, geometry, buffers, materials, draws, and retirements in candidate maps, then commits the complete publication. The portable contract requires validation and realization; it does not prescribe a renderer API named prepareResources().

The concrete Three realization

Three deliberately has two layers of storage. The coordinator retains immutable portable payloads by wire reference. The plan executor owns separate caches of Three GPU-facing objects. A draw's resource record contains the reference that joins those layers.

The real implementation performs this inside ThreeTextRenderPlanExecutor. Bitmap and MSDF become cached THREE.DataArrayTexture objects. A Slug resource group becomes three cached THREE.DataTexture objects. Supplied geometry becomes a THREE.InstancedBufferGeometry whose attributes, index, topology conversion, and draw range come from the portable geometry payload. Synthetic quads use Three's shared unit-quad construction instead.

// Supplied geometry follows the same payload-to-renderer-object rule.

  const accessor = payload.accessors[attribute.accessor];

All of those objects are built against candidate maps first. Only after resources, policy buffers, geometry, materials, transforms, draws, and retirements validate together does Three replace its live maps. If preparation throws, newly created candidate objects are disposed and the previously accepted frame remains intact. Retirement later removes and disposes objects no longer referenced by an accepted plan.

Font disposal follows those owners. Calling font.dispose() prevents new use and requests retirement, but it does not free bytes that a live Text or registered stack still addresses. Three retains the exact binding used by each stack. The final stack release disposes that Wasm binding first and only then releases its decoded renderer resources; runtime teardown force-closes any remaining leases. A Wasm FONT_IN_USE response preserves JavaScript ownership so the same disposal can be retried safely.

readDrawList() is example code built from TextEngineRenderPlanView and the core record readers. A synchronous same-thread renderer such as Three reads the borrowed A/B Wasm publication immediately, before any intervening call that can grow the same shaper's memory. The asynchronous example calls copyPublication() once. A worker receiver treats transferred bytes as untrusted and calls bindBytes(); ownership provenance is deliberately realm-local. That current primitive validates plan bytes only—a renderer must separately transport referenced payloads. The target migration above makes that missing resource manifest explicit. Submission validates generations, patches, primitive spans, named bindings, geometry, program identity, draw order, and retirements into candidate state. Only a successful commit advances renderer fences.

Define the portable schema and policy body

import { defineTechniqueSchema, f32, techniqueProgram } from '@pmndrs/glyph/core';

export const schema = defineTechniqueSchema({
  technique: technique.id,
  scope: 'glyph',
  binding: { f32: ['inset', 'red', 'green', 'blue', 'alpha'] },

    size:   { id: id('buffer', 'studio.example/size'), scalar: 'f32', lanes: ['widthX', 'heightY'] },
    color:  { id: id('buffer', 'studio.example/color'), scalar: 'f32', lanes: ['red', 'green', 'blue', 'alpha'] },
  },
  resources: {
    glyphGeometry: {
      kind: 'geometry',
      attributes: [
        { semantic: 'position', componentType: 'f32', components: 3 },
        { semantic: 'uv', componentType: 'f32', components: 2 },
      ],
    },
  },
  render: { resource: 'glyphGeometry', geometry: suppliedIndexedQuad },
  glyphOrigin: { buffer: 'origin' },

const GLYPH_EXAMPLE_PROGRAM_VARIANT = 0;

export const definition = {
  technique,
  schema,
  programVariant: GLYPH_EXAMPLE_PROGRAM_VARIANT,
  policyBody(system) {
    const p = techniqueProgram(schema, { system });
    const { inlineOrigin, blockOrigin, fontSize, color } = p.semantics;
    const { inset, red, green, blue, alpha } = p.binding;
    const insetPx = f32.mul(inset, fontSize);
    return p.compile({
      origin: [f32.add(inlineOrigin, insetPx), f32.sub(blockOrigin, insetPx)],
      size: [f32.sub(f32.mul(fontSize, f32.const(0.65)), f32.mul(insetPx, f32.const(2))),
             f32.sub(fontSize, f32.mul(insetPx, f32.const(2)))],
      color: [f32.mul(color.red, red), f32.mul(color.green, green),
              f32.mul(color.blue, blue), f32.mul(color.alpha, alpha)],
    });
  },
  // compileFont follows in step 2.
};

Drive a retained frame and submit it

Publications are borrowed Wasm views. Track engine acceptance separately from device acceptance so rejection cannot acknowledge GPU work that never committed.

let engineRevision = 0;
let consumedPlanRevision = 0;
let acceptedPublicationGeneration = 0;

const request = compileTextEngineFrameUpdate({
  ...frame,
  expectedEngineRevision: engineRevision,
  consumedPlanRevision,
  acknowledgedPublicationGeneration: acceptedPublicationGeneration,
});
const borrowed = session.update(request);
engineRevision = borrowed.engineRevision; // Wasm accepted the authored update.
const owned = session.copyPublication(borrowed); // required before this async boundary
const drawList = readDrawList(owned);

const pending = device.prepareSubmission(drawList); // validate everything
await pending.commit();                            // validate GPU work, then publish once
consumedPlanRevision = drawList.planRevision;
acceptedPublicationGeneration = drawList.publicationGeneration;

if (drawList.draws.length === 0) {
  throw new Error('Acceptance requires a non-empty draw list');
}

If device preparation or commit throws, do not advance the last two fences. The renderer keeps its already accepted scene; the next update is compiled from the current engine revision and the last plan revision the device actually accepted. No failed or older candidate is substituted. Do not use session.acknowledgedGeneration for this transactional fence.

Using the same technique from Three

Three remains a fully external consumer of the portable contract. The application selects the TSL variant and registers a Three-owned material realization. No Three file lives in the raster package root, and the TSL subpath does not auto-register.

import { registerThreeRasterPlanProgram, threePolicyAbi } from '@pmndrs/glyph/three';
import { planProgram } from 'my-technique';
import { tslShader, tslVariant } from 'my-technique/tsl';

registerThreeRasterPlanProgram({
  technique: planProgram.technique,
  schema: planProgram.schema,
  variant: {
    id: 'tsl',
    language: 'tsl',
    buffers: tslVariant.buffers,
    resources: tslVariant.resources,
    outputs: tslVariant.outputs,
    geometry: tslVariant.geometry,
    createMaterial(context) {
      const origin = context.namedBuffers.get('origin');
      const size = context.namedBuffers.get('size');
      const color = context.namedBuffers.get('color');
      if (origin?.scalarType !== threePolicyAbi.scalarTypes.f32 ||
          origin.vectorWidth !== 2 || size?.vectorWidth !== 2 || color?.vectorWidth !== 4) {
        throw new TypeError('Incompatible named buffers');
      }
      const shader = tslShader({
        origin: storage(origin.attribute, 'vec2', origin.attribute.count).element(context.instance),
        size: storage(size.attribute, 'vec2', size.attribute.count).element(context.instance),
        color: storage(color.attribute, 'vec4', color.attribute.count).element(context.instance),
        quadPosition: positionLocal,
        quadUv: uv(),
        transformPosition: context.transformPosition,
      });
      const material = new THREE.MeshBasicNodeMaterial({ transparent: true });
      material.positionNode = shader.position;
      material.colorNode = shader.color;
      material.opacityNode = shader.opacity;
      return material;
    },
  },
});

Why a renderer registration still exists: it selects a renderer-language implementation and constructs renderer-owned material/pipeline objects. It does not reinterpret technique policy. Named metadata is the glue; the portable plan remains the source of record spans, buffer/resource identities, geometry, and draws.

Geometry choices

Synthetic quad

The plan declares no geometry resource. The renderer generates one unit quad per draw and uses recordCount as instance count.

Supplied geometry

The technique retains immutable bytes, views, accessors, vertex semantics, optional indices, topology, and draw range. Geometry never declares instance count; the plan still owns it.

const geometry = {
  kind: 'geometry',
  topology: 'triangle-list',
  bytes, // GLB-style immutable vertex/index storage
  views: [{ offset: 0, length: 80 }, { offset: 80, length: 12 }],
  accessors: [
    { componentType: 'f32', components: 3, view: 0, offset: 0,  count: 4 },
    { componentType: 'f32', components: 2, view: 0, offset: 48, count: 4 },
    { componentType: 'u16', components: 1, view: 1, offset: 0,  count: 6 },
  ],
  attributes: [
    { semantic: 'position', accessor: 0 },
    { semantic: 'uv', accessor: 1 },
  ],
  indices: { accessor: 2 },
};

// Three checks its reserved widths twice: declarations when the renderer
// variant registers, and actual payload attributes when the font is bound.
compiler.retain('glyphGeometry', data.geometryResource, geometry);

1 · PrepareClone or journal candidate metadata; realize new resources and draws off to the side.
→
2 · ValidateAuthenticate generations, identities, shapes, spans, geometry, named bindings, and all references.
→
3 · CommitApply validated patches, swap owned maps/draws, then dispose retired objects.

Renderer-relevant invalidation follows a rejected candidateFrame coordinatorRequests a fresh checkpoint from the last device-consumed plan revision
Retired-object cleanup throws after commitCommit cleanupFirst cleanup failure is reported; accepted state remains current and future frames continue

There is no stale-material restoration, unchanged-frame retry, or permanent renderer latch. Correctness comes from “live state is untouched until the candidate is valid,” not from rolling back to an older picture after partial mutation.
