pmndrs/glyph · durable implementation report

From immutable font to accepted GPU draw

This is the current renderer-neutral contract. A Glyph engine owns shaping memory, a backend owns one renderer integration, a retained plan owns desired text and one acceptance frontier, and a plan target joins that core hierarchy to a renderer device or context.

Complete application and rendering flow

Mutation is lazy. update() changes desired state. layout() and glyphs() synchronously pay shaping/lookup cost only on a cache miss. publish() performs the retained batch update and does not advance its accepted revision until the target commits.

Ownership and cardinality

Object Created by Owns Use more than one when
Font loadFont() Immutable artifact backing and decoded portable raster data Source, face, subset, or raster variant differs
GlyphEngine createGlyphEngine() One Wasm domain, engine-local shaping registrations, all child backends Worker/memory/teardown isolation is required
GlyphBackend glyphEngine.createBackend() One integration’s policy, bindings, identities, and retained plans Renderer policy, physical device domain, or integration lifetime differs
RetainedPlan backend.createRetainedPlan() Desired text, target, capacity budget, and one acceptance frontier Scene, viewport, target, worker, or independent commit boundary differs
RetainedText retainedPlan.createText() One desired text state inside the retained plan Application text instances differ

A Glyph engine permanently owns its backends; a disposed engine disposes them first. A backend cannot rebind. Fonts are different: they are immutable application assets and may bind into several engines or backends. Bindings are backend-local, counted leases.

Complete custom-renderer setup

1

Load a font before creating renderer state

import { createFontStack, loadFont } from '@pmndrs/glyph';
import { glyphExample } from '@pmndrs/glyph-example-raster';

const font = await loadFont({
  input: { baked: '/fonts/Inter.font.glb' },
  raster: { technique: glyphExample, options: { paletteSeed: 7 } },
});
const fontStack = createFontStack(font);

Loading validates immutable CPU data. It does not create a Glyph engine or GPU object.

2

Create a Glyph engine, backend, and policy

import { createGlyphEngine } from '@pmndrs/glyph/core';

const glyphEngine = await createGlyphEngine();
const backend = glyphEngine.createBackend({
  integration: 'studio.webgpu-text',
});
const policy = backend.installPolicy(rendererPolicy);

The renderer builds rendererPolicy from its capabilities and system lanes plus each technique’s portable policy program. Capability ordinals are automatic; stable protocol IDs are branded numeric hashes, never user-authored numbers.

3

Bind the stack and create one plan target

const stack = backend.bindFontStack(fontStack);

const target = {
  delivery: 'borrowed',
  accept(candidate, signal) {
    signal.throwIfAborted();
    const transaction = device.beginCandidate(candidate.planRevision);
    try {
      decodeAndStage(candidate, transaction);
      transaction.commit();
      return { accepted: true };
    } catch (error) {
      transaction.discard();
      return { accepted: false, error };
    }
  },
  dispose() {
    device.disposeTarget();
  },
} satisfies PlanTarget;

The default path borrows Wasm A/B memory only during synchronous accept(). The CPU copies needed bytes into renderer-owned GPU/upload storage before returning; GPU execution may continue afterward.

4

Create a retained plan and text

const retainedPlan = backend.createRetainedPlan({
  policy,
  capabilitySet,
  target: () => target,
  limits,
  requestCapacity: 64 * 1024,
  resultCapacity: 256 * 1024,
  textCapacity: 16 * 1024,
});

const title = retainedPlan.createText({
  font: stack,
  text: 'Hello',
  style: { fontSize: 48 },
  contentBox: { width: { mode: 'at-most', size: 800 } },
});
5

Update, query on demand, then publish

title.update({ text: 'Hello, Glyph' });

const metrics = title.layout();
const positioned = title.glyphs();

const result = retainedPlan.publish({ semanticViews: 'measurement' });
if (!result.accepted) reportRendererError(result.error);

layout() returns aggregate metrics. glyphs() returns caller-owned positioned columns and ink boxes. Both may synchronously incur lookup work on a cache miss; glyphs() also copies its returned columns. Their canonical constraint caches are bounded three-entry LRUs. Neither publishes a draw.

6

Dispose from leaf to root

title.dispose();
retainedPlan.dispose();
stack.dispose();
policy.dispose();
backend.dispose();
glyphEngine.dispose();
font.dispose();

Parent disposal is a safety net and cascades through children. Explicit leaf disposal makes resource release timing predictable.

What the renderer does with resources

Plan table Renderer action
resources Acquire a counted portable payload and create/update/retain its texture, buffer, geometry, or group realization.
buffers Declare renderer storage shape and map semantic policy-buffer IDs to shader bindings.
patches Allocate/resize, write, fill, copy, or retire exact byte ranges.
primitives Map record spans to technique, resource generation, geometry meaning, and logical order.
draws Submit ordered program/material/transform spans.
retirements Release exact resource or buffer generations after the acknowledged fence. 
const resources = candidate.plan.table('resources');
for (let i = 0; i < resources.count; i += 1) {
  const record = readTextEngineResource(candidate.plan, resources, i);
  if (record.referenceId === 0) throw new TypeError('missing payload reference');

  const lease = candidate.acquirePayload(record.referenceId);
  transaction.realize(record.id, record.generation, {
    name: lease.resourceName,
    payload: lease.payload,
    release: () => lease.dispose(),
  });
}

The map is a device cache keyed by branded numeric (id, generation), not the endpoint. The cached value is the physical texture/buffer/geometry plus its payload lease and destruction logic. Acceptance swaps a complete candidate cache into live state. Rejection destroys only provisional objects; it never restores stale content. A resource retirement removes the accepted plan reference; when no accepted reference remains, the target disposes the portable payload lease and asks the device to destroy its physical realization.

AsyncPlanTarget exists only when CPU consumption crosses an asynchronous boundary such as a Worker. It receives one owned transferable copy and must return the same buffer identity when done. The normal same-thread GPU path uses PlanTarget and makes no extra plan copy. 

// The target captured PlanTargetControl when the retained plan was created.
oldDevice.dispose();
const nextDevice = new TypeGpuExampleRendererDevice({ device: nextGpuDevice, width, height });
engine.replaceDevice(nextDevice);

// No authored mutation is required: this publication is a complete checkpoint.

Device replacement clears only renderer-owned physical state. The immutable font and portable payload remain reusable; the checkpoint re-declares current resources, buffers, primitives, and draws so the new device can rebuild deterministically.

What a portable raster technique provides

Raster decoder

Validates its GLB extension and returns immutable typed data plus stable resource identities.

Technique schema

Names policy buffers, lanes, retained resources, geometry meaning, and shader-facing semantics.

Policy-body factory

Computes per-glyph values from semantic inputs while the renderer supplies system lanes and capabilities.

Font compiler

Runs on first backend binding, producing binding bytes and constrained portable payloads—not per frame or glyph.

Baker

Produces the authenticated artifact. Discovery already follows runtimeBaker; no renderer dependency is involved.

Optional shader subpaths

TypeGPU, TSL, WGSL, or GLSL variants may ship explicitly. Core imports none of them; an engine selects or authors one. 

export const plan = {
  technique,
  schema,
  programVariant: 0,
  policyBody(system) {
    const p = techniqueProgram(schema, { system });
    return p.compile({
      origin: [
        f32.add(p.semantics.inlineOrigin, p.binding.inset),
        f32.sub(p.semantics.blockOrigin, p.binding.inset),
      ],
      color: [
        f32.mul(p.semantics.color.red, p.binding.red),
        f32.mul(p.semantics.color.green, p.binding.green),
        f32.mul(p.semantics.color.blue, p.binding.blue),
        f32.mul(p.semantics.color.alpha, p.binding.alpha),
      ],
    });
  },
  compileFont(compiler) {
    compiler.retain('glyphGeometry', compiler.font.data.resource, geometry);
    return compiler.compile({
      strikes: [0],
      resource: () => compiler.font.data.resource,
      f32: { inset: row => compiler.font.data.insets[row] },
    });
  },
} satisfies RasterPlanProgram;

The main technique import performs only renderer-neutral plan registration. Shader variants remain explicit subpath imports. Three, TypeGPU, and another engine all consume the same schema, payloads, and plan records without technique-specific core adapters.

Valid renderer topologies

One WebGL canvas

Usually one Glyph engine → one backend → one or more retained plans → one WebGL context. A second canvas means another non-sharing WebGL context and normally another backend/device cache.

Two WebGPU canvases

One GPUDevice may configure both canvas contexts. One backend may serve retained plans for both when policy and device cache domain are shared; each plan keeps its own target and acceptance frontier.

Onscreen + Offscreen WebGPU

A shared device can serve both contexts. Use separate retained plans; use an async target only where plan consumption crosses the Worker boundary.

Onscreen + Offscreen WebGL

The contexts do not share GPU objects. Treat them as separate device/cache domains, generally separate backends, and optionally separate Glyph engines if worker isolation is desired.

Sync and async together

Yes. Separate retained plans under one backend may use borrowed synchronous and owned asynchronous targets. The engine-wide borrow gate prevents reentry while a synchronous candidate is active.

Several Glyph engines

Valid for independent workers or teardown domains. Immutable fonts may bind into each; shaping registrations and Wasm memory are intentionally not shared across engines.
