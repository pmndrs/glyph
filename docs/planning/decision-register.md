| D-273 | The retained per-glyph position lane is addressed as DISPLACEMENT FROM REST, never as a coordinate. The three shipping techniques store three different things in the lane an animation writes: MSDF and Slug pack the ink box's top-left corner, and Bitmap stores the glyph origin plus the baked strike's raster bearing -- a value no layout number can reconstruct, because the strike quantizes it. A renderer that reads or writes the lane as a position is therefore reading a number whose meaning depends on the technique, which is what let the previous snapshot return one array holding two coordinate spaces. What every technique does share is that the plan's own value for a glyph at rest corresponds to the layout's shaped origin for that glyph, so `value - rest` is in glyph-origin space for all of them and `rest + (wanted - shaped)` writes back. The executor therefore needs no per-technique declaration at all, and a technique added later is animatable without describing its packing. A schema-declared coordinate space was built first and rejected: it could name the ink-box case but not Bitmap's, so it would have been a second source of truth that was already wrong for one of the three techniques it covered. | Accepted |
| D-274 | Per-glyph extents come from the engine that positions the glyphs, not from a second decode of the baked font. `positioning.rs` already computes each glyph's ink box from the font's extents table to build its render record and discards it for the semantic view; the shaped advance is likewise in scope and dropped. Both are carried into `SemanticGlyph` and out through the semantic record, together with each line's ascent and the union ink box of the glyphs on it. The alternative -- decoding the baked `glyphExtents` table on the TypeScript side against `glyphIds`, `glyphFontSizes`, `x`, and `y` -- reproduces `positioning.rs`'s arithmetic exactly, including its f64-then-narrow ordering, and is a shadow implementation of a rule the engine owns. Reading them out of the technique-specific packed plan buffers is the same internal-representation leak the audit exists to close, and covers only glyphs that render, so a space would have no extents at all. | Accepted |
| D-275 | Two extents ship under names that cannot be confused, because they answer different questions and neither is a better version of the other. `contentWidth`/`contentHeight` and `GlyphRun.bounds` are ADVANCE extents: the space the text claims, which is the correct number for a flex or grid host because CSS box layout is advance-based. `inkBounds` and `GlyphRun.ink` are INK extents: the union of the outlines, which is the correct number for centring something visually, because italics, accents, and swashes overhang their advances. Publishing one and calling it the extent makes the other silently wrong at every call site that needed it. troika ships `blockBounds` beside `visibleBounds` and the DOM ships `actualBoundingBox*` beside `width` for the same reason. Ink is derived from positioned glyphs, so a query that skipped positioning reports `inkBounds: undefined` under an explicit engine flag rather than substituting the advance box -- absence is stated, never filled in, and a paragraph that positioned zero glyphs reports a real empty box rather than absence. | Accepted |
| D-276 | Animation addresses what a reader sees move -- a glyph, a word, a line -- through one snapshot that is internally consistent by construction, and the cycle is stated: SNAPSHOT, MANIPULATE, RESTORE. `GlyphPlacements` names its one coordinate space in the type, owns the identity that survives reflow, reports every glyph it could not read, and applies totally or returns exactly what it did not reach. The identity is the package's, not the engine's: `glyphStableIds` identifies a record within one committed layout, which is what the GPU write needs and what a reflow discards, so `GlyphKey` is font, glyph id, cluster, and occurrence -- durable across a change that moves glyphs, explicitly not across one that reshapes them. That statement is the point; the previous API's one real consumer had to discover it and rebuild the key itself over six public arrays it also had to hand-check for equal length. `restoreGlyphs` is a step of the cycle rather than a call learned by watching an override outlive the motion that set it. The retained-GPU-buffer write path is kept unchanged in capability: patching without a reshape or a CPU re-upload is what makes the API worth having. | Accepted |
| D-277 | A paragraph and an inline run are different kinds of thing and carry different props. `Text` is a box and a Three `Object3D`; `TextSpan` is never mounted -- the tree collapses into one string and one span array before any object exists -- so it accepts exactly the five properties the flattener reads and names every box-level property as `never`. A transform, a capacity, an error handler, or a `ref` on a run is now a type error rather than a value the compiler accepts and the flattener discards, and a `ref` that could never fire cannot be written. The box-only key set is derived from the outer props type rather than listed, so a property added to the paragraph cannot quietly become a silently-discarded inline one. Flutter separates `RichText` from `TextSpan` on the same line. | Accepted |
| D-272 | A paragraph publishes what it has committed as a value. `commitState()` distinguishes unbound from pending from committed from failed, because they need different responses: an unparented paragraph will never commit on its own, while a pending one commits on the next world-matrix update. | D-282 | `Text.layout()` measures current desired local layout after scene attachment but before the first rendered frame. | D-283 | Positioned layout answers are safe values, not mutable views into a cache. | D-284 | Core ownership follows actual lifetimes. A `TextEngineHost` claims policies, font bindings, font stacks, and sessions inside one Wasm instance and rejects another host's references before invalidating the last accepted publication; a successful registration retains the numeric ID's provenance until that registration or its host is disposed. A `TextEngineSession` owns one hot paragraph batch, its revisions, physical plan storage, publications, and engine resource residency—not a scene, GPU device, or render pass. Policies and stacks named by committed session state report `registrationInUse`, failed disposal remains retryable, and owned publication copies carry package-private runtime provenance that visible-field copies cannot forge. Core therefore gains no scene/device API and no implicit standalone batch. Three's session-local GPU texture duplication and compatible font-stack batching remain renderer implementation work that must preserve paragraph and visual order. | Accepted |
| D-285 | Wasm A/B publication and renderer acceptance are separate transactions. A synchronous renderer consumes the borrowed current slot before another session call; a deferred same-realm consumer calls `copyPublication()` once. A worker sender also copies first, then transfers the self-owned buffer as untrusted boundary data and the receiver calls `TextEngineRenderPlanView.bindBytes()`; the package-private `OwnedTextEnginePublication` runtime witness is realm-local and is not claimed to survive structured cloning. `bindBytes()` transactionally rejects an ABI mismatch, non-success status, and malformed render or semantic table framing before replacing a reader's prior valid publication. Copying bytes does not acknowledge device acceptance. If Three realization throws, it keeps the last accepted plan revision and publication generation, discards renderer-owned candidates, preserves the error, and does not retry unchanged frames. Semantic measurement cannot advance that fence, while positioned inspection and placement queries return `undefined` until explicit renderer-relevant invalidation successfully realizes a checkpoint. Three's plan target does not own the GPU device; a device-owning renderer explicitly requests the same checkpoint only after rebuilding its lost-device resource pool. A malformed emitted plan is an engine defect and never enters recovery. The forced material-failure fixture proves unchanged traversal and inspection make no engine crossing, measurement leaves acceptance unchanged, and explicit invalidation makes exactly one. Fixed-capacity candidate rejection releases every provisional stack and material lease before retaining the last accepted draw. | Accepted; supersedes D-279 retry clause |
| D-286 | Portable fonts are immutable root-package `Font<Technique>` assets, not children of a Wasm runtime. Root `loadFont()` owns one canonical GLB backing and internal views; an optional application-owned `FontLibrary` has explicit cache leases, while the top-level loader retains only in-flight coalescing. Existing `FontInput`, `FontToken`, and `defineFont` remain the static bake-discovery contract, with explicit source-versus-baked byte discriminants. The root stays the canonical barrel for portable application/provider vocabulary; runtime/host/session/policy/plan names live only in `/core`, and integrations re-export root names only when their own signatures use them. Each runtime privately deduplicates one Wasm shaping registration per backing but releases it at the final host-binding lease, and each renderer pools only by package-authenticated content-derived payload identity plus device/variant—never a host-scoped wire ID. `createTextRuntime`, `TextRuntime`, and `TextEngineHost` are integrator-only `/core` names; a runtime creates and owns hosts through `runtime.createTextEngineHost()`, runtime disposal cascades hosts and sessions, hosts never rebind, and fonts may outlive and bind to another runtime. `host.bindFont()` is idempotent in underlying state but returns independent leases, while convenience APIs hide dynamic numeric IDs; core exposes no vague `realizeFont()` operation. Every render session binds one complete host-owned policy descriptor, one descriptor-owned capability set, validated limits, and exactly one disposable `PlanTarget` or `AsyncPlanTarget`; it owns retained text handles and the only acceptance cursor, gives its target factory one opaque checkpoint control, and exposes no raw caller-authored IDs, revisions, masks, or acknowledgment path. The bounded transfer pool reuses only returned allocations of exactly the same byte length and evicts least-recently-returned buffers to remain within byte/count bounds. GPU execution completing asynchronously does not make renderer acceptance asynchronous. The runtime gates borrowed Wasm memory across all hosts; device pools fan loss out to every attached session, with each session independently blocked only until its own checkpoint commits; lockstep targets prepare all members before any commit. Canvas, GPU, Three.js, and TypeGPU remain renderer-owned. Explicit idempotent disposal/refcounts determine correctness; finalizers are rejected because an unbound unreachable Font and its ordinary JS backing are already collectible, while bound assets and explicit library caches have deterministic owners. | Accepted; implemented |
