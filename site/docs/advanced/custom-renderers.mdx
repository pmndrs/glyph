<Intro>
  three.js is one adapter. `@pmndrs/glyph/core` exposes the contract it is built on: a `GlyphConfig` that names how
  plans are encoded, decoded into stable object bindings, resolved into resources, and handed to a renderer. The
  example renderer in the repository implements the same contract against a raw device oracle.
</Intro>

```ts
import type { GlyphConfig } from '@pmndrs/glyph/core';
import { defaultDecoder } from '@pmndrs/glyph/core';

const MyConfig: GlyphConfig<MyHandle, MyBindings, MyPrepared, MyResource> = {
  encode: () => myCodec,
  decode: defaultDecoder,
  resolve: (payload) => resolveToMyResource(payload),
  renderer: myRenderer,
  createHandle: (domain) => new MyHandle(domain),
};

const mine = glyph.handle('mine', MyConfig);
```

## The hooks

| Hook | Job |
| --- | --- |
| `encode` | supply the `Codec`; the engine defines the canonical typed command buffer it produces |
| `decode` | turn that buffer into a `BorrowedBoundCommandBuffer` of stable object bindings; wrap or replace `defaultDecoder` type-safely |
| `resolve` | turn an immutable portable payload into a boundary-owned disposable lease, synchronously |
| `renderer` | `prepare` / `commit` / `discard` over the bound buffer's phases |
| `createHandle` | the adapter's handle factory |

## Phases

```
resources → buffers → patches → primitives → draws → retirements
```

{/* prose: bindings are stable objects — resources from `resolve`, buffer bindings, transform/material bindings,
primitive objects — never numeric plan ids; those stay private to each adapter's binder. `GlyphCommandBufferBinder`
and `applyGlyphPublication()` own decode → prepare → commit/discard and candidate resource cleanup for you. */}

## When you need a device

{/* prose: three's resolver creates three.js objects with no renderer, scene, canvas, or `GPUDevice`; a raw WebGPU
adapter needs a device at its first `device.create*`, captured in the config closure; a canvas only when it presents.
No universal host-context or public session concept. */}
