## The header

| Field | Meaning |
| --- | --- |
| `abiVersion`, `byteLength`, `status` | checked first, in that order; anything else is read only after they pass |
| `flags` | bit 1 is `checkpoint`: this plan replaces every buffer and resource |
| `plannerId` | which root's planner answered |
| `engineRevision`, `planRevision` | both advance by one per accepted update |
| `requiredBaseRevision` | the plan revision this one patches; a checkpoint patches nothing |
| `publicationGeneration` | a fence the renderer acknowledges on its next request |
| `outputSlot` | which of the two output slots this answer lives in |
| `requestCapacity`, `resultCapacity`, `requiredRequestCapacity`, `requiredResultCapacity` | the arenas as reserved, and what this frame would have needed |
| `codecHandle`, `capabilitySet`, `codecFingerprint` (two words) | the codec this plan was compiled against |
| `…Offset`, `…Count` × 8 | where each table starts and how many records it holds; a count of 0 means an offset of 0 |
| `faultParagraphId`, `faultStyleId` | which paragraph or style a rejection blames; 0 means none |

## The tables

| Table | Stride | One record per | Fields that matter |
| --- | --- | --- | --- |
| `resources` | 40 | `(resourceId, generation)` a glyph draw uses | `techniqueId`, `resourceKind`, `action` (create 1, update 2, retain 3), `referenceId` |
| `buffers` | 36 | program buffer per storage batch | `id`, `generation`, `programId`, `codecBufferId` (`0xffff` is the order buffer), `scalarType`, `vectorWidth`, `strategy`, `liveRecords`, `capacityRecords`, `byteLength`, `orderBufferId` |
| `patches` | 36 | byte edit to one buffer | `opcode` (allocate-or-resize 1, write 2, fill 3, copy 4, retire 5), `bufferId`, `bufferGeneration`, `destinationOffset`, `byteLength`, `payloadStart`, `sourceBufferId`, `sourceOffset`, `fillValue` |
| `primitives` | 64 | draw span | `id` (the first stable glyph id), `kind` (glyph 1, decoration 2), `techniqueId`, `resourceId`, `programId`, `programVariant`, `bufferId`, `recordIndex`, `recordCount`, `logicalOrder`, `clipId`, `semanticId`, extents |
| `draws` | 64 | draw span | `programId`, `programVariant`, `materialId`, `clipId`, `depthKey`, `transformId`, `primitiveStart`/`Count`, `bufferStart`/`Count`, `resourceStart`/`Count`, `orderToken`, `indirectBufferId`, `indirectOffset` |
| `retirements` | 24 | thing to drop | `kind` (resource 1, buffer 2, slot range 3, output bytes 4), `id`, `generation`, `afterPublicationGeneration`, `byteOffset`, `byteLength` |

## How draws are batched

```
storage batch key = technique · programVariant · programId · resource(id, generation, kind)   [+ material · clip · depth per storageKeyMask]
draw span ends when: batch differs, slots are not contiguous, a drawKeyMask key differs (material, transform), or 65 535 records
independent compositing: spans form per batch without the contiguity rule; draws sort by (depthKey, orderToken)
```

{/*

  program variant, program, and resource — plus material, clip, or depth only when the program's `storageKeyMask`
  includes that bit; a batch is a set of physical buffers, so a new batch is a new buffer generation.

## Revisions, checkpoints, and expiry

| Data | You may |
| --- | --- |
| `patch` payloads | read them during `accept`; copy anything you keep |
| draw, primitive, buffer, resource scalars | read them during `accept` |
| `PortableResource` payloads | retain — they come from the compiled font, not from the publication |
| buffer and resource identities | rely on: interned per `(id, generation)`, stable across frames |

{/*
write
- Question: when is a plan a checkpoint, and when does my borrow die?
- Paragraph 1: each request carries the renderer's `expectedEngineRevision`, `consumedPlanRevision`, and
  `acknowledgedPublicationGeneration`; the engine rejects a request whose engine revision is stale, whose consumed
  revision is ahead of it, or whose acknowledgement is not monotonic; nothing about a bad request reaches a
  renderer.
- Paragraph 2: a plan is a checkpoint when the renderer has never consumed one or when its consumed revision is not
  the current one — every buffer gets `allocate-or-resize` and a full rewrite, every resource is `create`;
  otherwise patches cover changed ranges only. A renderer can force one by asking its target control for a
  checkpoint, which resets the consumed revision it sends.
- Paragraph 3: acknowledging a generation releases the stable slots quarantined behind it; the planner records the
  accepted generation and echoes it on the next frame; a rejected accept leaves every revision untouched, which is
  how a bad frame never corrupts the next one.
- Paragraph 4: the borrow expires when any of these happens: the engine answers another call (its epoch advances),
  Wasm memory grows (the old buffer is detached), or the transport is disposed; the planner expires the lease in a
  `finally` right after `accept` returns, and every reader call after that throws.
- Point at: the table — the one thing you may keep is a `PortableResource`, because it never lived in the
  publication.
- Avoid: the A/B slot mechanics.
- Shape: four short paragraphs, then the table.

## Consuming one

```
source   = projector.source(candidate)        typed views over the six tables
update   = projector.project(source)          resolve resources, buffers, materials, transforms to your bindings
prepared = renderer.decode(update)            stage: allocate, read, copy — mutate nothing the host sees
prepared.commit()                             apply, then settle(committed: true)
on throw: prepared.discard()                  clean up, then settle(committed: false)
```

```ts
import type { AnyGlyphBindings, CommandBufferView, GlyphRenderer, PreparedRendererCommit } from '@pmndrs/glyph';

interface Staged {
  readonly writes: readonly { readonly buffer: object; readonly offset: number; readonly bytes: Uint8Array }[];
  readonly draws: number;
}

export function createRenderer<Bindings extends AnyGlyphBindings>(): GlyphRenderer<Bindings, Staged> {
  let committed: Staged = { writes: [], draws: 0 };
  return {
    decode(view: CommandBufferView<Bindings>): PreparedRendererCommit<Staged> {
      // Stage: read every field you need and copy every payload now; the view expires when this call returns.
      const writes = Array.from(view.updates.patches).flatMap((patch) =>
        patch.kind === 'write'
          ? [{ buffer: patch.buffer, offset: patch.destinationOffset, bytes: patch.payload.slice() }]
          : [],
      );
      const draws = view.displayList.kind === 'replace' ? view.displayList.value.children.length : committed.draws;
      const staged: Staged = { writes, draws };
      return {
        result: staged,
        commit: () => {
          committed = staged; // the only place the host changes
        },
        discard: () => undefined, // drop the staged state; the host is untouched
      };
    },
    syncTransforms: () => undefined,
    dispose: () => undefined,
  };
}
```

## What a consumer must uphold

| Rule | What breaks it |
| --- | --- |
| `accept` returns synchronously | a returned promise is a `TypeError` |
| read every field and copy every payload before `accept` returns; never retain `publication.bytes` | the next engine answer, a memory growth, or disposal detaches what you kept |
| `decode` stages; `commit` is the only place the host changes; `discard` cleans up; each runs at most once | a second `commit` throws; `discard` after `commit` is a no-op |
| the order is fixed: source, project, decode, commit, settle; on a throw: discard, then settle as not committed | once `commit` began, settlement is the committed branch even if cleanup throws |
| do not call the engine while holding a borrow | any call advances the epoch and voids it; reentering `shape()` throws |
| a `checkpoint` replaces everything; an `unchanged` display list keeps your draws and applies the patches | mixing the two corrupts the next incremental frame |
| buffer identity is `(id, generation)`; a retirement for an older generation must not touch a newer one; `codecBufferId === 0xffff` is the order buffer | a buffer keyed by id alone is retired by its own successor |
| `recordIndex` is the first physical record of a span and `recordCount` its instance count, in the buffers the draw names | reading from record 0 draws the wrong glyphs |
| iterate `children` in table order; `order` and `depthKey` are already resolved | sorting by your own key breaks decorations and compositing |
| register technique shader variants before an engine snapshots the registry | a later registration throws and names the technique |
