<Intro>
  Text you assign is validated in JavaScript, analysed for scripts, directions, and break opportunities, then
  crosses into Rust once per `glyph.shape()` for every dirty root at once. There it is shaped with HarfRust, laid
  out, and planned into batches; what comes back is one byte range per root, borrowed for the length of a
  synchronous call, that a renderer turns into draw objects. Between frames the engine keeps everything: an
  unchanged root costs nothing, and a moved one costs a matrix upload.
</Intro>

![The glyph pipeline: text and fonts enter JavaScript for Unicode analysis, cross into Rust for shaping, layout and planning, come back as one published byte buffer, and a renderer decodes it into draw objects.](/examples/diagrams/pipeline.svg)

## Analysis

Every property is validated where it enters — construction, `set()`, a hook — with the offending value in the error.
The paragraph text is then analysed in JavaScript: UAX 9 bidi runs, UAX 14 line-break opportunities, UAX 24 scripts,
UAX 29 grapheme clusters, and the spans' font stacks resolved to registered fonts. The engine receives runs, not
strings.

## Shaping

<glyph-proxy root="scenes" data-scene="shaping" aria-label="Eight scripts arriving one grapheme cluster at a time" aspect="16 / 9" />

Each run is shaped with HarfRust against the stack's first font. Clusters whose glyph is missing are collected and
re-shaped with the next font in the stack, as many times as the stack is deep; a cluster still missing after the
last font stays glyph 0 in the last font tried. Fallback is decided by `cmap`, not by raster coverage: a glyph the
font maps but the raster did not bake raises `RasterCoverageError` rather than falling back.

## Layout

Lines are broken at the opportunities analysis found, justified within the paragraph's bounds, flowed through
columns, and positioned in F26.6 fixed point. The result is retained per paragraph: `measure()` and `glyphs()` read
it through separate synchronous calls and never wait for a publication.

## The render plan

The planner walks glyphs in logical order and packs them into storage batches keyed by technique, program, and
resource, then cuts draw spans wherever the codec's masks say a key changed. The output is one publication: a
header and six tables — resources, buffers, patches, primitives, draws, retirements — laid out in Wasm memory.
[Reading the render plan](/docs/advanced/render-plan) documents every field.

## The retained frame transaction

![The retained frame transaction: the app assigns desired state, shape publishes each dirty root once, the planner lends a borrowed plan, the renderer decodes, resolves and prepares, then commits or discards.](/examples/diagrams/frame-transaction.svg)

`glyph.shape()` is synchronous and non-reentrant, and a no-op when nothing is dirty. It stages every dirty root —
each root's `prepare` hook may decline — then makes **one** Wasm call for all of them across every handle. Per root
it adopts the answer, lends it to the root's renderer as a borrowed view, and runs the transaction: project the
tables onto the objects your schema names, `decode` to stage, `commit` to apply, settle. A throw runs `discard` and
settles as rejected; that root keeps its last accepted draw and the error is retained on its texts. `shape()`
rethrows after every root has been visited, one error or an `AggregateError`.

Revisions make this safe. Each request states the engine revision it expects, the plan revision it consumed, and
the last publication generation it acknowledged; a plan is a checkpoint that replaces everything when the consumed
revision is not current, and a set of patches otherwise. A rejected accept leaves every revision untouched.

## What three.js does with it

three's config returns the root's executor as its renderer. On a `replace` it realises one instanced mesh per draw
span under the root's draw object, with the codec's buffers as storage attributes and one material per span from
the format's factory; on an `unchanged` publication it applies patches into the same buffers. `renderOrder` is the
span's index; `userData.pmndrsGlyphRunStart` is its first record. Every frame after, `Text.updateMatrixWorld`
syncs matrices into the transform table without entering Wasm; a text that only moved never reaches the planner.

| Path | Enters Wasm | Cost |
| --- | --- | --- |
| text, style, layout, font, or material changed | once per `shape()`, for every dirty root together | shape, layout, plan, decode, commit |
| position, rotation, scale, visibility changed | no | matrix uploads for the rows that changed |
| nothing changed | no | nothing |
