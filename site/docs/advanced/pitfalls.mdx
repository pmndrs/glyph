## The declared format is not in the GLB

```ts
import { glyph } from '@pmndrs/glyph';
import { msdf } from '@pmndrs/glyph/raster/msdf';

const Inter = glyph.fontFace('/fonts/Inter.glb', { format: msdf({ emSize: 32 }) }); // baked at the default 64
await Inter.formats(); // ['pmndrs.msdf', …] — the keys, not the options; the mismatch is in the descriptor
await Inter.load(); // FontLoadError FONT_FACE_FORMAT_UNAVAILABLE
```

{/*
write
- Symptom: `load()` rejects with `FONT_FACE_FORMAT_UNAVAILABLE` and the message "does not implement the declared
  msdf format", although the GLB plainly has MSDF in it.
- Cause: raster options are part of the raster's identity; `msdf` at `emSize: 32` is a different raster from `msdf`
  at the default 64, and a baked GLB never bakes another one at runtime.
- Fix: keep one constant for the options and pass it to both the bake and the declaration; `await Inter.formats()`
  tells you which formats the GLB advertises before you load anything.
- Shape: one paragraph.

notes · internals
- the rejection — `font-face.ts:550–560` (wraps `RASTER_NOT_FOUND` / `RASTER_SOURCE_UNAVAILABLE`); a name that is no
  format at all — `:652–660`
- identity = SHA-256 of the canonical descriptor — `internal/raster-identity.ts#deriveRasterKey` (`:90–102`)
- `formats()` reads the main GLB without loading sidecars — `font-face.ts:211`; a baked miss never runtime-bakes — D-310
*/}

## Text throws "not loaded"

```ts
import { glyph } from '@pmndrs/glyph';
import { slug } from '@pmndrs/glyph/raster/slug';

const Hero = glyph.fontFace('/fonts/Playwrite.glb', { format: slug });
await Hero.slug.load(); // or Hero.load(); without one of these, createText throws synchronously
three.createText({ font: Hero.slug, text: 'glÿph' });
```

{/*
write
- Symptom: `createText` or `text.font =` throws `FontLoadError` `FONT_FACE_FORMAT_NOT_LOADED` — "format slug is not
  loaded".
- Cause: imperative construction cannot wait; the handle binds a loaded immutable font at construction time, so the
  selection you pass must already be loaded. `Inter.load()` loads every declared format; `Inter.slug.load()` only
  that one.
- Fix: await the load first. React does not have this pitfall: `<Text>` checks `isLoaded()` and suspends on the
  same load promise.
- Shape: one paragraph.

notes · internals
- the throw — `font-face.ts#requiredFontFaceFormat` (`:636–650`), reached from `FontFaceHandleStore.acquire` (`:349–354`)
  and `ThreeRoot.createText` (`three/text.ts:270`)
- `load()` loads every declared format; a member loads only itself — `font-face.ts#FontFaceBase.load` (`:86–89`); D-310
- React: `isThreeHandleFontLoaded` else `use(loadThreeHandleFont(...))` — `react.ts#useHandleFontFace` (`:655–660`); D-301, D-302
*/}

## An outer `<Text>` without a font

```tsx
import { Text } from '@pmndrs/glyph/react';

export function Label() {
  return (
    <Text font={inter}>
      Hello <Text style={{ color: '#ffd166' }}>world</Text>
    </Text>
  );
}
```

{/*
write
- Symptom: a mount-time `TypeError`: "an outer R3F Text requires a font".
- Cause: only a nested `<Text>` inherits; it compiles into a span of its parent and never becomes an object. The
  outer one is the paragraph, and a paragraph must name a font.
- Fix: put `font` on the outer element; inner ones may override it or leave it.
- Shape: one paragraph.

notes · internals
- the throw — `react.ts:453`; nested children flatten into spans — `react.ts#R3fTextChild` (`:65–71`), `flattenText`
  (`:759–790`); D-277 (an inline run carries only the five span properties)
*/}

## Nothing draws in plain three.js, and nothing threw

```ts
import { glyph } from '@pmndrs/glyph';

text.set({ text: 'changed' });
glyph.shape(); // throws here, where you can catch it — traversal swallows the same error into text.error
renderer.render(scene, camera);
```

{/*
write
- Symptom: a `Text` is in the scene, `renderer.render` runs, the screen is empty, the console is quiet.
- Cause: scene traversal shapes for you — the root's draw object calls `glyph.shape()` inside three's own
  `updateMatrixWorld` — but it catches whatever that throws and parks it on `text.error` and `onError` so a render
  loop never dies. If the paragraph was rejected (a bad span, a missing font stack, a capacity overrun) you see
  nothing and hear nothing.
- Fix: call `glyph.shape()` yourself after your edits and before rendering; it rethrows the root's error. Or read
  `text.commitState()` — `failed` carries the error, `pending` means nothing has been accepted yet. Set `onError` in
  any case.
- Correct the earlier draft's claim: an explicit call is not required for drawing; it is required to *see* a failure.
- Shape: one paragraph.

notes · internals
- traversal shape and the swallowed throw — `three/text.ts#ThreeRoot.#commitTraversal` (`:478–493`); the draw root's
  override — `:139–142`; first attachment binds the scene and runs one traversal — `#observeHostTree` (`:421–429`)
- `glyph.shape()` rethrows one error or an `AggregateError` — `glyph-engine.ts:552–555`; D-312
- errors retained and forwarded — `three/text.ts:494–503`, `:918–922`; `commitState()` — `:756–764`
- the proof example runs `scene.add(text) → glyph.shape() → renderer.render` — D-304
*/}

## A span boundary moved

```ts
import { span, txt } from '@pmndrs/glyph';

const accent = span({ color: '#ff0000' });
const literal = txt`${accent`a`}́bc`; // the combining acute lands in the cluster of the styled "a"
literal.spans; // resolved at the join: [{ start: 0, end: 2, … }] — the mark took its base's style
three.createText({ font: Inter, text: literal });
```

{/*
write
- Symptom: a combining mark is drawn in its base letter's colour although you styled only the letter — or the
  other way round, a styled mark's style vanished into a plain base.
- Cause: the engine styles whole grapheme clusters, and a boundary inside one is resolved forward to the end of the
  cluster — a cluster takes the style of its base. Nothing throws; `txt`/`span` and nested `<Text>` resolve the
  boundary where two fragments join, so the paragraph the engine sees is already on the cluster grid.
- Fix: author on cluster boundaries; when you need to know whether a boundary moved, compare the literal's `spans`
  with what you meant. There is no `spans` getter on a Text and no public alignment helper at HEAD.
- Shape: one paragraph.

notes · internals
- the rule and both entry points — D-265; `formatted-text.ts#alignSpansToClusters` (`:41–69`), applied in
  `three/text.ts:1453–1454`; the join rule for `txt`/`span` and nested `<Text>` — `formatted-text.ts:33–40`
- the worked examples — `docs/planning/three-api.md:204–265` (codex tree)
- raw `spans` are rejected at the boundary: "cannot declare raw spans; compose formatted text with txt and span" —
  `three/text.ts:718`, proven at `tests/integration/text-frame-rejection.test.mjs:26–36`
- `Text` has no public `spans` getter (`three/text.ts:646–710`; `spans` is desired state at `:102`), and
  `alignSpansToClusters` is exported from neither `index.ts` nor `three.ts`; `docs/planning/three-api.md:206–265`
  shows both and lags the code
- [verify] the resolved range in the comment (`[0, 2)` for a styled base plus a plain mark): run the literal
  through `txt` before publishing the number
*/}

## Two scenes, one root

```ts
import { glyph } from '@pmndrs/glyph';
import { ThreeConfig } from '@pmndrs/glyph/three';
import { Scene } from 'three/webgpu';

const app = glyph.handle('app', ThreeConfig);
const overlay = new Scene();
scene.add(app.createText({ font: Inter, text: 'world' }));
overlay.add(app('overlay').createText({ font: Inter, text: 'HP 100' })); // a second scene is a second root
```

{/*
write
- Symptom: an error naming the root and "spans more than one Scene; select a different handle root for each Scene".
- Cause: a root discovers its scene from its attached texts and binds to exactly one; the draw meshes live under
  that scene.
- Fix: `handle('name')` for the second scene. In R3F, wrap the portal's subtree in
  `<GlyphProvider handle={app('overlay')}>`.
- Shape: one paragraph.

notes · internals
- the throw — `three/text.ts#ThreeRoot.#bindScene` (`:543–551`); membership by nearest scene — `#renderMembers` (`:564–571`)
- one scene per root, two scenes two roots — D-307
- `GlyphProvider handle` accepts a handle or a named root — `react.ts:193–199`, `#selectReactRoot` (`:417–420`)
*/}

## Nothing changes with `fixed` capacity

```ts
import { glyph } from '@pmndrs/glyph';
import { defineThreeConfig } from '@pmndrs/glyph/three';

const hud = glyph.handle('hud', defineThreeConfig({ capacity: { size: 64, policy: 'fixed' } }));
const readout = hud.createText({ font: Inter, text: 'x'.repeat(65) });
readout.commitState(); // { status: 'pending' } for as long as the root is over budget
// Shorten the text, or give it a handle with room; capacity cannot change on a live handle:
const roomy = glyph.handle('hud-roomy', defineThreeConfig({ capacity: { size: 128, policy: 'fixed' } }));
```

{/*
write
- Symptom: the text stops updating, `commitState()` reports `pending` forever, `measure()` still answers.
- Cause: desired UTF-16 length across the root exceeds `size`; a `fixed` root declines the batch and keeps its last
  accepted draw, by design.
- Fix: shorten, or move the text to a handle configured with room; the decision is retried on every traversal, with
  no latch to clear. Capacity cannot change on a live handle (D-325).
- Shape: one paragraph.

notes · internals
- `required = Σ text.length`, `prepareShape` returns `false` — `three/text.ts:1260–1270`; `capacityExceeded` (`:1111`)
- capacity is immutable config: `defineThreeConfig({ capacity })` normalizes it once (`three/handle.ts:180–181`) and
  every root of the handle receives it (`:236`); `setCapacity` was removed in codex `b4012b703` — D-325; D-282 (no
  rejection latch), D-136
*/}

## `caretAt` returns `undefined`

```ts
const caret = text.caretAt(12, -4); // undefined until the root has accepted a publication for this revision
const box = text.measure(); // desired state; always answers
```

{/*
write
- Symptom: measurement works, `caretAt`, `selectionRects`, and `measureGlyphs` return `undefined`.
- Cause: measurement reads desired state; placements read committed state, and only when the committed revision
  equals the desired one and the last renderer update was accepted. Before the first `shape()`, or right after an
  edit, there is no committed layout to hit-test.
- Fix: shape once (in R3F, wait a frame) before interaction; or use `glyphs()` for desired positions.
- Shape: one paragraph.

notes · internals
- `caretAt` → `#glyphPlacements` → `binding.glyphPlacements` → `#canonicalInspection`, which returns `undefined` when
  unbound, rejected, or `committedRevision !== desiredRevision` — `three/text.ts:861–867`, `:771–774`, `:1213–1225`,
  `:1343–1357`
- `measure()` is desired-state — `three/text.ts:736–742`; D-282, D-292 (committed-only placements)
*/}

## Disposing in the wrong order

```ts
text.dispose(); // releases its font leases
group.dispose(); // does not dispose descendant texts
handle.dispose(); // then the root: no new construction after this
Inter.dispose(); // the declaration last; a disposed face rejects every new selection
```

{/*
write
- Symptom: a `TypeError` "FontFace … has been disposed" on the next `createText`, or a text that keeps drawing after
  you thought its font was gone.
- Cause: leases are counted. A text holds its own immutable font lease and releases it in `dispose()`; a disposed
  face does not invalidate fonts already retained, it only refuses new selections. Disposing the face first therefore
  leaves live texts alive and breaks the next construction.
- Fix: text → group → handle → face. `TextGroup.dispose()` does not dispose its children, so dispose them yourself or
  move them.
- Shape: one paragraph.

notes · internals
- `Text.dispose()` unbinds, unregisters, disposes owned fonts — `three/text.ts:875–881`; `TextGroup.dispose()` — `:1032`
- `FontFace.dispose()` must be called on the declaration; a disposed face throws on selection —
  `font-face.ts#disposeFontFace` (`:266–281`), `#fontFaceSelectionState` (`:284–295`)
- the recommended order — `docs/planning/three-api.md:424–433` (codex tree); disposal without finalizers —
  `docs/planning/font-runtime-ownership.md:1211–1229`
*/}

{/*

- Symptom: WebGPU on `localhost`, WebGL2 on `http://10.0.0.x`; or on the identity branch, fonts that will not load

## Each letter lit separately

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';
import { normalize, positionLocal, vec3 } from 'three/tsl';

const lit = defineTextMaterial((context) => {
  const material = context.createDefaultMaterial();
  material.normalNode = normalize(vec3(positionLocal.x, positionLocal.y, 1)); // paragraph space, not glyph space
  return material;
});
```

{/*
write
- Symptom: a custom lit material shades each glyph as its own little object.
- Cause: the normal was derived from a per-glyph coordinate (`renderCoordinate` is em space for Slug, the unit quad
  for the others), so every glyph sees the same gradient.
- Fix: derive it from `positionLocal` normalised by the paragraph's ink box, as the materials example does.
- Shape: one paragraph.

notes · internals
- `context.position` is the final renderer-local position; `context.shader` outputs are per format —
  `three/material.ts:19–54`; Slug's `renderCoordinate` is "interpolated em-space" — `tsl/slug-shader.ts:86–89`
- the example — this repo, `site/examples/src/scenes/materials/scene.tsx:15–34` (`normalNode` from `positionLocal`
  over the ink span)
*/}

## Leading opens up with a fallback face

{/*
write
- Symptom: one line is much taller than its neighbours.
- Cause: line extents are resolved per cluster from the font that actually drew it; leading is
  `requested − ascent − descent`, clamped at zero, so a fallback face with tall ascent or descent wins the line.
- Fix: choose fallback faces with similar vertical metrics, or state a `lineHeight` that fits the tallest.
- Shape: one paragraph.

notes · internals
- per-cluster extents from the cluster's resolved font — `rust/shaper/src/engine/flow_composition.rs#extents_for_cluster`
  (`:858–905`); `requested = font_size × line_height` when set, else the font's natural height (`:893–896`);
  `leading = (requested − ascent − descent).max(0.0)` (`:897`)
*/}

## A font load rejects again and again

```tsx
import { GlyphProvider } from '@pmndrs/glyph/react';

export function App() {
  return (
    <GlyphProvider errorFallback={(error) => <mesh />}>
      {/* … */}
    </GlyphProvider>
  );
}
```

{/*
write
- Symptom: the network tab shows the same font fetched over and over after one failed load.
- Cause: a rejected load is evicted so a later call is a new operation — by design, so a transient failure can be
  retried — and something in your tree keeps retrying: a component that re-renders and calls the hook again.
- Fix: an error boundary that shows the failure once. `GlyphProvider errorFallback` catches `FontLoadError` and
  rethrows anything else.
- Shape: one paragraph.

notes · internals
- rejection deletes the record — `font-face.ts:549`; D-305, D-310; the cache helper `internal/successful-promise-cache.ts#cacheSuccessfulPromise` (`:1–14`)
- the boundary catches only `FontLoadError` — `react.ts#GlyphFontErrorBoundary` (`:360–373`); prop — `:198`
- the React retry loop seen on the decorations example — this repo, `docs/planning/docs-site-outline.md` (Findings for core)
*/}
