reader
- Has fonts that cannot be baked at build time — user uploads, a font picker, a prototype — and has read Baking
  fonts. Knows what a Worker is. Arrives asking "can the browser do the bake?", should leave knowing that it can,
  what it costs, where the result is cached, and that a baked GLB never re-bakes.

write · intro
- Question: what runs in the browser, and when should it?
- Say: the same baker that runs in the CLI runs in a module Worker; give a FontFace a source font and it produces
  the identical GLB on the client and caches the result in `CacheStorage`. It is the fallback for fonts you cannot
  pre-bake, never the production default.
- Anchor: "the build step, moved to the client, paid once per font".
- Shape: two sentences, then the table.

write · keypoints
- A `.ttf`/`.otf` URL or `File` given to `glyph.fontFace` is baked in a Worker the first time it is needed.
- The sibling `.font.glb` is probed first; only a miss bakes.
- The Worker caches only the final validated GLB, with a lifetime inherited from the source response.
- Nothing reaches the Worker or the baker Wasm unless a source font is used.

| Approach | Best for | Tradeoff |
| --- | --- | --- |
| [Pre-baked GLB](./baking) | production, static fonts | one build step, no runtime cost |
| Runtime bake | user-supplied fonts, fast iteration | the baker Wasm and a Worker load on demand; a bake per new font |

## What the Worker does

{/*
write
- Question: is the client's GLB the same file the CLI would write?
- Paragraph 1: one request normalizes the Unicode ranges, prepares the source once, and feeds the exact prepared
  bytes to the shaping bake and every requested raster bake; it composes one canonical GLB and transfers it back.
  Validation is skipped: the Worker trusts its own output the way the runtime trusts a CLI bake.
- Paragraph 2: only Bitmap, MSDF, and Slug bake inside the Worker; a custom format bakes host-side through the
  baker its own declaration names. Progress arrives as stage and phase events if you want a progress bar.
- Shape: two paragraphs.

notes · internals
- Worker entry: cache lookup, then `bakeFontPipeline` without `validateArtifact`, then cache put and transfer —
  `runtime-bake-worker.ts:38–73`; prepare once, feed core and rasters — `internal/font-bake-pipeline.ts:35–57`, `:71–87`
- Worker raster kinds — `internal/runtime-bake-protocol.ts#workerRasterKinds` (`:10–18`); host-side bake for other
  formats — `loader.ts#runtimeBakeFormat` (`:1722–1745`)
- one request at a time per Worker — `runtime-bake-worker.ts:30–36`; the host serializes too — `runtime-bake.ts:17–25`
  (`SerialWorkerHost`), Worker URL `../dist/runtime-bake-worker.js` `:25`

## Caching

{/*
write
- Question: will the same font bake again next visit?
- Paragraph 1: only the final validated GLB is cached, in `CacheStorage`, under a key of the source bytes, the face
  index, the normalized ranges, and the ordered raster descriptors; the cache name carries the format and baker
  versions, so an upgrade is a clean miss.
- Paragraph 2: persistence follows the source response: `no-store`, `no-cache`, missing freshness, or an already
  expired response stays memory-only; `max-age` (from the response `Date`) or `Expires` sets the derived
  expiration. Quota eviction, private modes, and corruption are transparent misses followed by the same bake.
  An uploaded `File` has no response, so it is memory-only.
- Shape: two paragraphs; a table of the freshness rules if you prefer.

notes · internals
- cache name `pmndrs-glyph-font-bakes-<format>-<baker>` — `internal/runtime-font-cache.ts:7`; key = SHA-256 of
  `{ face, rasters, sourceHash, unicodeRanges }` — `:40–49`
- `put` only with a future `expiresAt` — `:83–85`; expired, short, or hash-mismatched entries are deleted on read
  `:56–77`; storage failures never fail the bake `:79–81`, `:101–103`; requires an `http(s)` origin `:27–34`
- freshness from the source response — `loader.ts#persistentResponseExpiration` (`:2733–2752`); attached to the
  request as `cache.expiresAt` — `:629–635`; byte sources have no expiry `:624–627`
- the Worker skips the cache when the expiry is absent or past — `runtime-bake-worker.ts:41–42`; D-298
*/}

## Bundle boundary

{/*

## A baked GLB never re-bakes

{/*
write
- Question: if my GLB lacks Slug, will the runtime bake it for me?
- Two sentences: no; a member whose exact descriptor the GLB does not advertise rejects with
  `FONT_FACE_FORMAT_UNAVAILABLE`, and runtime baking runs only for a source font that authenticates as TTF/OTF.
  Link Raster formats → Options are identity.

notes · internals
- rejection without baking — `font-face.ts:549–560`; D-310; D-298 ("a GLB with a missing requested format throws
  and never invokes a baker"; baking is entered only after the bytes authenticate as SFNT)
- a `.glb` URL has no source, so a miss is `BAKED_FONT_MISSING`, not a bake — `loader.ts:604–611`
*/}
