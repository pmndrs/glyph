<Intro>
  Shaping and layout are the same for every format; a format only decides how an outline becomes pixels. Bitmap
  bakes pixels at the sizes you choose. MSDF bakes a distance field once and decodes an edge wherever it lands.
  Slug keeps the outline's curves and solves them under every pixel. One baked font can carry all three, and the
  choice is made per font, not per project: pick for the text's size range, motion, and what it has to look like
  at the edge.
</Intro>

<Keypoints title="The short version">
  <KeypointsItem>Default to MSDF. It is right for body copy and labels at any subpixel position, and it is the only format with outline and shadow.</KeypointsItem>
  <KeypointsItem>Use Bitmap for UI at sizes you know. One texel per pixel, snapped to the device grid, and the smallest atlas — but blurry between strikes and no effects.</KeypointsItem>
  <KeypointsItem>Use Slug where the text is the hero: titles, zoom, surfaces in 3D, steep angles. Exact at any size; costs the most per pixel; no effects.</KeypointsItem>
  <KeypointsItem>A format's options are part of its identity. The bake and the declaration must name the same descriptor, or the face rejects.</KeypointsItem>
</Keypoints>

## Choosing

| If the text… | Pick | Because |
| --- | --- | --- |
| sits still in a HUD or a dense UI at sizes you know | **Bitmap** | a strike is pixel-exact at its size and `pixelSnapping` locks it to the device grid; one fetch per pixel |
| is body copy, labels, anything read at a normal size | **MSDF** | one atlas serves every size in its range, any subpixel position, and outline and shadow come from the same field |
| needs an outline or a drop shadow | **MSDF** | the other two reject `outline` and `shadow` at the boundary rather than drawing something wrong |
| zooms, is magnified, or is set very large | **Slug** | coverage is solved from the curves, so there is no resolution to run out of |
| lives on a surface in 3D or is read at a steep angle | **Slug** | the quad is dilated analytically from the exact projection, and the footprint is measured per axis |
| is tiny and must be crisp | **Bitmap** at that strike, else **MSDF** | Bitmap is exact at its ppem; MSDF floors its antialiasing range at one pixel |
| is a whole CJK font | **Bitmap** or **MSDF** with `coverage` | Slug always bakes every glyph; the other two can be seeded with the code points you use |

## Bitmap

Bitmap rasterises each glyph at one or more **strikes** — exact pixel sizes — into an `r8unorm` atlas per strike.
There is no interpolation between strikes: at draw time the engine computes a target size, `fontSize ×
rasterPixelRatio`, and takes the strike with the nearest ppem. Draw at a strike and every pixel is the one the
rasteriser produced; draw between strikes and the sampler blurs.

```ts
import { bitmap } from '@pmndrs/glyph/three/bitmap';

const ui = glyph.fontFace({ baked: '/fonts/inter.font.glb' }, {
  format: { raster: bitmap, options: { strikes: [16, 32] } }, // the strikes the GLB was baked with
});
three.createText({ font: ui, text: 'HP 100', style: { fontSize: 16 }, pixelSnapping: true });
```

| Fact | Value |
| --- | --- |
| options | `strikes: number[]` — required, unique integers from 1 to 1022, stored ascending; `coverage?` seeds a subset |
| atlas | one `r8unorm` texture array per strike; pages up to 1024 px, at most 60 per strike, 1 texel padding |
| per pixel | one `texture(page, atlasUv).r` fetch |
| strike choice | nearest ppem to `fontSize × rasterPixelRatio`; ties go to the first strike; camera distance is not considered |
| `pixelSnapping` | rounds the quad to whole device pixels; Bitmap is the only format that honours it |
| effects | none — `outline` and `shadow` throw when the style is accepted |

Bake the sizes you draw at, times the pixel ratios you ship: a 16 px label on a 2× display wants a 32 strike, and
`rasterPixelRatio` is how a `Text` says so without changing its layout.

## MSDF

MSDF bakes a **multi-channel signed distance field**: for every glyph, a small `rgba8` cell where the RGB channels
each hold a distance to a differently coloured set of edges and the alpha holds the true distance. At draw time the
shader takes the median of the three channels to recover an edge with sharp corners, and reads the alpha for
effects. Two options size it. `emSize` is how many atlas texels one em occupies, so it bounds how faithfully the
outline is stored; `pixelRange` is how many texels the field reaches on either side of the edge, so it bounds how
far an outline or shadow can extend.

```ts
import { msdf } from '@pmndrs/glyph/three/msdf';

const body = glyph.fontFace({ baked: '/fonts/inter.font.glb' }, { format: msdf }); // emSize 64, pixelRange 8
three.createText({
  font: body,
  text: 'Body copy',
  style: { fontSize: 18, outline: { color: '#0a0c12', width: 0.5 }, shadow: { color: [0, 0, 0, 0.6], offset: [1, -1] } },
});
```

| Fact | Value |
| --- | --- |
| options | `emSize` (default 64, 1 to 1022) and `pixelRange` (default 8, 1 to 1020); `coverage?` seeds a subset |
| atlas | one `rgba8unorm` texture array; pages up to 1024 px, at most 60; one lossless KTX2 page per level |
| per pixel | two fetches (fill, and shadow at an offset), `median(rgb) − 0.5` for the edge, `a − 0.5` for the true distance |
| antialiasing | the screen-space range comes from the derivatives of the atlas coordinate and is floored at one pixel |
| effects | `outline` as a ring around the true distance; `shadow` only where the fill leaves alpha; both bounded by `pixelRange` |
| filtering | linear, no mipmaps — minified far below one texel per pixel it will alias |

The field is exact along the edge and only as true as `emSize` texels per em away from it, so a heading set at
four times its `emSize` still has sharp corners but its curves flatten. That is the signal to move up to Slug, or to
bake a second face with a larger `emSize` for the sizes that need it.

## Slug

Slug stores the glyph's **outline** — its quadratic curves, quantised to half floats — sorted into sixteen
horizontal and sixteen vertical bands, in three textures per page: the curves as `rgba16float`, band headers and
curve references as `r32uint`. At draw time the vertex stage dilates the quad by half a pixel using the exact
projection, and the fragment stage walks the one horizontal and one vertical band under the pixel, solves each
curve it meets, and sums coverage. There is nothing to run out of: the same data draws a 12 px caption and a wall.

```ts
import { slug } from '@pmndrs/glyph/three/slug';

const hero = glyph.fontFace({ baked: '/fonts/playwrite.font.glb' }, { format: slug }); // no options exist
three.createText({ font: hero, text: 'glÿph', style: { fontSize: 320 } });
```

| Fact | Value |
| --- | --- |
| options | none; Slug has no descriptor to configure and always bakes every glyph |
| data | 40-byte glyph records; curves in 4096-wide `rgba16float` pages; `r32uint` headers and references |
| per pixel | one header load per axis, then per curve one reference and two curve texels and a quadratic solve; at most 512 curves per band, with an early exit once curves fall behind the pixel |
| footprint | measured per axis from the derivative of the render coordinate, so anisotropy does not soften it |
| effects | none — `outline` and `shadow` throw when the style is accepted |
| filtering | none; there is no texture to filter |

Cost scales with covered area times curves per band, so a full-screen paragraph in Slug is the wrong tool and a
full-screen word is the right one.

## What each one costs

Measured on the package-size report for the full Inter face, every glyph, default options:

| | Bitmap 16 + 32 | MSDF 64 / 8 | Slug |
| --- | ---: | ---: | ---: |
| baked asset, raw | 3.1 MB | 39.3 MB | 3.4 MB |
| baked asset, gzip | 0.56 MB | 8.2 MB | 0.62 MB |
| baker Wasm, raw | 623 kB | 557 kB | 461 kB |
| runtime with three.js `Text` and one format, gzip | 58 kB | 58 kB | 58 kB |

The MSDF number is the price of `emSize: 64` across a whole Latin, Greek, and Cyrillic face; a subset baked at the
size you draw is a fraction of it — see [Baking fonts](/docs/fonts/baking). The three runtimes weigh the same
because the format is a few kilobytes of shader; the engine is the bulk.

| GPU | Bitmap | MSDF | Slug |
| --- | --- | --- | --- |
| textures | one `r8` array per strike | one `rgba8` array | three per page: curves, headers, references |
| instance buffers | origin, size, uvOrigin, uvSize, color, page | rect, uvRect, uvBounds, color, effectColor, page | rect, planeRect, bandTransform, color, inverseFontSize, tableStarts, bandCounts |
| texture memory cap | 256 MiB | 256 MiB | pages of 4096 × ≤2048 half-float texels |

## Options are identity

> [!IMPORTANT]
> The raster key is a SHA-256 of the format's canonical descriptor: kind, version, and options. `msdf` at
> `{ emSize: 32 }` is a different raster from `msdf` at the default 64, and a face whose declared descriptor the GLB
> does not advertise rejects with `FONT_FACE_FORMAT_UNAVAILABLE`. A baked miss never triggers runtime baking. Write
> the options once and pass them to both the bake and the declaration.

```bash
glyph bake --input Inter-Regular.ttf --output inter-small.font.glb --msdf em-size=32,pixel-range=6
```

```ts
const InterSmall = glyph.fontFace({ baked: '/fonts/inter-small.font.glb' }, {
  format: { raster: msdf, options: { emSize: 32, pixelRange: 6 } },
});
await InterSmall.formats(); // what the GLB actually carries, without loading anything
```

Two rules keep the key stable. A bare format value (`msdf`) means its defaults, and the defaults canonicalise to a
descriptor with no fields, so `{ emSize: 64, pixelRange: 8 }` and `msdf` are the same raster. Bitmap strikes are
stored sorted, so `[32, 16]` and `[16, 32]` are the same raster too.

## A typical pairing

One GLB, three formats, one shaping table shared. The first declared format is the face's default, and a
`ThreeConfig` defaults an undeclared face to MSDF.

```ts
const Inter = glyph.fontFace({ baked: '/fonts/inter.font.glb' }, {
  format: [msdf, slug, { raster: bitmap, options: { strikes: [16, 32] } }],
});

three.createText({ font: Inter, text: 'Body copy' });      // MSDF, the default
three.createText({ font: Inter.slug, text: 'Hero' });       // Slug
three.createText({ font: Inter.bitmap, text: 'HP 100' });   // Bitmap at 16 or 32
```

```tsx
const body = useMsdf(url);
const title = useSlug(url);
const ui = useBitmap(url, { strikes: [16, 32] });
```

## Mixing formats

A format is bound to a **font**, not to a paragraph. Every font inside one `txt` literal unifies to one technique,
so a span cannot switch format mid-paragraph; a fallback stack may mix them — Latin in MSDF, an icon face in Slug —
and the plan partitions draws by format and resource. Effects are validated against every technique in the
selection, so a stack with a Bitmap member cannot take an outline. Renderer-free code loads typed `Font`s with the
tuple form:

```ts
const [interBitmap, interMsdf, interSlug] = await loadFont({ baked: '/fonts/inter.font.glb' }, [
  { raster: bitmap, options: { strikes: [32] } },
  msdf,
  slug,
]);
```
