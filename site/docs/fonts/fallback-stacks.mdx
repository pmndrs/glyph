## Icon fonts

```tsx
import { glyph } from '@pmndrs/glyph';
import { Text } from '@pmndrs/glyph/react';
import { slug } from '@pmndrs/glyph/three/slug';

const Icons = glyph.fontFace('/fonts/icons.font.glb', { format: slug });

<Text font={Inter}>
  Hello world <Text font={Icons.slug}>{''}</Text>
</Text>;
```

```ts no-check
import { glyph, txt } from '@pmndrs/glyph';
import { span } from '@pmndrs/glyph/three';
import { slug } from '@pmndrs/glyph/three/slug';

const Icons = glyph.fontFace('/fonts/icons.font.glb', { format: slug });
await Icons.load();
three.createText({ font: Inter, text: txt`Hello world ${span(Icons.slug)``}` });
```

## Leading across faces

{/*
write
- Question: why did one CJK word make its line taller?
- A `> [!WARNING]` callout, three sentences: line height is resolved per style segment from that segment's font
  metrics; when `lineHeight` is set the leading is `fontSize × lineHeight` minus ascent and descent, clamped at
  zero, so a face with tall ascent or descent (Myanmar, Arabic Noto statics) opens the line it lands on. Prefer
  faces with similar vertical metrics in one stack, or set `lineHeight` large enough for the tallest.
- Shape: the callout only.

notes · internals
- extents per style segment: `requested = fontSize × lineHeight` if set, else the font's natural
  ascender − descender + lineGap; `leading = max(requested − ascent − descent, 0)`, split half above and half below —
  `rust/shaper/src/engine/flow_composition.rs:884–903`
- [verify] how per-segment extents merge into a line (`#positive_extents`, `:906`) before writing "the tallest wins"
*/}
