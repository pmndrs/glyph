## Declare and load

```ts
import { glyph } from '@pmndrs/glyph';

const Inter = glyph.fontFace('/fonts/inter.font.glb', { family: 'Inter' });
await Inter.load();

const label = three.createText({ font: Inter, text: 'Hello' });
```

{/*
write
- Question: what is the least I have to write?
- Paragraph 1: one argument is enough; `glyph.fontFace(source)` names the family `Font1`, `Font2`, … and denotes the
  handle's default format, which is MSDF for `ThreeConfig`. A family name you give must be unique among live faces.
- Paragraph 2: `load()` is idempotent and resolves to the same face, so `font: await Inter.load()` is the same as
  the two lines above; a rejected load is forgotten so the next call retries.
- Shape: two short paragraphs under the code.

notes · internals
- generated family `Font{n}` — `font-face.ts#nextFamily` (`:798–804`), used at `:167`; a live duplicate throws
  `FontFace family "…" already exists` — `:168–171`; names are trimmed — `#normalizedFamily` (`:791–796`)
- undeclared format → the handle's default — `font-face.ts#FontFaceHandleStore.#resolveFormat` (`:368–369`);
  `ThreeConfig` defaults to `'msdf'` — `three/handle.ts:177`, `#ThreeConfigOptions.defaultFontFormat` (`:96`)
- `load()` keeps one promise and resolves to the face — `font-face.ts#loadFontFace` (`:389–413`); rejection evicts
  it `:404–409`; D-305
- `createText({ font })` accepts a face, a member, or a family string — `three/text.ts:256–259`; it acquires an

## Formats are members

```ts
import { glyph } from '@pmndrs/glyph';
import { bitmap } from '@pmndrs/glyph/raster/bitmap';
import { msdf } from '@pmndrs/glyph/raster/msdf';
import { slug } from '@pmndrs/glyph/raster/slug';

const Inter = glyph.fontFace('/fonts/inter.font.glb', {
  family: 'Inter',
  format: [msdf, slug, bitmap({ strikes: [16, 32] })],
});

// Inter.default === Inter   the first declared format is the face's default
// Inter.slug !== Inter      every other declared format is its own selection
await Inter.slug.load(); // loads only Slug
await Inter.load(); // loads every declared format
await Inter.formats(); // ['bitmap', 'msdf', 'slug'] — what the GLB carries, without loading sidecars
```

| Selection | Loads | Use when |
| --- | --- | --- |
| `Inter` / `Inter.default` | the default format | ordinary text |
| `Inter.msdf`, `Inter.slug`, `Inter.bitmap` | that format only | a title in Slug, UI in Bitmap |
| `Inter.load()` | every declared format | you will use several |

{/*
write
- Question: what are `Inter.slug` and `Inter.bitmap`, and when do I load which?
- Paragraph 1: a declaration lists the formats it will use; the first is the default, so `font: Inter` and
  `font: Inter.default` are the same selection, and each other format is a member you pass where you want it.
  Loading a member loads that format only; loading the face loads every declared format plus any format the file
  advertises for which a decoder is imported.
- Paragraph 2: `formats()` answers "what does this file carry?" from the file's own directory without loading a
  raster. A declared member the file does not advertise rejects with `FONT_FACE_FORMAT_UNAVAILABLE`, and a baked
  miss never triggers runtime baking. Options are part of the format: `msdf({ emSize: 32 })` matches only a bake made
  with that value (link Raster formats → Options are identity).
- Shape: two paragraphs, then the table.

notes · internals
- declared members are defined per format key; a repeated key throws — `font-face.ts:226–247`; a string key
  resolves through the imported formats — `#tryResolveDeclaredFormat` (`:663–666`), `config/raster-format.ts#rasterFormatForKey` (`:158–168`)
- `face.slug.load()` — `font-face.ts#loadDeclaredFontFaceSelection` (`:481–487`) → `#loadFontFaceFormat` (`:496–527`)
- `face.load()` = every declared format + `loadAdvertised` — `font-face.ts#loadAllFontFaceFormats` (`:438–479`);
  nothing advertised and nothing declared → `FONT_FACE_FORMAT_REQUIRED` `:457–462`
- `face.formats()` reads the source lease's `formats` without loading — `font-face.ts#fontFaceFormats` (`:568–583`),
  `loader.ts#FontFaceSourceLease.formats` (`:921–924`)
- `FONT_FACE_FORMAT_UNAVAILABLE` wraps `RASTER_NOT_FOUND` / `RASTER_SOURCE_UNAVAILABLE` — `font-face.ts:549–560`; D-310
- options in the identity — `font-face.ts#singleFormatIdentity` (`:782–789`); `bitmap({ strikes })` is a callable
  request — `config/raster-format.ts:128–131`
*/}

## Load before use

```ts
const title = three.createText({ font: await Inter.slug.load(), text: 'Title' });
Inter.slug.isLoaded(); // true, synchronously, after the promise settles
```

## Strings and the provider

```tsx
import { GlyphProvider, Text } from '@pmndrs/glyph/react';
import { slug } from '@pmndrs/glyph/raster/slug';

<GlyphProvider fontFaces={{ Inter: '/fonts/inter.font.glb', Title: { src: '/fonts/playwrite.font.glb', format: slug } }}>
  <Text font="Inter">Hello</Text>
  <Text font="Title">Hello</Text>
</GlyphProvider>;
```

{/*
write
- Question: can I name a font with a string?
- Paragraph 1: a string resolves through the nearest provider's `fontFaces` table, then the root catalog by family;
  an unknown name throws `FONT_FACE_NOT_FOUND`. The table declares names, it does not gate loading: a resolved
  selection follows the same `isLoaded`/`use` path as a direct one.
- Paragraph 2: a provider with `fontFaces` or `fallback` adds a local Suspense boundary; `errorFallback` catches
  font load errors only and rethrows everything else; `handle` selects a handle or a named root and is immutable —
  remount to change it.
- Shape: two paragraphs.

notes · internals

## Sources

| Source | Resolves to |
| --- | --- |
| `'/fonts/inter.font.glb'` or a `URL` ending in `.glb` | baked only; a miss is `BAKED_FONT_MISSING` |
| `'/fonts/Inter.ttf'` or any other URL | the source font, and a probe for the sibling `Inter.font.glb`; a missing sibling warns in development and bakes at runtime |
| `File` or `Blob` | a `.ttf`/`.otf` name or font MIME type is a source font; anything else is a baked GLB |
| `SerializedFontFace` | a face cloned from another realm — see below |

{/*
write
- Question: what can I pass as the first argument?
- One sentence above the table: a source is one thing — a URL, a file, or a clone — and the file's own directory
  decides which formats exist; there is no list of candidates.
- One paragraph under: one content-addressed graph backs every face and handle: two declarations over the same URL
  share one fetched artifact and acquire only the raster artifacts their selected formats request. Family names are
  aliases, never cache keys.
- Avoid: the `{ baked }` / `{ source, baked }` object forms; they belong to the immutable-Font loaders being removed.

notes · internals
- `.glb` URL → baked only; other URL → source plus sibling `.font.glb` probe — `loader.ts#resolveFontRequest`
  (`:2675–2700`, the sibling at `:2693–2699`)
- baked probe first, then runtime bake when a source exists — `loader.ts:596–643`; development warning
  `#warnMissing` (`:733–743`); `BAKED_FONT_MISSING` when there is no source `:604–609`
- `Blob` classification by name or MIME — `font-face.ts#fontFaceLoadInput` (`:747–761`)
- serialized clone — `font-face.ts:172`, `:622`
- source types — `font-face.ts#FontFaceSource` (`:27`); D-297 (one source per face), D-298 (content identity)
- [in flight] `FontFaceSource` still admits the immutable-Font `FontInput` objects (`font.ts:57–71`) and the

## Errors

| Code | When |
| --- | --- |
| `BAKED_FONT_MISSING` | a baked-only source answered 404 or 410 |
| `BAKED_FONT_FETCH` | any other HTTP failure |
| `BAKED_FONT_INVALID`, `BAKED_FONT_INCOMPATIBLE` | the bytes are not a `PMNDRS_font` GLB, or its version pins do not match this runtime |
| `BAKED_FONT_RESOURCE_LIMIT` | over 64 MiB, more than 4096 buffer views, or more than 256 rasters |
| `FONT_FACE_FORMAT_UNAVAILABLE` | the declared format and options name a raster key the file does not carry |
| `FONT_FACE_FORMAT_REQUIRED` | `load()` found no declared or decodable format |
| `FONT_FACE_FORMAT_NOT_LOADED` | imperative `createText` on a selection that has not loaded |
| `FONT_FACE_NOT_FOUND` | a family string no provider table or catalog entry answers |
| `RUNTIME_BAKER_UNAVAILABLE` | a source font needed baking and the runtime baker could not be imported |

{/*
write
- Question: what can go wrong, and which code tells me which?
- One paragraph under the table: `face.load()` loads every declared format and every format the file advertises
  for which a decoder has been imported; `face.slug.load()` loads one. Decoding rechecks each raster's identity,
  validates its record table and pages, and refuses an atlas over 256 MiB. GPU upload happens on first draw.
- Shape: the table and one paragraph; every code is a `FontLoadError` with `.code` and `.url`.

notes · internals
- `FontLoadError` — `loader.ts:208–216`; `BAKED_FONT_MISSING` `:604–609`; `BAKED_FONT_FETCH` `:653`, `:660`;
  `BAKED_FONT_INVALID` / `INCOMPATIBLE` / `RESOURCE_LIMIT` `:684–700`; limits `:61–63`
- `FONT_FACE_FORMAT_UNAVAILABLE` `font-face.ts:555`, `:655`; `FONT_FACE_FORMAT_REQUIRED` `:458–461`;
  `FONT_FACE_FORMAT_NOT_LOADED` `:644–647`; `FONT_FACE_NOT_FOUND` `three/text.ts:584`, `react.ts:494`
- `RUNTIME_BAKER_UNAVAILABLE` — `loader.ts#loadDefaultRuntimeBake` (`:1957–1969`)
- 256 MiB decoded-texture cap — `raster/bitmap.ts:34`, `:275–277`; `raster/internal/msdf-decoder.ts:32`, `:94`;
  `raster/internal/slug-decoder.ts:26`
- KTX2 page validation — `internal/raster-ktx.ts#validateNativeKtx2` (`:38`)
- [verify] "GPU upload happens on first draw": find the upload in `three/renderer-resources.ts` before stating it
*/}

## Across realms

```ts
declare const worker: Worker;

const [serialized, transfer] = await Inter.slug.clone();
worker.postMessage(serialized, transfer);
```

```ts
import { glyph, type SerializedFontFace } from '@pmndrs/glyph';

self.onmessage = ({ data }: MessageEvent<SerializedFontFace>) => {
  const Inter = glyph.fontFace(data);
  void Inter.load();
};
```

{/*
write
- Question: how does a Worker get the font without fetching it again?
- Two sentences: `clone()` loads the selection if needed, then copies the main GLB and that format's dependencies
  into fresh buffers and returns them with their transfer list; nothing ordinary ever copies font bytes. On the other
  side, `glyph.fontFace(serialized)` claims the envelope and imports it as a seed into that realm's graph, so a later
  clone of another format enriches the same face rather than reloading it.
- Shape: two sentences, the two blocks.

notes · internals
- `clone()` loads first, snapshots into fresh buffers — `font-face.ts#cloneFontFace` (`:415–436`); returns

## Ownership

| Object | Dispose when | Then |
| --- | --- | --- |
| `Text` | it leaves the scene for good | its font lease releases |
| `FontFace` | no text or hook uses it | pending loads abort; its graph leases release |
| handle | the adapter is finished | after existing leases end |

{/*
write
- Question: who disposes what, in which order?
- One paragraph: dispose texts before faces; a face disposed early keeps its texts alive because leases are counted,
  and the text's own lease releases when it disposes. `dispose()` is called on the declaration, not on a member.
  Disposal is the correctness mechanism; the finalizer is only a safety net for abandoned React roots.
- Shape: the table and one paragraph.

notes · internals
- `Text.dispose()` releases the fonts it acquired — `three/text.ts:875–881`; the acquired lease is a clone of the

  `font-face.ts#disposeFontFaceResourceOwner` (`:679–692`); must be the declaration, not a member `:272–274`
