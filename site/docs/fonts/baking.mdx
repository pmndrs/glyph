## Bake one font

```bash
glyph bake --input Inter-Regular.ttf --output inter.font.glb --unicodes U+0020-007E --bitmap 32 --msdf --slug
```

| Option | Meaning |
| --- | --- |
| `--input <path>` | source TTF, OTF, TTC, or OTC; WOFF and variable fonts are rejected with a named error |
| `--output <path>` | the `.font.glb` to write; it must not alias the input |
| `--font-face-index <n>` | face within a collection; default 0 |
| `--unicodes <set>` | code points to keep: `U+XXXX` and `U+XXXX-YYYY`, comma separated, up to 4096 ranges |
| `--bitmap <ppem,…>` | embed Bitmap strikes; positive integers up to 1022, stored deduplicated and ascending |
| `--msdf [em-size=N,pixel-range=N]` | embed MSDF; defaults 64 and 8; limits 1022 and 1020 |
| `--slug` | embed Slug; it has no options |
| `--check` | rebuild into a temporary directory and compare bytes with `--output`; never writes the target |
| `--json` | print the complete bake report |

## Subset to what you render

```bash
glyph glyphs fa-solid-900.ttf --name globe --name earth-americas --unicode-set
# U+F0AC,U+F57D
glyph bake --input fa-solid-900.ttf --output icons.font.glb --unicodes U+F0AC,U+F57D --bitmap 32 --msdf --slug
```

{/*
write
- Question: how do I ship only the glyphs I draw, and how do I find their code points?
- Paragraph 1: `glyph glyphs` lists a font's code-point mappings with its `post` or CFF glyph names; `--name`
  filters, `--unicode-set` prints the set in the form `--unicodes` takes, and a name the font does not have is an
  error rather than an empty result.
- Paragraph 2: subsetting happens before anything is baked: the source is cut to the requested code points with
  every layout script kept and the default layout features closed over, glyphs are renumbered, and that prepared
  font feeds the shaping payload and every raster baker alike. Selection is by code point only; there is no glyph-id
  form, so the shaper's cmap always matches what was baked.
- Closing (was a NOTE): a code point the subset dropped shapes to glyph 0, takes `.notdef`'s advance, and is counted
  in `measure().missingGlyphCount`; a fallback stack is how a missing code point finds another face, a wider subset
  is how it stops being missing.
- Shape: two paragraphs and a closing sentence; keep the comment line in the bash block, it is the answer.

## Choose raster options deliberately

```bash
glyph bake --input Inter-Regular.ttf --output inter-small.font.glb --msdf em-size=32,pixel-range=6
```

## Node API

```ts
import { bakeFont, inspectFont, bakeProject } from '@pmndrs/glyph/bake';
import { bitmapBaker } from '@pmndrs/glyph/bakers/bitmap';
import { msdfBaker } from '@pmndrs/glyph/bakers/msdf';

const report = await bakeFont({
  input: 'fonts/Inter-Regular.ttf',
  output: 'public/fonts/inter.font.glb',
  font: { fontFaceIndex: 0 },
  unicodeRanges: [{ start: 0x20, end: 0x7e }],
  rasters: [
    { baker: bitmapBaker, packaging: { artifact: 'embedded', pages: 'embedded' }, options: { strikes: [32] } },
    { baker: msdfBaker, packaging: { artifact: 'embedded', pages: 'embedded' }, options: { emSize: 32, pixelRange: 6 } },
  ],
});
report.execution.outputs; // [{ role: 'font', file, bytes, sha256 }]
report.execution.timingsMs; // read, coreBake, rasterBake, compose, validate, transport, write, total

await inspectFont({ input: 'fonts/Inter-Regular.ttf' });
await bakeProject({ projectRoot: '.', outputRoot: 'public/generated' });
```

| --- | --- |
| `NodeBakeError` `STALE_OUTPUT` | `--check` found a difference |
| `NodeBakeError` `OUTPUT_OVERLAPS_INPUT`, `OUTPUT_CONFLICT`, `SOURCE_OUTSIDE_ASSET_ROOT`, `OUTPUT_TARGET_TYPE` | the paths you gave cannot be honoured |
| `NodeBakeError` `GLYPH_NAME_NOT_FOUND`, `FONT_INSPECTION_FAILED` | `glyph glyphs` could not answer |
| `FontBakeError` `UNSUPPORTED_CONTAINER` | WOFF or WOFF2 input; decompress it first |
| `FontBakeError` `UNSUPPORTED_VARIABLE_FONT` | a font with `fvar`, `gvar`, or another variation table; instance it first |

| `FontBakeError` `MISSING_TABLE`, `INVALID_TABLE`, `INVALID_GLYPH_EXTENTS`, `SUBSETTING_FAILED` | the source is not a font the baker can read |
| `FontArtifactValidationError` | the composed GLB failed validation; `issues` names each check |

## What is in the file

| Field | Content |
| --- | --- |
| `shaping` | a stripped SFNT — `head`, `maxp`, `cmap`, `hhea`, `hmtx`, `OS/2`, and `BASE`, `GDEF`, `GSUB`, `GPOS`, `VORG`, `kern`, `vhea`, `vmtx` when present — plus per-glyph extents and an availability bitset; its SHA-256 is the shaping hash |
| `metrics` | glyph count, units per em, ascender, descender, line gap, underline position and thickness, strikeout position and size |
| `provenance` | source hash, descriptor hash, face index, baker, HarfRust, HarfBuzz reference, and Unicode versions |
| `rasters` | a directory of `{ rasterKey, kind, extension, version, source }`, embedded or external |

{/*
write
- Question: what am I shipping, byte for byte?
- Paragraph 1: one GLB, one JSON chunk, one binary chunk. The `PMNDRS_font` extension holds the four fields in the
  table. No outlines travel in the shaping payload: `glyf`, `loca`, and `CFF` are dropped with every other table
  not on the list, and glyph imagery lives only in the rasters.
- Paragraph 2: each raster is its own extension — `PMNDRS_font_bitmap`, `PMNDRS_font_distance_field`,
  `PMNDRS_font_slug` — carrying the shaping hash, glyph count, and raster key it was baked against, so a raster
  cannot be paired with a different shaping payload; every page is a lossless KTX2 texture.
- Closing: the line metrics are what draw underlines and strike-throughs at runtime; a font without `post` gets a
  conservative derived underline rather than zeros.
- Shape: two paragraphs and a closing sentence.

- extension shape — `generated/font-artifact-schema.ts#PmndrsFontExtension`: `shaping` (`:6–15`, format
