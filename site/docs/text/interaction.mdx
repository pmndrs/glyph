A `Text` answers the geometry an editable field needs and applies one exact edit. Selection state, caret drawing,
keyboard, pointer, clipboard and undo stay in your application.

```ts
const position = text.hitTest({ x: 0.4, y: 0.2 }); // { offset, affinity }
const caret = text.caret(position); // { rect, line, level, secondary, clipped }
const next = text.move(position, 'right', 'grapheme'); // { position, goalX }
const word = text.boundary(position, 'word'); // { start, end }
const rects = text.rangeRects(word.start, word.end); // LayoutBox[]
text.replace(word.start, word.end, 'glyph');
```

## Units and coordinates

- Offsets are UTF-16 code units of `text.text`, and must be grapheme boundaries. A ligature has caret stops inside it;
  an emoji sequence, a flag and a combining sequence are one unit.
- Coordinates are Text-local with +X right and **+Y down**, anchor included. A Three.js local point is +Y up, so
  negate `y` on the way in and on the way out.
- Every method prepares the text first if a setter left it dirty. None returns `undefined` and none waits for a
  frame.

A position is an offset and a side. `affinity` is `'downstream'` when the caret belongs to the grapheme that starts at
the offset and `'upstream'` when it belongs to the one that ends there. The two differ at a soft wrap, where
`'upstream'` is the end of the earlier line, and at a bidi boundary, where they are two x positions on one line and
`caret().secondary` is the other one.

## From a pointer to a caret

```ts
import { Raycaster, Vector2, Vector3 } from 'three/webgpu';

const raycaster = new Raycaster();
const hit = new Vector3();

function positionFromPointer(event: PointerEvent, canvas: HTMLCanvasElement) {
  const rect = canvas.getBoundingClientRect();
  const ndc = new Vector2(
    ((event.clientX - rect.left) / rect.width) * 2 - 1,
    -(((event.clientY - rect.top) / rect.height) * 2 - 1),
  );
  raycaster.setFromCamera(ndc, camera);
  const { origin, direction } = raycaster.ray;
  hit.copy(origin).addScaledVector(direction, -origin.z / direction.z); // the text lies on z = 0
  const local = text.worldToLocal(hit);
  return text.hitTest({ x: local.x, y: -local.y });
}
```

`hitTest` returns the caret stop nearest the point. The point may be between lines or outside the text. Draw the caret
from `text.caret(position).rect` as a child of the text so it inherits the transform.

## Selection

```ts
import { Mesh, MeshBasicNodeMaterial, PlaneGeometry } from 'three/webgpu';

const [anchor, focus] = [9, 3];
for (const box of text.rangeRects(Math.min(anchor, focus), Math.max(anchor, focus))) {
  const highlight = new Mesh(new PlaneGeometry(box.width, box.height), new MeshBasicNodeMaterial({ color: '#264f78' }));
  highlight.position.set(box.x + box.width / 2, -(box.y + box.height / 2), -0.01);
  text.add(highlight);
}
```

`rangeRects` returns one rectangle per run of the range that is contiguous on its line, so a bidi line can yield
several. It throws `TextOffsetError` for a reversed range; order the anchor and the focus yourself.

## Keyboard movement

```ts
import type { TextPosition } from '@pmndrs/glyph';

let position: TextPosition = { offset: 0, affinity: 'downstream' };
let goalX: number | undefined;

function onKey(key: string): void {
  if (key === 'ArrowLeft' || key === 'ArrowRight') {
    position = text.move(position, key === 'ArrowLeft' ? 'left' : 'right', 'grapheme').position;
    goalX = undefined;
  } else if (key === 'ArrowUp' || key === 'ArrowDown') {
    const moved = text.move(position, key === 'ArrowUp' ? 'up' : 'down', 'line', goalX);
    position = moved.position;
    goalX = moved.goalX; // keeps the column across short lines
  }
}
```

`'left'` and `'right'` are visual and cross bidi runs; `'forward'` and `'backward'` are logical. The unit is
`'grapheme'`, `'word'`, `'sentence'` or `'line'`.

## An exact edit

```ts
let caretOffset = text.text.length;

function type(insert: string, selectionStart = caretOffset, selectionEnd = caretOffset): void {
  text.replace(selectionStart, selectionEnd, insert);
  caretOffset = selectionStart + insert.length;
  const { rect } = text.caret({ offset: caretOffset, affinity: 'upstream' }); // already the edited layout
}

function backspace(): void {
  if (caretOffset === 0) return;
  const start = text.move({ offset: caretOffset, affinity: 'upstream' }, 'backward', 'grapheme').position.offset;
  type('', start, caretOffset);
}
```

`replace` edits exactly the range it names and spans follow it: inserted text takes the style of the grapheme before
it. Because the next query prepares the text, the caret rectangle read right after an edit is the edited one.

An input method needs nothing more. Track the composition as a range and replace it on every update:

```ts
let composition = { start: 0, end: 0 };

function compose(insert: string): void {
  text.replace(composition.start, composition.end, insert);
  composition = { start: composition.start, end: composition.start + insert.length };
  const underline = text.rangeRects(composition.start, composition.end);
}
```

## Errors

Every method throws `TextOffsetError` for an offset that is not a whole number, is out of range, ends a reversed range
or is inside a grapheme. Nothing is snapped or clipped. See [Errors](/text/errors).
