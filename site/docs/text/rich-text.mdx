<Intro>
  A paragraph is one shaped unit; a span is a range inside it that overrides font, style, or material. You can author
  the ranges as offsets, as template-tag fragments, or as nested React elements — all three compile to the same pair
  of `text` and `spans`, and all three resolve their boundaries onto grapheme clusters before a frame is built.
</Intro>

<Keypoints title="What you'll learn">
  <KeypointsItem>Three ways to author the same document</KeypointsItem>

  <KeypointsItem>The cluster rule: a boundary moves forward, a base keeps its style</KeypointsItem>
  <KeypointsItem>Editing: one assignment per keystroke, `text` and `spans` together</KeypointsItem>
</Keypoints>

## Offsets

```ts
three.createText({
  font: inter,
  text: 'Status: online',
  spans: [{ start: 8, end: 14, style: { color: '#4ade80' }, font: mono }],
});
```

## Template tags

```ts
import { span, txt } from '@pmndrs/glyph';

const ok = span({ color: '#4ade80' });
const code = span(mono, { letterSpacing: 0.01 });

three.createText({ font: inter, text: txt`Status: ${ok`online`} in ${code`us-east-1`}` });
```

{/* prose: `txt` composes fragments and derives every boundary at a concatenation join; `span(font?, ...styles)`
returns a tag; nesting is allowed. The result is a frozen `{ text, spans }`. */}

## Nested Text

```tsx
<Text font={inter}>
  Status: <Text style={{ color: '#4ade80' }}>online</Text> in <Text font={mono}>us-east-1</Text>
</Text>
```

{/* prose: a nested `<Text>` is an inline run — it inherits the paragraph's font and style, creates no Object3D,
carries no transform, and accepts only `children`, `font`, `style`, and `material`; a box prop on it is named and
rejected at mount. */}

## What a span may override

| Field | Effect |
| --- | --- |
| `font` | a different loaded font or stack for the run |
| `style` | any `TextStyle` member; the rest inherits |
| `material` | a `defineTextMaterial` factory; span → text → group precedence |

## The cluster rule

> [!IMPORTANT]
> A cluster takes the style of its base. Every span boundary moves forward to the end of the cluster containing it,
> so a mark that attaches to a base follows the base. Nothing throws; `text.spans` reports the resolved offsets.

```ts
const accent = { color: '#ff0000' };
const label = three.createText({ font, text: 'abc', spans: [{ start: 0, end: 1, style: accent }] });
label.set({ text: 'ábc', spans: label.spans }); // 'a' + combining acute is now one cluster
label.spans; // [{ start: 0, end: 2, style: accent }]
```

{/* prose: why forward — backward would take style away from a base you styled and hand the cluster to its mark.
An emptied span stays in the array as `[n, n)` so entries line up with what you authored. Out-of-range or inverted
ranges are a different error and throw from construction/`set()`. `alignSpansToClusters(text, spans)` applies the
same resolution to your own offsets and returns the input by identity when nothing moves. */}

## Editing

```ts
label.text = document.value; // derives the smallest common-prefix/suffix UTF-16 edit
label.set({ text: document.value, spans: document.spans }); // when you own styled ranges
```

{/* prose: assignment is the edit protocol — one narrow edit per keystroke, no offset helpers. `text` without
`spans` clears the ranges it replaced, because replacement text carries its own formatting; an editor that owns
ranges rebases them in its own model and states both. The removed helpers (`insertText`, `deleteText`,
`replaceText`, `setSpan`, `removeSpan`) let a caller hand the engine an offset the tree cannot express. */}
