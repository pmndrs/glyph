<Intro>
  A paragraph is one shaped unit; a span is a range inside it that overrides font, style, or material. You author
  runs as `txt`/`span` fragments in three.js or as nested `<Text>` in React — both compile to the same document with
  no offsets in it, and both resolve their boundaries onto grapheme clusters before a frame is built.
</Intro>

  <KeypointsItem>The cluster rule: a boundary moves forward, a base keeps its style</KeypointsItem>
  <KeypointsItem>Editing: one assignment per keystroke</KeypointsItem>
</Keypoints>

## Template tags

```ts
import { glyph, loadFont, txt } from '@pmndrs/glyph';
import { span } from '@pmndrs/glyph/three';
import { msdf } from '@pmndrs/glyph/three/msdf';

const mono = await loadFont({ baked: '/fonts/mono.font.glb' }, msdf); // a span's font is a loaded Font or stack
const ok = span({ color: '#4ade80' });
const code = span(mono, { letterSpacing: 0.01 });
const glow = span(glowMaterial);

three.createText({ font: Inter, text: txt`Status: ${ok`online`} in ${code`us-east-1`} ${glow`●`}` });
```

{/* prose: `txt` composes fragments and derives every boundary at a concatenation join; `span(font?, ...styles)`
returns a tag whose font is a loaded `Font`/`FontStack` (the paragraph's own `font` may be a FontFace); the `/three`
`span` also accepts one material. Nesting is allowed. The result is a frozen document. */}

## Nested Text

```tsx
<Text font={inter}>
  Status: <Text style={{ color: '#4ade80' }}>online</Text> in <Text font={mono}>us-east-1</Text>
</Text>
```

{/* prose: a nested `<Text>` is an inline run — it inherits the paragraph's font, style, and material, creates no
Object3D, carries no transform, and accepts only `children`, `font`, `style`, and `material`; a box prop on it is
named and rejected at mount. */}

## What a span may override

| Field | Effect |
| --- | --- |
| `font` | a different loaded `Font` or stack for the run, in the paragraph's raster format |
| `style` | any `TextStyle` member; the rest inherits |
| `material` | a `defineTextMaterial` factory; span → text → group → root precedence |

> [!NOTE]
> A `txt` document is typed by one raster format, so a span's font shares the paragraph's format — Slug in Slug,
> MSDF in MSDF. To mix formats, put the faces in a stack on the paragraph; the run then selects a face, not a format.

## Reading the result

```ts
label.spans; // the resolved records: [{ start, end, style?, font?, material? }]
```

{/* prose: `spans` is read-only — you author through `text`; the resolved offsets it reports are on cluster
boundaries. */}

## The cluster rule

> [!IMPORTANT]
> A cluster takes the style of its base. Every span boundary moves forward to the end of the cluster containing it,
> so a mark that attaches to a base follows the base. Nothing throws; `text.spans` reports the resolved offsets.

```ts
txt`a${span({ color: '#ff0000' })`́b`}`;
// text  'áb' — the base and the combining acute fused into one cluster spanning [0, 2)
// spans [{ start: 2, end: 3, … }] — the fused cluster keeps the style of its base, which is plain
```

{/* prose: why forward — backward would take style away from a base you styled and hand the cluster to its mark. An
emptied span stays as `[n, n)` so entries line up with what you authored. Out-of-range or inverted ranges are a
different error and throw from construction/`set()`. */}

## Editing

```ts
label.text = document.value;                          // derives the smallest common-prefix/suffix UTF-16 edit
label.text = txt`${document.before}${ok`${document.selected}`}${document.after}`; // restate runs with the text
```

{/* prose: assignment is the edit protocol — one narrow edit per keystroke; a styled document is restated as a
document, never as offsets. The removed helpers (`insertText`, `deleteText`, `replaceText`, `setSpan`, `removeSpan`)
let a caller hand the engine an offset the tree cannot express. */}
