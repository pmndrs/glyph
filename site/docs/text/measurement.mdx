## Ink versus advance

```
          ┌─────────────────── width / contentWidth ───────────────────┐
  ascent  │  ╭──── inkBounds ────╮                                      │
          │  │  H e l l o        │                                      │  height /
 baseline ├──┼───────────────────┼──────────────────────────────────────┤  contentHeight
  descent │  ╰───────────────────╯                                      │
          └────────────────────────────────────────────────────────────┘
```

{/*
write
- Question: which width is "the" width?
- Paragraph 1: `contentWidth`/`contentHeight` are advance extents, the space the text claims; that is what a flex
  or grid host wants because CSS box measure is advance-based. `inkBounds` is what was drawn, the union of the
  outlines; italics, accents, and swashes overhang their advances, so it is what you centre on. `width`/`height`
  are the resolved box under the constraints and can be wider than the content when the constraint is `exact`.
- Paragraph 2: paragraph space is the top-left corner of the box, x right, y down; the scene is y-up, so every y
  flips sign when it becomes a position (point at the snippet above and the proxy).
- Closing: "centre on ink; stack on advance"; using one where the other belongs is a silent visual error.
- Avoid: repeating the field table.
- Shape: two paragraphs and the rule.

notes · internals
- advance vs ink, and why both ship under unconfusable names — `layout.ts:52–61`
- `width`/`height` are the resolved box; `contentWidth`/`contentHeight` are extents before box clamping — `layout.ts:68–75`
- paragraph space: origin top-left, positive y down — `layout.ts:4–7`, `:147–149`; the scene flip —
  `three/text.ts#Text.#setBoundingBox` (`:887–897`: `min.y = -(y + height)`)
- flexible widths resolve to content width; `exact` keeps the stated box — D-291
- the arc scene's ring closes with `contentWidth` and gaps with `width` — `.agents/docs/planning/docs-site-outline.md:503` (findings table), `site/examples/src/scenes/arc/scene.tsx`
*/}

## ParagraphLayoutSummary

<details>
<summary>Every field</summary>

| Field | Meaning |
| --- | --- |
| `ascent`, `descent`, `lineHeight` | box metrics around the first baseline; `ascent + descent === lineHeight`, half-leading already distributed |
| `width`, `height` | the resolved box under the given constraints |
| `contentWidth`, `contentHeight` | advance extents of the laid-out lines before box clamping |
| `firstBaseline`, `lastBaseline` | distance from the box top to the first and last baselines |
| `inkBounds` | union of glyph ink boxes; `undefined` only when the query did not position glyphs — zero glyphs report a zero-extent box |
| `overflowed` | content exceeded the box under the layout's overflow policy |
| `minContentWidth`, `maxContentWidth` | intrinsic widths: widest run with soft breaks taken / widest run between forced breaks |
| `glyphCount`, `lineCount`, `missingGlyphCount` | positioned glyphs including spaces; lines; `.notdef` glyphs |
| `lines[]` | `ParagraphLineMetrics`: `index`, `textStart/End`, `glyphStart/Count`, `baseline`, `advance`, `inkBounds`, `ascent`, `descent`, `lineHeight` |

</details>

{/*
write
- Question: what is in the summary, precisely?
- The table is the answer. Above it, one sentence: the summary is allocation-light on purpose and carries no
  per-glyph array; when you find yourself indexing glyphs you want `glyphs()`.
- Under it, two facts worth a sentence each: `ascent + descent === lineHeight` exactly, with half-leading already
  folded in, so a caller aligning to a baseline or an x-height reads box metrics, not raw font metrics; and
  `minContentWidth`/`maxContentWidth` ride the same pass as everything else, so a layout system does not need a
  second query at zero width.
- Avoid: restating the `inkBounds` rule; the table cell carries it.
- Shape: one sentence, table, two sentences.

notes · internals
- the interface — `layout.ts#ParagraphLayoutSummary` (`:116–124`) over `#ParagraphMeasurement` (`:63–91`) and
  `#ParagraphIntrinsicWidths` (`:139–142`)
- baseline metrics are box metrics — `layout.ts#BaselineMetrics` (`:37–50`); whole-paragraph metrics reference `firstBaseline` (`:64`)
- `inkBounds` absent means "did not position", never "empty" — `layout.ts:80–89`
- intrinsic widths: `maxContentWidth` between forced breaks, `minContentWidth` with soft breaks taken per wrap

## glyphs()

```ts
const inspection = text.glyphs();
inspection.x[0]; inspection.y[0]; inspection.glyphIds[0]; inspection.clusters[0]; inspection.glyphStableIds[0];
```

{/*
write
- Question: when do I need the columns?
- Paragraph 1: `glyphs()` is the summary plus every per-glyph and per-line column as typed arrays: positions,
  advances, ink boxes, font slots, bidi levels, shaper flags, line starts and counts. `glyphCount` is the one
  authority for their length; never re-derive a length from a column.
- Paragraph 2: every call copies the columns, so the caller owns them and nothing it does can corrupt the retained
  layout; that copy is the cost. Use it for custom hit testing or decoration; ordinary rendering never materialises
  it, and caret placement has its own API (link Interaction).
- Shape: two paragraphs.

notes · internals
- the columns — `layout.ts#GlyphLayout` (`:158–187`); `glyphCount` is the single authority (`:151–156`)
- `GlyphLayoutInspection` adds `glyphStableIds` — `layout.ts:198–200`; stable ids identify a record within one
  committed layout and do not survive a reflow — `glyph-placement.ts:28–31`
- copied per call — `three/text.ts:748–754` (docstring), `internal/render-planner.ts#_inspectText` (`:585–590`),
  `layout.ts#copyGlyphLayoutInspection` (`:203–228`)
- shaper flags decode with `glyphFlags` — `layout.ts:27–34`
- `Text.glyphs()` also refreshes `boundingBox` — `three/text.ts:748–754`, `:766–769`
*/}

## Intrinsic widths

```ts
const summary = text.measure();
summary.minContentWidth; // the longest unbreakable run
summary.maxContentWidth; // the width if nothing wrapped
```

{/*
write
- Question: how wide does this text want to be, so a layout system can negotiate a box for it?
- Paragraph 1: both widths are intrinsic — they do not depend on the constraints currently being probed — and they
  ride the same measurement pass as the rest of the summary. There is no second layout to pay for and no separate
  object to own: a host sizing a box reads them from the `measure()` it was already going to call.
- Paragraph 2: the pair is the CSS min-content/max-content pair, so a flex or grid integration maps onto it directly.
- Point at: uikit-style integrations as the audience.
- Shape: two paragraphs.

notes · internals
- `ParagraphIntrinsicWidths` — `layout.ts:139–142`; carried on every summary through `ParagraphLayoutSummary` (`:116`)
- the standalone `Paragraph`/`createParagraph` object is gone with the config API (D-314, D-321): measurement is an
  action on a `Text` in desired state, and the intrinsic widths that were its reason to exist now ride that pass
- a `Text` holds the face lease for as long as it is alive and releases it on `dispose()` — `three/text.ts#Text.dispose`
*/}

## When you can measure

| Situation | `measure()` | Notes |
| --- | --- | --- |
| Detached `Text` | works | routed through the root-owned encoder; see the [verify] below |
| `Text` under a `TextGroup` | works | same encoder; sequential queries extend one speculative transaction the next traversal adopts |
| Before the first frame | works | does not commit; `commitState()` stays `pending` |
| Unchanged since last call | free | returns the retained result without a Wasm crossing |

{/*
write
- Question: is it safe to measure now?
- Paragraph 1: measurement is desired-state: it reads what you have set, not what the renderer accepted, so it works
  before the first frame and immediately after `set()`. It does not traverse matrices, realise materials, publish
  a draw, or move `commitState()`.
- Paragraph 2: `boundingBox` and `computeBoundingBox()` are a local `Box3` derived from the last measurement and
  refreshed by `measure()` or `glyphs()`; caret and selection are the opposite kind of query — they read accepted
  placement and answer `undefined` while pending (link Interaction). Do not mix the two in one frame's logic.
- Shape: two paragraphs.

notes · internals
- `Text.measure()` → `ThreeRoot.measurement` → `ThreeRootPublication.measurement` → `handle.measure()` —
  `three/text.ts:736–742`, `:409–412`, `:1193–1201`; the publication reconciles `root.members()` first (`:431–433`)
- commit is marked only by `acceptShape` — `three/text.ts:1272–1281`; `commitState()` — `:756–764`
- retained result on a hit, cleared on update — `internal/render-planner.ts#_layoutText` (`:577–582`), `:568–569`
- a query re-sends the whole text and applies mutations for the queried paragraph only —
  `internal/render-planner.ts#queryText` (`:786–842`; the whole text at `:812–819`); the transaction the next traversal adopts — D-253, D-282
- `boundingBox` → `computeBoundingBox()` → `glyphs()` when stale — `three/text.ts:664–666`, `:766–769`; set by
  `measure()` too (`:741`)
- [verify] D-282 says a detached `Text.layout()` throws and detached measurement belongs to `Paragraph`;
  `.agents/docs/planning/three-api.md:275` says a detached Text uses "its implicit standalone planner"; at HEAD `measure()`
  reaches the root-owned planner regardless of scene attachment (`three/text.ts:409–412`, `:1193–1201`). Call it on
  a Text that is not in a scene and record which happens before the table's first row is final
*/}

## Cost

| Query | Pays for |
| --- | --- |
| `measure()` | one Wasm measurement on a miss; nothing on a hit |
| `glyphs()` | positioning plus copying every column |
| traversal | at most one mutating batch per `glyph.shape()`, every dirty root in one call |

{/*
write
- Question: what am I paying for?
- One sentence per row, in plain words; the third row is the reassurance that measuring in a frame loop does not
  add a second shaping pass. Point at the measurement scene, which calls `measure()` every frame.
- Close with one line pointing at Performance for numbers.
- Shape: three sentences and a pointer.

notes · internals
- measurement crossing — `internal/render-planner.ts#_layoutText` (`:577–582`) → `#queryText` → `transport.measureParagraph` (`:829`)
- copy per call — `internal/render-planner.ts#_inspectText` (`:585–590`)
- one batch per `glyph.shape()`, dirty roots only, cannot re-enter — `glyph-engine.ts#_shape` (`:387–433`), `textUpdateBatch` (`:488`)
- measured cost at the 22,000-glyph corpus: 1.815 ms median per measure query, zero publication bytes — D-253
- the measurement scene measures every frame — `site/examples/src/scenes/measurement/scene.tsx:31–33`
*/}
