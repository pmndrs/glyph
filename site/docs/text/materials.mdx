## The context

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';

defineTextMaterial((context) => {
  const material = context.createDefaultMaterial();
  if (context.kind === 'decoration') return material; // underline, overline, line-through
  switch (context.format) {
    case 'pmndrs.bitmap': // position, clipPosition, atlasUv, coverage, color, opacity
      material.colorNode = context.shader.color;
      break;
    case 'pmndrs.msdf': // position, atlasUv, fillCoverage, outlineCoverage, shadowCoverage, color, opacity
      material.opacityNode = context.shader.opacity.mul(context.shader.fillCoverage);
      break;
    case 'pmndrs.slug': // position, renderCoordinate, coverage, color, opacity
      material.colorNode = context.shader.color;
      break;
  }
  context.root; // { name, scene, drawRoot } — which root this material is being built for
  return material;
});
```

| Field | Meaning |
| --- | --- |
| `kind` | `'glyph'` or `'decoration'` |
| `format` | glyph branches only: `'pmndrs.bitmap' \| 'pmndrs.msdf' \| 'pmndrs.slug'`, or a custom format's literal key |
| `shader` | that pipeline's TSL output nodes |
| `position` | final renderer-local position including the Codec transform indirection — always your `positionNode` |
| `root` | `ThreeRootContext`: the root's `name`, its `scene`, its `drawRoot` |
| `createDefaultMaterial()` | the built-in realisation for this branch |

## Node table

| Node | Type | Meaning |
| --- | --- | --- |
| `coverage` / `fillCoverage` | `float` | antialiased fill before paint alpha |
| `outlineCoverage`, `shadowCoverage` | `float` | MSDF rings, fill already subtracted so they never double-count |
| `color` | `vec3` | the composite of fill, outline, and shadow, un-premultiplied |
| `opacity` | `float` | paint alpha × coverage (MSDF: fill + outline alpha, shadow where they leave room) |
| `atlasUv`, `renderCoordinate`, `clipPosition` | — | format-specific inputs; Bitmap alone publishes `clipPosition` because it snaps to the pixel grid |

{/*
write
- Question: which nodes are safe to compose over?
- Paragraph 1: `color` and `opacity` are the finished answer, already composited; a material that wants the default
  look with a tint multiplies `color`. The coverages are the ingredients: fill, and for MSDF the outline ring and the
  shadow, each already exclusive of the others so summing them never double-counts.
- Paragraph 2: the inputs are format-specific and are mostly for a material that re-derives coverage; `clipPosition`
  exists only on Bitmap because pixel snapping happens in clip space, and the default Bitmap material feeds it to
  `vertexNode`. Slug's `position` and `coverage` are two halves of one graph: use `coverage` and you must drive
  `positionNode` from `position`.
- Avoid: repeating the MSDF decode; link Raster formats.
- Shape: two paragraphs.

notes · internals
- outputs — `tsl/bitmap-shader.ts#TslBitmapShaderOutput` (`:38–52`), `tsl/msdf-shader.ts#TslMsdfShaderOutput` (`:49–60`),
  `tsl/slug-shader.ts#TslSlugShaderOutput` (`:85–94`), `tsl/decoration-shader.ts#TslDecorationShaderOutput` (`:13–17`)
- MSDF ring exclusive of fill: `outlineOnly = max(outlineCoverage − fillCoverage, 0)` — `tsl/msdf-shader.ts:89`, `:117`;
  shadow only where glyph alpha leaves room — `:101`; the un-premultiplied composite — `:103–107` (`.div(max(outputAlpha, 1e-6))`)
- opacity = paint alpha × coverage — `tsl/bitmap-shader.ts:82`, `tsl/slug-shader.ts:166`; MSDF `outputAlpha` — `tsl/msdf-shader.ts:102`, `:120`
- Bitmap alone publishes `clipPosition`; the default feeds it to `vertexNode` — `tsl/bitmap-shader.ts:40–45`,
  `three/internal/material-realizer.ts#bitmapMaterial` (`:616–623`); Slug publishes none — `tsl/slug-shader.ts:82–84`
- Slug `position` and `coverage` are one graph — `tsl/slug-shader.ts:100–101`

## The base contract

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';
import { DoubleSide, MeshPhysicalNodeMaterial, NormalBlending } from 'three/webgpu';

const physical = defineTextMaterial((context) => {
  const material = new MeshPhysicalNodeMaterial({
    blending: NormalBlending,
    depthTest: false,
    depthWrite: false,
    side: DoubleSide,
    transparent: true,
  });
  material.positionNode = context.position;
  material.colorNode = context.shader.color;
  material.opacityNode = context.shader.opacity;
  return material;
});
```

- Question: what must a material of my own keep?

## Lit text

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';
import { float, normalize, uniform, vec2, vec3 } from 'three/tsl';
import { DoubleSide, MeshPhysicalNodeMaterial, NormalBlending } from 'three/webgpu';

const inkCentre = uniform(vec2(0, 0)); // from measure().inkBounds, in Text-local units
const inkSpan = uniform(vec2(1, 1));

const lit = defineTextMaterial((context) => {
  if (context.kind !== 'glyph' || context.format !== 'pmndrs.msdf') return context.createDefaultMaterial();
  const material = new MeshPhysicalNodeMaterial({
    blending: NormalBlending,
    depthTest: false,
    depthWrite: false,
    side: DoubleSide,
    transparent: true,
  });
  const lean = context.position.xy.sub(inkCentre).div(inkSpan).mul(0.9); // a fake curvature across the whole word
  material.positionNode = context.position;
  material.normalNode = normalize(vec3(lean.x, lean.y, 1));
  material.colorNode = context.shader.color;
  material.opacityNode = context.shader.opacity;
  material.metalnessNode = float(0.62);
  material.roughnessNode = float(0.38);
  return material;
});

three.createText({ font: Inter, text: 'Metal', material: lit });
```

{/*
write
- Question: can text be lit like a mesh?
- Paragraph 1: yes, because a text material is a node material: swap the basic material for a physical one, feed
  `colorNode` and `opacityNode` from the shader, and lights, an environment map, metalness, and roughness do the rest.
  The one thing a flat quad lacks is a normal; fake one that leans with position across the paragraph's measured
  ink so the whole word lights as one surface. Derive it from `context.position`, not from the quad's own
  `positionLocal`, which spans each glyph's unit quad and would light every letter as its own object.
- Paragraph 2: feed `inkCentre` and `inkSpan` from `measure().inkBounds` once the text has a size; the landing
  wordmark is this material plus bloom and a lens flare from `useRenderPipeline`.
- Shape: two paragraphs; point at the proxy above.

notes · internals
- the scene's material: `MeshPhysicalNodeMaterial` with `normalNode = normalize(vec3(lean.x, lean.y, 1))`,
  `metalnessNode 0.62`, `roughnessNode 0.38`, a `RoomEnvironment` map — `site/examples/src/scenes/materials/scene.tsx:19–41`, `:70–83`
- the technique quads span `[0, 1]` with the origin at the upper-left, so `positionLocal` is per-glyph quad space —
  `tsl/bitmap-shader.ts:59–60`, `tsl/msdf-shader.ts:66–67`, `tsl/slug-shader.ts:103–104`; `context.position` is
  paragraph-local — `three/material.ts:32`
- the landing pipeline: bloom → lens flare → chromatic aberration — `site/landing/src/effects.tsx:23–49`
- [verify] the materials scene derives `lean` from `positionLocal` (`site/examples/src/scenes/materials/scene.tsx:32`) while its comment says
  "paragraph-local position — measured ink"; the snippet above uses `context.position.xy` instead. Render both and
  keep the one that lights the word as one surface; fix the scene if it is the other
*/}

## Decorations

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';
import { color, mix, positionLocal, uniform } from 'three/tsl';

const phase = uniform(0);

const gradientLine = defineTextMaterial((context) => {
  const material = context.createDefaultMaterial();
  if (context.kind === 'decoration') {
    const t = positionLocal.x.mul(0.25).add(phase).fract();
    material.colorNode = mix(color('#ff4dc4'), color('#70d6ff'), t).mul(context.shader.opacity);
  }
  return material;
});

three.createText({
  font: Inter,
  text: 'Sphinx of black quartz',
  style: { decoration: { underline: true, thickness: 0.06 } },
  material: gradientLine,
});
```

## Where a material applies

```ts
import { glyph, txt } from '@pmndrs/glyph';
import { defineTextMaterial, defineThreeConfig, span } from '@pmndrs/glyph/three';

const glow = defineTextMaterial((context) => context.createDefaultMaterial());

three.createText({ font: Inter, text: txt`Status ${span(glow, { color: '#4ade80' })`online`}` }); // one run
three.createText({ font: Inter, text: 'Whole text', material: glow });                         // one text
three.createTextGroup({ material: glow });                                                      // every descendant
three.material = glow;                                                                          // every text on this root
glyph.handle('app', defineThreeConfig({ material: glow }));                                     // every root of a handle
```

| Rule | Why |
| --- | --- |
| span → text → group → root → config precedence | the nearest material wins |
| equal factories share identity | the plan segments draws by material identity; one object, one binding |
| return synchronously; never query or update text inside | it runs while three holds borrowed plan attributes |
