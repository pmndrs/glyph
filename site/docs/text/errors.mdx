Glyph has no error callback and no per-text error state. A value you wrote that cannot be accepted throws from the
call that wrote it, and the text keeps its previous value. A failure the engine or the renderer finds later is thrown
from the render that finds it, once, with the failed text quoted in the message.

Every error Glyph raises on purpose extends `GlyphError` and carries a stable `code`. Branch on `code` or on the class,
never on the message.

## Where each failure is thrown

| You did | Thrown from | Error |
| --- | --- | --- |
| Passed an invalid value to `createText`, `set()`, a property setter or a React prop | that call | `GlyphInputError` (`code: 'invalid-input'`) |
| Passed an offset that is not a grapheme boundary to `caret`, `move`, `boundary`, `rangeRects` or `replace` | that call | `TextOffsetError` (`code: 'invalid-offset'`) |
| Wrote a layout input inside an `onLayout` callback | that setter | `GlyphLayoutPhaseError` (`code: 'layout-phase'`) |
| Loaded a font that is missing, corrupt or lacks the requested format | the `load()` promise, or the Suspense boundary in React | `GlyphFontError` (`code: 'resource-unavailable'`) |
| Rendered a text the engine refuses, exceeded a fixed capacity, or threw from your own `onLayout` | `renderer.render(scene, camera)` | the underlying error, once per failure |

## Invalid input

```ts
import { GlyphInputError } from '@pmndrs/glyph';

try {
  text.style = { fontSize: -1 };
} catch (error) {
  if (error instanceof GlyphInputError) console.warn(error.path, error.message); // ['style', 'fontSize']
}
```

A setter validates the whole next value before it assigns anything, so a throw leaves the text exactly as it was.
`path` names the input from the property you wrote, outermost first; it is empty when the values are only invalid
together. `cause` is the validator's own `TypeError` or `RangeError`.

A text longer than `maxTextUnits` (65,536 UTF-16 units unless you raise it in `defineThreeConfig`) is invalid input. A
lone surrogate is not: it draws as U+FFFD.

## Offsets

```ts
import { TextOffsetError } from '@pmndrs/glyph';

try {
  text.rangeRects(9, 3);
} catch (error) {
  if (error instanceof TextOffsetError) console.warn(error.reason, error.before, error.after); // 'reversed'
}
```

The editing methods never snap or clip. `reason` is `'not-integer'`, `'out-of-range'`, `'reversed'` or
`'inside-grapheme'`, and `before` and `after` are the nearest valid boundaries, so a caller that wants snapping can do
it explicitly.

## Failures found while rendering

```ts
try {
  renderer.render(scene, camera);
} catch (error) {
  console.error(error); // 'Glyph text "Hello, wor…" was not drawn: …'; the engine's error is `cause`
}
```

Setters make no engine call, so an engine refusal cannot surface where you assigned the value. It surfaces from the
render that prepares the text:

- The frame is drawn first. The failed text draws nothing; its siblings draw.
- The same standing failure is thrown once, not on every later frame. Changing the text's input retries it.
- The message quotes the first 40 UTF-16 units of the failed text, so a console line or an error report identifies
  it without any per-text state.
- `text.commitState()` stays `{ status: 'pending' }` for a refused text. There is no `'failed'` status and no
  `text.error`.

If you do not catch it, it reaches your global handler (`window.onerror`, an error reporter) like any other exception
from your render loop. TypeGPU throws the same failures from `root.draw()`, and PixiJS 3D from `glyph.shape()`.

An engine trap does not take the root down: the engine instance is replaced, every text restates itself, and the next
frame retries. An input that always traps is refused alone.

## Fonts

```ts
import { GlyphFontError } from '@pmndrs/glyph';

try {
  await Inter.load();
} catch (error) {
  if (error instanceof GlyphFontError) console.warn(error.reason, error.url);
}
```

A failed load rejects the `load()` promise and is evicted, so calling `load()` again is a new attempt.

## React

```tsx
import type { GlyphFontError } from '@pmndrs/glyph';
import { GlyphErrorBoundary, GlyphProvider, Text } from '@pmndrs/glyph/react';

<GlyphProvider errorFallback={(error: GlyphFontError) => <group name={error.reason} />}>
  <GlyphErrorBoundary fallback={null} onError={console.error}>
    <Text font={inter}>Hello</Text>
  </GlyphErrorBoundary>
</GlyphProvider>;
```

An invalid prop throws while React commits. Without a boundary inside the canvas that unmounts the whole canvas, so
wrap text in `GlyphErrorBoundary`: only the subtree it wraps is replaced by `fallback`, and the function form receives
`reset` to mount the children again. `GlyphProvider`'s `errorFallback` handles only `GlyphFontError` and rethrows
anything else. A failure found while rendering is thrown from R3F's render, outside React, so catch it with a global
handler.

In Vue, an invalid prop and a font that fails to load reach `onErrorCaptured` or `app.config.errorHandler`, and the
component keeps its previous value.
