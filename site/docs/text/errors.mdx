## Causes

| `rejection.cause` | Meaning | You fix it by |
| --- | --- | --- |
| `span-range` | a span is inverted, reaches past the text, or splits a surrogate pair | authoring valid offsets |
| `cluster-boundary` | a style boundary falls inside a grapheme cluster | nothing — `Text` resolves this before the engine; reaching it is a defect |
| `span-overlap` | two spans partially overlap | nesting or disjoint ranges |
| `paragraph-root` | the paragraph's root style is missing, duplicated, or does not cover the text | supplying `style` |
| `font-stack-missing` | a style names a font the engine does not hold | loading and binding the font first |
| `font-metrics-missing` | a font in the laid-out text has no registered metrics | re-baking |
| `capacity` | the frame did not fit the encoder arenas after they grew; carries `requiredRequestBytes`, `requiredResultBytes` | filing it, with the two numbers |
| `engine` | any status the engine does not classify; names nothing | filing it |

## Where errors surface

| Entry | Behaviour |
| --- | --- |
| `createText`, `set()`, a property setter | throw synchronously; desired state is left as it was |
| `createText({ font })` on an unloaded face | throws `FontLoadError` `FONT_FACE_FORMAT_NOT_LOADED` |
| `glyph.shape()` | per root: retained on `text.error` and `group.error`, `onError` called once per distinct error; other roots still publish; then it throws, an `AggregateError` when more than one root refused |
| `measure()` / `glyphs()` | throw on a disposed text; `Paragraph.measure(constraints)` throws for invalid constraints at the call |
| a font load | rejects the selection's `load()` promise with `FontLoadError`; the failed operation is evicted so a retry is a new load |

{/*
write
- Question: which calls throw, and which ones swallow?
- Paragraph 1: the boundary throws. `createText`, `set()`, and every property setter validate the whole next state
  before assigning it, so a `TypeError` or `RangeError` there leaves the text exactly as it was; the message names
  the field and the value. A face that has not finished loading is a `FontLoadError` at `createText`.
- Paragraph 2: the traversal retains. `glyph.shape()` stages every dirty root, and a root that is refused gets its
  error attributed to every one of its texts in the scene and every `TextGroup` above them, then `onError` fires
  once per new error; the other roots are accepted in the same call. The call then throws the error (or an
  `AggregateError`), which the three.js traversal catches for you; in vanilla three.js, catch it around your own
  `glyph.shape()`.
- Paragraph 3: fonts reject their promise and evict the failed operation, so calling `load()` again is a fresh attempt
  rather than the same rejection replayed.
- Shape: three paragraphs; the table is the index.

notes · internals
- `set()` builds the next state before assigning — `three/text.ts:712–731`; validation throws — `#normalizeDesired`

  `font-face.ts#requiredFontFaceFormat` (`:636–649`); a family string that is not declared throws `FONT_FACE_NOT_FOUND` — `three/text.ts:578–586`
- a non-immutable font in `set({ font })` throws — `loaded-font.ts#immutableFontSelectionFonts` (`:83–95`)

  `glyph-engine.ts#_shape` (`:387–433`), `#settleShapeParticipants` (`:531–556`)

## What the renderer keeps

```ts
const state = text.commitState();
if (state.status === 'failed') console.error(state.error);       // the last accepted draw is still on screen
text.material = undefined;                                        // any renderer-relevant change requests a fresh publication
```

{/*
write
- Question: what is on screen after a failure?
- Paragraph 1: the last accepted draw. Realisation is prepare-then-commit: a candidate is validated whole before any
  device state changes, so a failure never leaves half a frame. `commitState()` reports `{ status: 'failed', error }`
  and placement queries answer `undefined` until a later checkpoint succeeds.
- Paragraph 2: an unchanged frame is not retried — the root re-enters the batch only when something renderer-relevant
  changes: text, style, material, order, a transform binding. A malformed emitted plan is an engine defect, never a
  recovery path.
- Shape: two paragraphs.

notes · internals
- prepare then commit, last accepted plan kept, no retry of unchanged frames — D-279, D-285
- the rejected flag gates placement — `three/text.ts:1283–1286`, `#canonicalInspection` (`:1343–1357`); cleared on accept — `:1272–1274`
- `commitState()` — `three/text.ts:756–764`
- only dirty roots enter the batch — `glyph-engine.ts:390`; a root is dirty when reconcile finds a change —
  `three/text.ts#ThreeRootPublication.needsReconcile` (`:1157–1172`), `#ThreeRoot.#commitTraversal` (`:483`)
- material assignment stages a fresh publication — `three/text.ts:708–710`, `:1008–1012`
*/}

## Fixed capacity is not an error

```ts
three.setCapacity({ size: 4096, policy: 'fixed' }); // UTF-16 units across the root's texts; over budget keeps the last draw
```

{/*
write
- Question: what happens when a `fixed` root runs out of room?
- Paragraph 1: nothing is thrown and nothing is retained as an error. The root is skipped for that traversal: the last
  draw stays, `commitState()` stays `pending`, and `measure()` still answers for the desired text because it does not
  go through the shape. The bound is a text-length upper bound computed before shaping, so you can size content
  against the cap instead of discovering it after the fact.
- Paragraph 2: raising the capacity re-enters the root; `grow` and `chunk` resize instead and never skip.
- Close by pointing at Text, roots, and TextGroup → Capacity.
- Shape: two paragraphs, one pointer.

notes · internals
- the policy — `text-properties.ts#GlyphBufferCapacity` (`:7–16`)
- over budget returns `false` from prepare and records `capacityExceeded` — `three/text.ts:1260–1269`, `:1111–1113`;
  a `false` prepare is `SKIPPED`: neither accepted nor rejected — `glyph-engine.ts:451–453`, `:538`, `config/glyph.ts:651`
- raising capacity invalidates when exceeded — `three/text.ts:1115–1119`; the root setter — `:240–246`
- `fixed` re-admitted after D-267 removed it — D-282
- [verify] "retried on every traversal": staging removes the root from the dirty set (`glyph-engine.ts:446`), so an
  unchanged over-budget root re-enters only after an invalidation; D-282 says "retries the capacity decision every
  traversal without a rejection latch". Check `three/text.ts#ThreeRoot.#commitTraversal` (`:478–492`) → `needsReconcile` on an unchanged root before stating either
*/}
