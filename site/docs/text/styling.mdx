## Composing styles

```ts
import { TextStyle } from '@pmndrs/glyph';

const styles = TextStyle.create({
  base: { fontSize: 0.5, color: '#f4f7ff' },
  emphasis: [{ fontSize: 0.5, color: '#f4f7ff' }, { color: '#ffd166' }], // a rule may itself be a list
});

declare const active: boolean;
declare const opacity: number;
three.createText({ font: Inter, text: 'Styled', style: [styles.base, active && styles.emphasis, { opacity }] });
```

{/*
write
- Question: how do I reuse a style and switch parts of it on and off?
- Paragraph 1: a style is a value or a nested left-to-right list; `false` and `null` entries are ignored, so a
  condition reads naturally in the list. `TextStyle.create({ name: rule })` validates each named rule once, merges
  any list it was given, and returns the rules frozen.
- Paragraph 2: public boundaries merge and validate known values; unknown keys are ignored, malformed known values
  throw with the property named.
- Anchor: React Native's style arrays.
- Shape: two short paragraphs.

## Color and opacity

{/*
write
- Question: which colour forms work, and why not `hsl()`?
- One paragraph: a string is `#rrggbb` or `#rrggbbaa` (sRGB, converted to linear at the boundary); a tuple is
  already linear RGBA in `[0, 1]`; any other CSS form throws `… must be #rrggbb, #rrggbbaa, or linear RGBA`, so
  animate a hue by converting to hex or a tuple yourself. Opacity multiplies alpha and is inherited on its own, so a
  span can fade without restating colour.
- Shape: one paragraph.

notes · internals
- accepted forms and the throw — `text-properties.ts#assertColor` (`:320–334`)
- packing: hex parsed as sRGB bytes, tuples encoded through the sRGB transfer, alpha × opacity —
  `engine-encoding.ts#packedForeground` (`:249–257`), `#linearColorBytes` (`:280–286`)
- opacity inherited independently — `text-properties.ts:97–98`
- [verify] where the sRGB → linear decode happens on the GPU side (the decoration shader decodes through the EOTF
  per D-248); confirm glyph draws do the same before writing "converted to linear"
*/}

## Outline and shadow

{/*
write
- Question: why does my outline throw on one font and draw on another?
- Paragraph 1: MSDF renders both from the distance field — the outline as a ring around the true distance, the
  shadow as a second sample at an offset that shows only where the fill leaves alpha. Bitmap and Slug have no field
  and reject `outline` and `shadow` at the boundary, naming the format, rather than degrading.
- Paragraph 2: width and offset are in paragraph-local units; how far an outline or shadow can reach is bounded by
  the bake's `pixelRange` (link Raster formats → MSDF).
- Shape: two paragraphs.

notes · internals
- declared effects — `raster/msdf.ts:72` (`['outline', 'shadow']`), `raster/bitmap.ts:83`, `raster/slug.ts:59`
- the throw, per format in the selection — `engine-encoding.ts:199–212`; checked for the root font and every span
  font at construction — `three/text.ts:1457–1472`
- shader: outline ring `max(outlineCoverage − fillCoverage, 0)` — `tsl/msdf-shader.ts:88–89`; shadow sample at an
  offset, masked by `1 − glyphAlpha` — `:90–101`
- reach bounded by the bake — `internal/msdf-contract.ts:18` (`MSDF_MAX_OUTLINE_ATLAS_PIXELS = pixelRange / 2`)
- [verify] how `outline.width` in paragraph-local units maps to atlas pixels: read `instance.outlineWidth` encoding
  in `raster/msdf.ts` before quoting the bound
*/}

## OpenType features

```ts
three.createText({
  font: Inter,
  text: 'Ligatures off, small caps, tabular numbers 0123456789',
  style: { features: [{ tag: 'liga', value: 0 }, { tag: 'smcp' }, { tag: 'tnum', start: 43, end: 53 }] },
});
```

{/*
write
- Question: how do I turn a feature on, off, or on for part of a run?
- One paragraph: a feature is its four-letter tag; `value` defaults to 1, `0` turns a default-on feature off, and
  `start`/`end` restrict it to a UTF-16 range inside the run that carries the style. A range outside the run throws.
- Shape: one paragraph; three examples in the code (off, on, ranged).

notes · internals
- `FontFeature` — `font-feature.ts:1–6`; tag is four printable ASCII bytes, `value` a u32 — `text-properties.ts#assertFeature` (`:284–300`)
- `value` defaults to 1 — `engine-encoding.ts:175`
- ranges must lie inside the styled scope — `text-properties.ts#assertTextStyleFeatureRanges` (`:222–230`), applied
  to the paragraph `three/text.ts:1446` and to each span `:1517`
*/}

## Language and direction

{/*
write
- Question: when do I set `language` or `direction`?
- One paragraph: `language` selects locale-specific shaping and line-break classes and must be a well-formed tag;
  `direction: 'auto'` runs the bidi algorithm on the paragraph and picks the base direction from its first strong
  character, so set `rtl` explicitly for a paragraph that starts with neutrals. `align: 'start'` follows the base
  direction (link Paragraph layout → Direction).
- Shape: one paragraph.

notes · internals
- tag grammar — `text-properties.ts#validLanguage` (`:369–377`); direction enum `:193–195`
- language reaches the shaper per run — `rust/shaper/src/engine/state.rs:3986–3990`; HarfRust 0.12 — `rust/shaper/Cargo.toml:25`
- bidi: `auto` → no default level, `ltr`/`rtl` → forced level; Unicode 17 data — `rust/shaper/src/bidi.rs:52–57`
- UAX #14 line breaking — `rust/shaper/src/line_break.rs:1–2`
- `start`/`end` swap by paragraph level — `rust/shaper/src/engine/positioning.rs:1691–1692`
*/}
