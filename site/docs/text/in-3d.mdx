## Depth and occlusion

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';

const inScene = defineTextMaterial((context) => {
  const material = context.createDefaultMaterial();
  material.depthTest = true; // hidden by geometry in front of it
  return material;
});

three.createText({ font: Inter, text: 'occluded', material: inScene });
three.createText({ font: Inter, text: 'overlaid' }); // the default draws over everything
```

<glyph-proxy root="scenes" data-scene="depth" aria-label="A sphere passing in front of and behind two words" aspect="16 / 9" />

| Setting | Default | Change it when |
| --- | --- | --- |
| `depthTest` | `false` | the text is a surface in the world — signage, a label on a body, a paragraph on a wall |
| `depthWrite` | `false` | never for glyphs: the quad is transparent outside its ink and would write a rectangle |
| `transparent` | `true` | never: coverage is blended, not cut |
| `side` | `DoubleSide` | `FrontSide` when the back of a sign should be blank |

{/*
write
- Question: why does the label show through the sphere, and how do I stop it?
- Paragraph 1: the base material is a `MeshBasicNodeMaterial` with normal blending, no depth test, no depth write,
  double-sided, transparent. No depth test is the HUD default: a label is never lost behind the thing it annotates.
  One line turns the test on and the text becomes a surface: geometry in front hides it, geometry behind does not
  (point at the proxy).
- Paragraph 2: `depthWrite` stays off either way. A glyph quad is transparent outside its ink; writing depth would
  punch its rectangle into whatever it covers. Because no glyph writes depth, glyphs in one batch never z-fight
  whatever `depthTest` is; the test only compares against what opaque geometry wrote.
- Avoid: repeating the base-contract callout from Materials; link it.
- Shape: two paragraphs; the table carries the four settings.

notes · internals
- `baseTextMaterial` — `three/internal/material-realizer.ts:639–647`; `createDefaultMaterial()` returns it with
  `positionNode`, `colorNode`, `opacityNode` set — `:628–637`
- the depth scene: one word depth-tested, one default, a sphere on an ellipse through both — `site/examples/src/scenes/depth/scene.tsx:11–23`, `:29–33`
- [verify] "glyphs in one batch never z-fight": follows from `depthWrite: false`; confirm with two overlapping
  depth-tested texts at the same z before stating it
*/}

## Render order

```ts
text.renderOrder = 10;                     // a standalone Text: its draws take its order
three.createTextGroup({ renderOrder: 5 }); // a group states one order for every descendant
```

{/*
write

- Paragraph 1: every planned draw is a mesh whose `renderOrder` is the owning `Text`'s, or the nearest enclosing

## Labels that follow and face

```tsx
import { Text } from '@pmndrs/glyph/react';
import { defineTextMaterial } from '@pmndrs/glyph/three';
import { useFrame } from '@react-three/fiber/webgpu';
import { useRef, type ReactNode } from 'react';
import type { Group } from 'three/webgpu';

const inScene = defineTextMaterial((context) => {
  const material = context.createDefaultMaterial();
  material.depthTest = true;
  return material;
});

function Billboard({ children }: { readonly children: ReactNode }) {
  const group = useRef<Group>(null);
  useFrame(({ camera }) => {
    group.current?.quaternion.copy(camera.quaternion);
  });
  return <group ref={group}>{children}</group>;
}

<mesh>
  <sphereGeometry args={[0.3, 32, 24]} />
  <meshStandardNodeMaterial color="#f4d68a" />
  <Billboard>
    <Text font={Inter} material={inScene} position={[-1.5, 0.55, 0]}>
      Io
    </Text>
  </Billboard>
</mesh>;
```

## Steep angles

<glyph-proxy root="scenes" data-scene="off-axis" aria-label="A paragraph turning away from the camera" aspect="16 / 9" />

| Format | Off-axis | Why |
| --- | --- | --- |
| Slug | crisp at any angle | the outline is evaluated per pixel with a footprint measured per axis; nothing is sampled |
| MSDF | good until the atlas is stretched | a texture sample of a distance field; the antialiasing range is derived per axis and floored at one pixel |
| Bitmap | screen-space only | pre-rasterised at a size; `pixelSnapping` assumes a plane facing the camera |

{/*
write
- Question: why does the paragraph go soft when it turns?
- Paragraph 1: text is geometry, so perspective applies to it like anything else; what differs per format is what
  happens to the pixels. Slug solves the outline under every pixel and measures its footprint per axis, so a grazing
  angle costs nothing in edge quality. MSDF samples a texture; anisotropy stretches the sample and softens the far
  edge. Bitmap is a raster at one size and snaps in clip space, which assumes a plane facing the camera.
- Paragraph 2: `rasterPixelRatio` is how a `Text` asks MSDF or Bitmap for a larger raster when it will be seen
  larger than authored, without changing its layout.
- Close by pointing at Raster formats for the full comparison.
- Shape: two paragraphs, one pointer.

notes · internals
- Slug per-axis footprint from the derivative of the render coordinate — `tsl/slug-shader.ts:82–84`, `:141`; MSDF
  per-axis range floored — `tsl/msdf-shader.ts:133–135`; Bitmap snaps in clip space — `tsl/bitmap-shader.ts:91–105`
- `rasterPixelRatio` is a Text property — `three/text.ts:699–703`, `paragraph.ts:74`
- the off-axis scene: a Slug paragraph on a turning panel — `site/examples/src/scenes/off-axis/scene.tsx`
*/}

## Warping text onto surfaces

```ts
import { defineTextMaterial } from '@pmndrs/glyph/three';
import { cos, sin, uniform, vec3 } from 'three/tsl';

const spin = uniform(0);
const RADIUS = 5.2;

const carousel = defineTextMaterial((context) => {
  const material = context.createDefaultMaterial();
  if (context.kind !== 'glyph') return material;
  const p = context.position;                     // paragraph-local, after the engine's transform
  const angle = p.x.div(RADIUS).add(spin);        // advance along the line → angle around Y
  material.positionNode = vec3(sin(angle).mul(RADIUS), p.y, cos(angle).mul(RADIUS).sub(RADIUS));
  material.colorNode = context.shader.color.mul(cos(angle).mul(0.5).add(0.5).mul(0.88).add(0.12)); // the far side dims
  material.opacityNode = context.shader.opacity;
  return material;
});

three.createText({ font: Inter, text: 'around and around', material: carousel });
```

- Paragraph 1: text is geometry, so a material may move its vertices: `context.position` in, somewhere else out,

  flag, hang words on a curve. The text underneath stays live and reflows on the warped surface.
- Then an `> [!IMPORTANT]` callout, two sentences: warp MSDF or Bitmap text. Slug's vertex stage returns an

  draw; keep Slug for the flat, razor-sharp word and put the warped surfaces in MSDF.
- Close by contrasting with Break apart: a warp moves vertices in the shader and keeps the text live; `breakApart`
  gives one matrix per glyph and freezes the layout.
- Shape: one paragraph, callout, one sentence.

## Text as a texture: render targets

```tsx
import { GlyphProvider, Text } from '@pmndrs/glyph/react';
import { createPortal, useFrame } from '@react-three/fiber/webgpu';
import { Renderer, RenderTarget, Scene } from 'three/webgpu';

const surface = new Scene();            // a root spans at most one Scene: the tile gets its own named root
const target = new RenderTarget(2048, 128);

useFrame(({ renderer }) => {
  if (!(renderer instanceof Renderer)) return; // the WebGPU entry always is; the state's type is a union
  renderer.setRenderTarget(target);
  renderer.render(surface, camera);      // shapes the surface root, draws one line of text
  renderer.setRenderTarget(null);        // the main scene draws after this callback
});

createPortal(
  <GlyphProvider handle={handle('surface')}>
    <Text font={Inter.slug} style={{ fontSize: 2.6, color: '#ffffff' }}>
      live
    </Text>
  </GlyphProvider>,
  surface,
);
```

```ts
import { color, mix, texture, uniform, uv, vec2 } from 'three/tsl';
import { MeshBasicNodeMaterial, RenderTarget } from 'three/webgpu';

const target = new RenderTarget(2048, 128);
const repeat = vec2(8, 3);
const scroll = uniform(0);

// the tube's material: the Codrops fract-repeat-and-scroll over the live texture
const material = new MeshBasicNodeMaterial();
const scrolled = uv().mul(repeat).add(vec2(scroll.negate(), 0)).fract();
material.colorNode = mix(color('#141a26'), color('#e7ecf6'), texture(target.texture, scrolled).r);
```

{/*
write
- Question: what if the surface is the point and the text should follow every fold of it?
- Paragraph 1: render the text to a render target and let a material sample it. The texture is a live scene, so it
  can type, reflow, and recolour every frame, and the surface can be any geometry with a UV map; the Codrops
  `fract(uv * repeat - scroll)` tiles and scrolls it.
- Paragraph 2: the second scene needs its own root, because a root spans at most one `Scene`; `handle('surface')`
  is a named root on the same handle, one `GlyphProvider` away in React and one `createText` call away in
  three.js. Render the tile before the main scene; `glyph.shape()` shapes every dirty root, both scenes, in one call.
- Point at: the kinetic scene does exactly this for the knot's skin and keeps the rings as real glyphs on paths beside it.
- Shape: two paragraphs.

notes · internals
- a root spans one `Scene` or throws `… spans more than one Scene; select a different handle root for each Scene` —
  `three/text.ts#ThreeRoot.#bindScene` (`:543–562`)
- named roots: `handle(name)` returns the idempotent named root — `config/glyph.ts#GlyphHandle` (`:581–589`),
  `#GlyphNamedRoot` (`:575–578`); `GlyphProvider` accepts a handle or a root — `react.ts:193–199`
- one `glyph.shape()` for every dirty root — `glyph-engine.ts#_shape` (`:387–433`)
- the kinetic scene: `handle('tile')`, an orthographic tile camera, `RenderTarget`, the tile rendered before the
  main scene, the knot's `surfaceMaterial` — `site/examples/src/scenes/kinetic/three.ts:41–56`, `:121–123`,
  `site/examples/src/scenes/kinetic/materials.ts:31–42`; the React form — `site/examples/src/scenes/kinetic/scene.tsx:48`
*/}

## Post-processing

```tsx
import { useRenderPipeline } from '@react-three/fiber/webgpu';
import { bloom } from 'three/examples/jsm/tsl/display/BloomNode.js';

useRenderPipeline(({ passes, renderPipeline }) => {
  if (renderPipeline === null) return; // the callback also runs for the teardown pass
  const scene = passes.scenePass.getTextureNode();
  const glow = bloom(scene, 0.9, 0.4, 0.55);
  renderPipeline.outputNode = scene.add(glow);
  glow.strength.value = 1.2; // a uniform: animate it without rebuilding the pipeline
});
```

```ts
import { glyph } from '@pmndrs/glyph';
import { bloom } from 'three/examples/jsm/tsl/display/BloomNode.js';
import { pass } from 'three/tsl';
import { PostProcessing } from 'three/webgpu';

const scenePass = pass(scene, camera);
const post = new PostProcessing(renderer);
post.outputNode = scenePass.getTextureNode().add(bloom(scenePass.getTextureNode(), 0.9, 0.4, 0.55));

function frame(): void {
  glyph.shape(); // once per frame, before the host renders
  post.render();
}
```
