## Render text with React Three Fiber

```tsx
import { Text, TextGroup } from '@pmndrs/glyph/react';
import { useBitmap } from '@pmndrs/glyph/react/bitmap';
import { useMsdf } from '@pmndrs/glyph/react/msdf';
import { useSlug } from '@pmndrs/glyph/react/slug';

const VT323 = '/fonts/VT323.font.glb';
const INTER = '/fonts/Inter.font.glb';
const LOVERS_QUARREL = '/fonts/LoversQuarrel.font.glb';

void useMsdf.preload(INTER);

function Labels() {
  const inter = useMsdf(INTER);
  const loversQuarrel = useSlug(LOVERS_QUARREL);
  const vt323 = useBitmap(VT323, { strikes: [8, 16] });

  return (
    <>
      <Text
        font={loversQuarrel}
        style={{ fontSize: 32, color: '#f7f7f7' }}
        layout={{ align: 'center' }}
        constraints={{ width: { mode: 'exact', size: 480 } }}
        position={[0, -4, 0]}
      >
        Lorem <Text style={{ color: '#f70000' }}>Ipsum</Text>
      </Text>
      <TextGroup>
        <Text
          font={inter}
          style={{ fontSize: 32, color: '#f7f7f7' }}
          layout={{ align: 'center' }}
          constraints={{ width: { mode: 'exact', size: 480 } }}
          position={[0, -1, 0]}
        >
          Eos tempor iusto mollit reprehenderit dolor cillum.
        </Text>
      </TextGroup>
      <Text
        font={vt323}
        style={{ fontSize: 8, color: '#f7f7f7' }}
        layout={{ wrap: 'word' }}
        constraints={{ width: { mode: 'at-most', size: 480 } }}
        position={[0, 0, 0]}
      >
        lorem ipsum dolor sit amet consectetur adipiscing elit eiusmod anim vel proident nam sint quo laborum
      </Text>
    </>
  );
}
```

  `<Text>` is a styled run inside the paragraph, not a child object, which is why `Ipsum` is red without a
  transform of its own. `<TextGroup>` is an ordinary parent for transform, visibility, material, and render order;
  it does not decide batching.
- Point at `useMsdf.preload(INTER)`: a hook declares a face on the handle and suspends until it is loaded, so a
  preload at module scope means the first render finds it ready.
- Avoid: the provider and the default handle; link Components.
- Shape: one paragraph, four sentences.

- a nested `<Text>` is an inline run: it inherits font, style, and material, creates no scene object, and accepts only
  `children`, `font`, `style`, `material`; anything else throws at mount naming the prop — `react.ts:758–791`
  (`flattenText`), `:804–818` (`inlineProperties`), `:820–826` (`INLINE_TEXT_PROPERTIES`, `assertInlineTextProperties`)
- `<TextGroup>` is a scene-hierarchy parent for transform, visibility, material, pixel snapping, render order, not a
  batching boundary — `three/text.ts:84–90` (`TextGroupOptions`), D-307
- the hooks are the React loading surface: each declares through `glyph.fontFace` on the selected handle and owns the
  mounted `Font` lease — `react.ts#useFont` (`:628–631`), `:667–683` (`reactFontFaceResource` →

## Render text with three.js

```ts
import { glyph, span, txt } from '@pmndrs/glyph';
import { ThreeConfig } from '@pmndrs/glyph/three';

await glyph.init();
const handle = glyph.handle('app', ThreeConfig);
const Inter = glyph.fontFace('/fonts/Inter.font.glb');
await Inter.load();

const accent = span({ color: '#70d6ff' });
const label = handle.createText({
  font: Inter,
  text: txt`Hello ${accent`world`}`,
  style: { fontSize: 32, lineHeight: 1.2, color: '#f4f7ff' },
  layout: { wrap: 'word' },
  constraints: { width: { mode: 'at-most', size: 480 } },
});

scene.add(label);
glyph.shape();                  // publish every dirty root; Mesh children now sit below label
renderer.render(scene, camera); // three performs the actual draw
```

{/*
write
- Question: what is the same thing without React, and who does what?
- Say, in the order of the code: `glyph` is the runtime and `init()` loads the shaper once. A handle is one adapter
  configured once, and the handle is itself the root your text lives on. A face is declared once with `fontFace`
  and loaded once with `load()`; it never takes a handle. `createText` returns an ordinary `Object3D`, not a canvas
  or a renderer: add it to the scene and position it like a mesh. `glyph.shape()` publishes every root that changed
  and the meshes appear under the label; `renderer.render` draws them.
- Then one sentence: three.js authors rich text with the `txt` and `span` tags where React nests `<Text>`.
- Avoid: `handle(name)` and named roots; that is Text, roots, and TextGroup.
- Shape: one paragraph of five sentences, then the `txt`/`span` sentence.

notes · internals
- `glyph.init()` once; it keeps one settled Promise forever, so a second call costs nothing — `glyph.ts:44–57`, D-305
- `glyph.handle(name, config)` throws before `init()` and on a duplicate name — `glyph.ts:59–68`
- the handle is its own anonymous root; `handle(name)` returns an idempotent named sibling root —
  `config/glyph.ts:581–589` (`GlyphHandle`), `three/handle.ts:132–137` (`threeHandleRoot`), D-307
- `ThreeConfig` is `defineThreeConfig()` with `transformMode: 'indexed'`, `allocationMode: 'ordered'`,
  `defaultFontFormat: 'msdf'` — `three/handle.ts:171–177`, `:265`; the options are `capacity`, `compositing`,
  `transformMode`, `allocationMode`, `defaultFontFormat`, `material` — `#ThreeConfigOptions` (`:93–99`),
  `three/text.ts:78–82` (`ThreeRootOptions`)
- `glyph.fontFace(source, { family?, format? })` never takes a handle; the one-argument form gets a generated family
  `Font{n}` and resolves to the handle's default format — `glyph.ts:100–105`, `font-face.ts:167`, `:798–804`; D-297, D-310
- `await Inter.load()` loads every format the GLB advertises plus every declared one, once — `font-face.ts:87–88`,
  `:389–413` (one aggregate Promise), `:438–479`
- `createText({ font })` takes a face, a member, or a family string and acquires the handle's `Font` lease; an
  unloaded face throws `FONT_FACE_FORMAT_NOT_LOADED` — `three/text.ts:256–282`, `font-face.ts:636–650`
- `Text` is only ever constructed by a root — `three/text.ts:623–644`
- `glyph.shape()` stages every dirty root of every handle and crosses into Wasm once — `glyph.ts:94–98`, D-312;
  three's own `updateMatrixWorld` on the root's draw object also calls it, so `renderer.render` alone would publish —
  `three/text.ts:139–142`, `:478–486`

## Measure before you render

```ts
import { glyph } from '@pmndrs/glyph';

scene.add(text);
const measured = text.measure();
text.position.x = -measured.contentWidth / 2;
glyph.shape();
renderer.render(scene, camera);
```

{/*
write
- Question: can I ask how big it is before anything draws?
- Say: yes, synchronously, on the object you just made, with no scene attachment, no world matrix, and no frame.
  `contentWidth`/`contentHeight` are the advance box layout claims; `inkBounds` is what the glyphs actually cover;
  they are different numbers on purpose. Centre on ink when the eye judges it; size a flex box on the advance.
- Shape: two sentences; link Measurement.

notes · internals
- `measure()` answers for desired state, synchronously, with no scene attachment or matrix traversal —
  `three/text.ts:732–742`
- `contentWidth`/`contentHeight` are advance extents (what layout claims); `inkBounds` is the union of glyph outlines
  (what was drawn); they are deliberately not interchangeable — `layout.ts:56–61`, `:73–75`, `:80–89`
- `Text.measure()` answers for desired state — no world matrix, no renderer resource, no committed frame —
  `three/text.ts:814`
*/}

## Does it need WebGPU?

{/*
write
- Question: will this run where I deploy?
- Say: no. three's `WebGPURenderer` carries a WebGL2 backend and swaps to it when a WebGPU adapter cannot be had,
  which is what happens on any plain-http origin; every format is one TSL shader that compiles for both backends.
  What you give up on WebGL2 is nothing text-specific.
- Shape: one paragraph, three sentences. "On its own" is confirmed in the notes below.

notes · internals
- `WebGPURenderer` constructs a `WebGPUBackend` and hands the base renderer a `getFallback` that builds a
  `WebGLBackend`; `forceWebGL` skips WebGPU outright —
  `packages/glyph/node_modules/three/src/renderers/webgpu/WebGPURenderer.js:57–71` (three 0.185.1, the peer floor)
- the swap runs when backend init fails and `_getFallback` is set — `…/three/src/renderers/common/Renderer.js:785`;
  the WebGPU backend's init asks `navigator.gpu` for an adapter — `…/renderers/webgpu/WebGPUBackend.js:217`
- an absent `navigator.gpu` does reach the fallback: `WebGPUBackend.init` is `async` and its
  `navigator.gpu.requestAdapter()` (`WebGPUBackend.js:217`) throws inside it, so the promise rejects, and
  `Renderer.init` catches that rejection and constructs `getFallback(error)` — `Renderer.js:775–790` (three
  0.185.1); the fallback the constructor installs is `new WebGLBackend(parameters)` with a console warning —
  `WebGPURenderer.js:57–69`. "On its own" is correct
- `navigator.gpu` exists only in a secure context, so `http://<lan-ip>` gets WebGL2 — `site/vite.config.ts:12–15`
  (the comment); the spec marks the `NavigatorGPU` mixin `[SecureContext]` — WebGPU, "navigator.gpu",
  https://www.w3.org/TR/webgpu/#navigator-gpu
- one TSL shader per format serves both backends — `three/bitmap.ts:1`, `:25`; `three/msdf.ts:1`, `:29`;
  `three/slug.ts:1`
- the examples explainer forces WebGL with `?renderer=webgl` — `site/docs/components/explainer/root.tsx`
  (`forceWebGL`; find the line)
*/}

## Is it slower than sprites or a canvas texture?

{/*
write
- Question: I already batch sprites; will this cost me draw calls?
- Say: no. Text is retained and instanced: every `Text` on a root shares one planner and one reconcile, and the plan
  emits a draw only where a boundary forces one. Point at Performance for what those boundaries are and how to
  count them.
- Anchor: "you write paragraphs; the GPU sees instance buffers".
- Shape: two sentences plus the link. The boundary keys are derived in the notes below; list them.

notes · internals
- one planner per root: every `Text` on the root is one publication stream and one reconcile —
  `three/text.ts:150` (`ThreeRoot`), `:436–448` (`prepareShape` reconciles all members); D-307
- draws are instanced batches in the display list — `config/glyph.ts:428` (`DisplayListBatch`),
  `three/internal/draw-realizer.ts:87–113` (batch children → instance spans)
- `compositing: 'independent'` lets Rust reorder compatible draws when order does not matter —
  `three/text.ts:78–82`, `three/handle.ts:180–183`
- capacity defaults to 4 096 glyphs, chunked growth — `three/text.ts:191–194`
- the batch-boundary keys, derived: a draw extends while the pending batch (program + storage) is the same, the
  order records are contiguous and under `u16::MAX`, the resource id and generation match, and material and
  transform match only when the program's `draw_key_mask` carries `BATCH_MATERIAL` / `BATCH_TRANSFORM` —
  `rust/shaper/src/engine/stable_plan.rs:1408–1424`, `#same_draw_span` (`:1585–1605`), mask bits `codec.rs:34`,
  `:38`, resource `:1434–1442`; the reader-facing table and its cites are on advanced/performance ("Draw
  boundaries"). Clip and paint layer are three-side realization keys, not engine keys
- the batching example counts draws — `site/examples/src/scenes/batching/scene.tsx`

  Bidi, UAX #29 clusters, and UAX #14 line breaks all run in Rust; JavaScript keeps only grapheme boundaries,
  pinned to the same Unicode version, so a span never splits a cluster the engine sees whole. Layout is horizontal
  today.
- Point at the shaping example.
- Shape: one paragraph. The Unicode version is 17.0.0, pinned as the notes below show.

## Where does layout happen?

{/*
write
- Question: which side of the Wasm boundary does the work?
- Say: Rust. Shaping, line fitting, justification, and glyph positioning run in the engine in F16.16 integer layout
  units under one rounding contract, so native and Wasm builds agree bit for bit; JavaScript owns cluster
  alignment, the scene graph, and the render loop, and crosses into Wasm once per `glyph.shape()`.
- Shape: two sentences; link How it works.

notes · internals
- shaping, line fitting, justification, and positioning are Rust modules —
  `rust/shaper/src/engine/line_composition.rs`, `positioning.rs`, `cluster_state.rs`
- layout units are F16.16 integers (1/65 536 of a caller unit) under one round-half-up contract, identical in
  native and Wasm builds — `rust/shaper/src/engine/layout_units.rs:1–30` (`LAYOUT_UNIT_BITS = 16`). The earlier
  stub said F26.6; that is wrong at this HEAD.
- one Wasm crossing per `glyph.shape()` — D-312
- JavaScript owns grapheme alignment and the render loop — `internal/graphemes.ts`, `react.ts`
*/}
